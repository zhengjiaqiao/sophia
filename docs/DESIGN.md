# Sophia 设计系统

**本文件是实现的唯一依据。** 规范分四个文件：

| 文件 | 放什么 |
|---|---|
| `docs/DESIGN.md`（本文件） | token（front-matter）、设计原则、视觉语言、组件使用指南（每个组件做哪一件事、什么时候用、不要用在哪、和谁容易混）、模式、产品裁决、Do / Don't |
| `docs/DESIGN-components.md` | 每个组件的精确规格：尺寸、状态、token、行为细节；`/design-sync` 的输入 |
| `docs/DESIGN-decisions.md` | 决策记录与「已裁决的冲突」表：每条规则怎么来的、改过几版、为什么 |
| `docs/archive/DESIGN-v4-checklist.md` | V4 落地清单（已完成，只作历史） |

视觉语言以 V4（拉姆斯 / Braun）为准：`.superpowers/design/RamsDirections2.dc.html` 的 V4 列是视觉参照，`docs/DESIGN-spacex.md` 是 V4 之前 shop 面的历史参照，与本文件不一致时都以本文件为准。改组件先改 `DESIGN-components.md`（用法变了同时改本文件「组件使用指南」），再改代码，再同步画布。token 只从 `src/tokens.css` 出，本文件 front-matter 记同一组值（留作档位、代码里还没用上的除外）。`scripts/lint-ui.mjs` 把硬性约束变成了可执行断言，接在 `make lint` 里。

本文件只写结论。各屏布局 2026-09-24 按 V4 与五支柱十八条重新推导（D1–D14），同日补了沿用旧设计的审查（D15–D24），字体与标志回到原设计——这些的经过、以及每条规则背后的推理，在 `docs/DESIGN-decisions.md`（更早的在 `docs/specs/2026-09-21-ui-decisions-log.md`）。

## Overview

**少，但更好。** 参照拉姆斯 / Braun：一件放在桌上的家电，而不是一张线框图。窗体是机壳（`shell`），内容放在一块平的机面上（`face`：1px 细边、不投影）；**物性只给会被手碰的三样**——键、页签、开关：它们抬起一点、有重量、按下贴近机面、滑块用阻尼弹簧停稳——其余全平。表格是整窗最平、最亮的一块，它是主角（③）。颜色是近中性的灰白，外加一个 Braun 橙，**橙只表示「开着 / 在生效」**（开关的刻条与指示点），不承载文字、不当强调、不当主动作。投影只说离机面多高：键与滑块抬起一点，浮层浮得最高，平铺的东西不投影。下面「材料与工艺」一节是这一版的总纲，其余各节与它冲突时以它为准。

界面回答两个问题：**这东西在这个 agent 下现在能不能用**；**点了没成的话，是什么挡住了**。第二个问题必须给出用户能据此行动的话，不是错误码。

## 设计原则：尊重用户的注意力与判断

**这是此后一切评审的标尺**（产品负责人，2026-09-22 立；2026-09-24 按产品负责人更新的《设计原则体系》改为「一个理念、一个地基、五根支柱、十八条原则」）。下文「材料与工艺」「视觉优先」和各节裁决都是它们的具体化；冲突时以本节为准。

**核心理念：尊重用户的注意力与判断。** 用户依次付出**注意力**（去看）、**理解**（去弄懂）、**行动**（去操作），长期下来交出**信任**。尊重有两层：**不让用户多付**——对这四样分别负责，降低认知负荷与交互成本（支柱一至四，可用性：让产品不被讨厌）；**让付出值得**——用户得到的不只是任务完成，还有确定、顺手、愉快（支柱五，情感化设计：让产品被人愿意用）。

**地基：克制——少，但更好。** 每一个元素、概念、步骤、商业诉求都要证明自己存在的理由，证明不了就不出现。克制不是极简风格，也不是功能越少越好：「少」是手段，「更好」是目的——去掉不必要的，把精力留给剩下的部分，把它们做到位。克制贯穿每根支柱：信息的克制（信噪比）、概念的克制（不发明不必学的新东西，不轻易推翻已学会的）、步骤的克制（不多走一步）、商业冲动的克制（不为短期指标牺牲判断）、装饰的克制（愉悦来自把本分做好）。**犹豫不决时，默认选更克制的方案**——加一样东西容易，去掉一样东西难。

| 支柱 | 原则（及具体准则） | 在 Sophia 里意味着 |
|---|---|---|
| **一 不浪费注意力**<br>用户该看到什么 | ① 每条信息都必须提供价值：判断标准不是信息本身重不重要，而是此时此刻对这个用户重不重要；价值不只是功能，确定感、愉悦、归属感同样是价值（见支柱五），一个细节可以不「有用」但必须「值得」。准则：渐进式披露（暂时没价值的收起或延后，不必删）；同一信息不在同一界面重复；能一个词说清不用一句，能不说的不说 | 问题只在它所在的那一行显示，不另弹提示；新手提示每处只出一次；只在挑模型时有用的说明放进网关行的展开区；提示框只说屏幕上没说的；空闲时界面静止 |
| | ② 在对的时间，出现在对的位置：太早是干扰、太晚是失职，出在视线之外等于没出现。准则：就近出现（格式塔接近）；就近不遮挡；局部就近、全局全局；严重程度决定打断程度（一般提示非模态、自动消失，需要决策或后果不可逆才用模态打断） | 提示与反馈锚在触发它的控件上：单格浮在被点那一格下、批量贴在按下的那一项下；成功与失败都是浮起的纸窗、会自己走，要你处理的才嵌在页面里；弹层只用于确认 |
| | ③ 视觉权重与重要性一致：一个界面一个主角、一个主要操作，处处强调等于没有强调；强调手段按层级有限使用、同层不叠加；次要内容靠退后让位，而不是让主角更吵 | 表格是主角；勾选框、开关都让位于主动作；强调只靠三档，橙不当强调 |
| | ④ 默认值本身就是设计：默认状态就是大多数人的真实体验（默认效应）；必要的复杂度不会消失只会转移（Tesler），由设计者承担。准则：先想「不改它的人得到什么」；按大多数用户的真实场景而非对业务最有利的方式设定；加设置项前先问更好的默认值能否让它没必要存在 | 见「默认值」表；不把「要不要自动重启 Codex」做成设置项 |
| **二 降低理解成本**<br>用户能否看懂 | ⑤ 一致性（内部）：相同的形式承载相同的含义，含义不同的不长得一样；破坏的不只是美观，更是信任。准则：设计令牌统一基础变量，新样式要有理由才加入；一个概念一个名字；语义色与图标的含义不在局部挪作他用 | 墨键＝主动作；平贴的实心墨＝这个在 / 选上了；墨色浮窗只有提示框；橙＝开着 / 在生效（一个义，两种形：开关刻条、指示点）——一种形一个义，不再加新义；`scripts/lint-ui.mjs` 守 token 集 |
| | ⑥ 符合用户已有的心智模型（外部一致）：用户带着别处的习惯（雅各布定律）和自己的语言来。准则：用用户的词汇，不用内部术语、字段名；平台惯例默认遵守；偏离惯例前写下理由，并验证收益大于重新学习的成本 | 界面说「原件」不说「本体」、说「同名」不说「撞名」（lint 旧词表拦回潮）；同名用惯例 `×2`，不用自创括线 |
| | ⑦ 尊重用户已经学会的东西（时间上的一致）：用户的学习成本沉淀为熟悉感与肌肉记忆，频繁改版、挪入口、换风格会把它清零（改版阵痛）；好设计不追潮流，所以不易过时。准则：高频操作的入口位置和手势非必要不动；改版先答「老用户失去了什么」；重大变化给过渡；视觉更新优先渐进演化 | 高频入口不挪：Skills 与 MCP 同一面板宽度，切 `skills ｜ mcp` 时页面头的键不跳；项目段第一项固定是 `全局`，切页签侧栏与选中不变；V4 只换视觉语言，行为与交互规则不变；各屏布局重新推导时要答「老用户失去了什么」 |
| | ⑧ 让可供性被感知，文字用于提供确定性：仅凭颜色、形状、质感这些意符就能判断能不能点、拖、展开；控件方向与效果自然映射；不用文字弥补意符的缺失，但视觉可能误解或误判代价高时，一句清晰的文字必要。准则：可操作与静态内容用意符区分，不过度扁平；误判代价高的按钮写明结果 | 格子悬停出光晕表示能点、点本身不变；有框的都能点、抬起＝能按、平贴＝按不下；文字确定性由「提示框」承载，不用原生 title |
| | ⑨ 保持上下文连续，让用户始终知道自己在哪（寻路）：动效解释空间关系；选项、历史、上下文保持可见，识别优于回忆。准则：每页能答我在哪、从哪来、怎么回去；从哪展开就收回到哪；返回时保持状态 | 侧栏在每一页都在、选中项就是「在哪」；确认框的标题写明在决定的对象；添加来源在机面里从右推入、返回滑回；来源筛选片平铺、不收进下拉 |
| **三 让行动轻松且安全**<br>用户能否放心地做 | ⑩ 交互成本与使用频率和风险匹配：常用的事轻松，不可逆的事慎重（有意增加摩擦）；给熟练用户加速器，但不增加新手负担。准则：高频目标大而近（费茨定律）；危险操作与常用操作拉开距离；加速器只做捷径，不做唯一路径 | 见「键盘」；命中区与视觉尺寸分开 |
| | ⑪ 每个操作都有反馈，系统状态始终可见：回应「收到了、正在处理、成功了或失败了」，强度与操作分量相称；加载、选中、不可用、空状态本身就该被看见；最好的反馈常常是足够快。准则：约 0.1 秒即时反馈，超 1 秒显示进行中，超 10 秒说明进度并允许离开或取消；出错说原因和下一步 | 格子行带 + 悬停光晕、列头悬停提示框（轻）；按下影子收紧、键面贴近机面（明确）；刚点亮反色闪 120ms（确认）；刻度扫过 + 一句忙什么（持续）；做不成时提示条写一句能行动的原因 |
| | ⑫ 预防错误优先于处理错误：用约束、禁用无效选项、限定输入、合理结构让错误没机会发生；能在源头消除的，不留到事后撤销。准则：无效选项禁用或隐藏，必要时说明为什么；内联校验；能从结构上杜绝的不靠文案警告 | 添加时就地解决同名，不把冲突推进待处理；删原件先确认、写清后果，skill 进废纸篓、MCP 可撤销（见「删除原件」） |
| | ⑬ 允许犯错，并让犯错的代价足够低（容错）：挽回机制与挽回难度相称；能挽回的不弹确认（频繁确认导致习惯化，用户条件反射地点「是」）。按挽回成本分级：天然可逆的（开关类）反向操作就在原位、一步可达，只需状态反馈清晰；可逆但难找回的（删除、移出列表）给撤销或软删除；不可逆的才确认并写明后果。判断标准：能否在原地一步恢复原状。用户输入意外中断后能恢复 | 格子与批量键是开关：再点一次就是准确反操作时不给 `撤销`；再点不能准确复原时（原本就有一部分、移除的副本改过）才给；确认只给不可逆的事（删网关连带钥匙串密钥、重启 Codex 打断对话），写明后果 |
| **四 守护信任**<br>用户能否长期信赖 | ⑭ 诚实，不操纵：不让产品显得比实际更好，不诱导，不藏取消入口，不用任何暗黑模式。模糊地带问：用户知道了真实情况会不会觉得被骗？准则：数字、标签如实呈现，不为效果夸大；不制造虚假紧迫感，不确认羞辱 | 问题一直在那一行上看得见，不藏，也不弹窗催；新手提示关掉或学会就不再出；「改动待生效」按 Codex 实际加载的配置判定，永远说实话；撤不了就说实话 |
| | ⑮ 用户始终保有控制权：随时能退出、拒绝、改主意，与诚实一起构成信任的两面（不骗你，也不绑住你）。准则：进出对称；用户能查看、修改、删除自己的数据与偏好；自动化行为可感知、可关闭 | 自动规则在背后做的事都用例行一行交代，规则开关在来源管理页；重启时机归用户，不自动重启 |
| **五 让付出值得**<br>用户愿不愿意主动回来 | ⑯ 细节贯彻到底（本能层）：间距、对齐、字体、动效曲线、文案语气、边缘情况，用户说不出但感受得到；精致的细节让人相信整体可靠（美即好用效应）。准则：边缘情况与正常状态同等设计（空状态、超长文本、首次使用）；微文案语气一致、不推卸责任；上线前走查到像素与帧 | 空态一句现状 + 一个动作；长名字真被截断时才出提示框；读不到描述就不写，不写「无描述」；圆角随尺寸、汉字零字距；键的抬起与按下必须在 1x 屏截图验收 |
| | ⑰ 操作要有手感（行为层）：⑪ 要求反馈说清状态，这一条要求反馈让人确定、愉悦——像拨盘有阻尼、按键有回弹，手比眼睛先知道成没成。准则：动效用符合物理直觉的缓动或弹簧，有质量和惯性，不匀速线性；按下即响应，乐观更新；触觉反馈只给关键时刻 | 格子、勾选先按操作画出来、后台写（乐观更新），失败弹回并说原因；键抬起、按下贴近机面、松开弹簧回位；页签与开关的滑块用阻尼弹簧停稳（过冲 1.5%）、越重越慢，开关可拖；颜色与透明度用 120ms 机械缓动 `cubic-bezier(.2,.8,.2,1)` |
| | ⑱ 有性格，但不喧宾夺主（反思层）：辨识度来自一以贯之的做法，不靠堆装饰；愉悦服务于用户要做的事，集中在关键节点（峰终定律），不平铺、不打断主流程。准则：品牌调性靠一致的细节（色彩、动效节奏、文案语气）；每一处「眼前一亮」都要答得出帮用户做成了什么 | 字标的黑猫与玻璃、大写 `S` 与左下重影——猫只在字标动效与空态插图，不进控件、托盘和图标，平时静止、只由用户唤起；一个 Braun 橙，只表示「开着」 |

### 怎么用这套原则

- **层次**：核心理念 → 地基（克制）→ 五根支柱 → 十八条原则 → 具体准则（本文件其余各节）。具体准则最开放，在实践中持续积累和修订；理念、地基、支柱保持稳定，轻易不改——这本身也是 ⑦ 的要求。
- **原则冲突时，向上裁决**：两条原则矛盾，或体验与商业目标冲突时，回到理念问——哪种做法更尊重用户的注意力与判断？是在帮用户判断，还是在干扰用户判断？仍难抉择，回到地基：选更克制的那个。常见冲突的倾向：
  - **愉悦 对 克制**：愉悦来自把本分做好（细节、手感、质感），需要额外添加才有的愉悦通常不值得。
  - **创新 对 稳定**：新方案的收益必须明显大于用户重新学习的成本，否则保持现状。
  - **体验 对 商业**：商业目标可以争取，但不能以操纵为手段；⑭ 是底线，不参与权衡。
  - **效率 对 安全**：按风险分配交互成本；可撤销的操作偏向效率，不可逆的操作偏向安全。
- **新经验出现时，向上归位**：先问它属于哪条原则、服务哪根支柱；找不到归属，要么它不重要，要么体系有缺口、值得补——作为「体系缺口」上报产品负责人。
- **术语**：是为了讨论更精确，不是为了显得专业；一句白话能说清就不换成术语。术语表见本节末「附录：术语表」。
- **评审与改动说明都标原则编号**（①–⑱）。`DESIGN-decisions.md` 里本次更新之前的条目用旧 13 条编号，对照见 `DESIGN-decisions.md`「编号对照」。

**已裁决的冲突**（原则之间、原则与产品负责人意见之间怎么取舍的，二十多条）见 `DESIGN-decisions.md`「已裁决的冲突」。

## 材料与工艺

**总约束（产品负责人原话）：「依然服务于功能，易用，给人惊喜又符合直觉，剔除不增加价值的任何元素。」** 每个元素都过一道检验：**拿掉它，用户会少知道什么、或少能做什么？答不上来就删。** 每个交互先满足惯例（开关像开关、链接像链接、可点的看得出可点、不可点的不像可点），再在手感和响应上超预期。惊喜放在**行为**上——点格时指示灯即时点亮（乐观更新）、失败时弹回并由提示条说明原因、撤销一键复原、键按下时贴近机面、开关滑块被弹簧稳稳停住——不是多一个图形。任何需要用户学习的新图形语言都算缺陷，除非它换来明确的效率。

**拉姆斯的「少，但更好」不是少画，是：一块平的机面托住内容、每个会被手碰的控件都像实物一样有位置、重量与回弹、一个颜色只说一件事、极小而精确的刻字。** 翻译成界面，**不看起来像实物，而表现得像实物**（产品负责人 2026-09-24：有重量、有惯性、有层次、做出物理上合理的反应，不过度拟物，依然提供可供性）——没有金属、拉丝、螺丝、发光灯、纹理、渐变、高光；抬起只用一层柔和短投影（模糊 ≤ 8px），凹只用 1–2px 内凹。

### 机壳、机面与手会碰的三样（V4）

| 材料 | 是什么 | 给谁 |
|---|---|---|
| **机壳**（`shell` #F4F4F2） | 窗体本身 | 侧栏直接落在机壳上，**不画分隔线**（侧栏右、侧栏底都没有线；分区由机面的边给出）；D1 起没有顶栏 |
| **机面**（`face` #FCFCFB） | 放内容、放数据的一块平面：1px `hairline` 边、`face` 12 圆角、**无投影** | 表格、表单、列表、模型行；一屏一块。表格直接铺在机面上，不再另套一层面板框 |
| **按键面**（`paper` #FFFFFF） | 比机面亮一档的「可以按的东西」与「浮起来的东西」 | 默认键、页签选中的滑块、开关滑块、未勾的勾选框；菜单浮层、确认框、提示条 |
| **凹面**（`recess` #F2F2EF） | 「在这儿输入」 | 输入框（另作开关槽与没选的来源胶囊的底） |
| **墨面**（`ink` #1C1C1A） | 实心的墨，见下 | 主动作键、刚点亮的格子反色；格子里的 ●、勾上的勾选框、选中的来源胶囊；提示框 |

**物性给会被手碰的三样：键、页签、开关**（①③⑧⑪⑰）。它们像实物一样有高度、重量与惯性：

1. **键**：默认键与墨键**抬起**一点（`raise` / `raise-ink` 柔和投影，边由投影的 1px 环给出）；悬停＝手靠近，影子略重、不位移；按下＝贴近机面，影子收紧、键面下沉 0.5px 并微缩；松开由弹簧回位。
2. **页签**：页签装在一条凹下去的**槽**里（`surface` 底、`recess-tabs` 内凹、`tab-track` 10 圆角），选中的那一页是槽里一枚抬起的**滑块**（`paper` + `raise`、`control` 7 圆角）。位置＝当前页；切换时滑块被阻尼弹簧带过去、停稳。
3. **开关**：圆角矩形槽 + 抬起的方滑块；滑块位置与露出的刻条两重表达开 / 关（旁边不再另点指示点，2026-09-25：紧挨开关的灯是同一件事说两遍，①）；滑块可点可拖，弹簧停靠（见 `DESIGN-components.md`「开关 Switch」）。

除此之外全平：机面、行、片、格点、灰面板、表格都不投影、不凹下；**格点不加凹坑**（56×4 个凹坑会成纹理，③）。**按不下的东西不离开机面**：禁用的键与开关平贴、无投影。勾选框只在手靠近时抬起迎手，静止与勾上都平贴。

**墨色靠形状分义，不再加新义**（⑤）：
- **墨键**——抬起的键（或是格子）：**主动作 / 已按下**（主动作键、刚点亮的格子反色闪一下）。
- **平贴的实心墨**——**这个在 / 选上了**：格子里的 ●（已加上，文件事实，不是运行状态）、勾上的勾选框（墨底白勾）、选中的来源胶囊。它们平贴、不抬起，与抬起的墨键分开（2026-09-25：选中在全应用一律墨色；抬起的墨键不再表示「已选中」）。
- **提示框**——浮起、带浮层投影：悬停（或键盘焦点）出的说明。**墨色的浮窗只剩这一种**（2026-09-25 产品负责人：「黑条提示都不要了……黑条提示现在应该只在悬浮才出」）：做不成、部分失败、单格失败原因都用纸窗（见下）。

**「开着 / 在生效」只归橙色**（开关刻条 + 指示点），与 ● 不同形、不同义。

墨面上的字：主 `face`，次 `ctl-border`；墨面上的分隔线 `ink-mute` 1px。

- **提示条一律是纸**（2026-09-25 起）：成功与失败同一种纸窗，失败靠左侧记号栏（⊘ / !）与**否定动词**分开，不靠颜色——长相与写法见 `DESIGN-components.md`「提示条 Toast」，形态与锚点的总规则见「Patterns › 反馈」。
- **问题只就地常显**：没有收件箱、待处理页、「忽略」，也没有新问题提示；每类问题在哪看得见、在哪处理见「产品裁决 › 问题在哪看得见、在哪处理」。
- **对话框（确认框）**：纸浮层、一律在窗口正中、遮罩整面压暗、只说后果——规格与写法见 `DESIGN-components.md`「确认框 Confirm」；Sophia 里哪些事要确认见「产品裁决 › 哪些要确认」。
- **忙碌态**：只在用户发起、正在等的地方出现，刻度扫过 + 一句「忙什么」（见 `DESIGN-components.md`「忙碌 BusySlot + Spinner」）。

### 线：两档灰，不用墨（层级是功能：哪里是区块边界、哪里只是行）

| 线 | 规格 | 给谁 |
|---|---|---|
| 边线 | 1px `hairline` | 机面的边、浮层的边、输入框；**表头底**（结构线，表格的上沿）；展开区、筛选下拉的边界 |
| 行线 | 1px `row-line` | 行与行（最后一行不画） |
| 控件边 | 1px `ctl-border` | 目标小框等可点边框；**抬起的键与滑块不画描边**，边由 `raise` 的 1px 环给出 |

墨色不画线：V4 没有 2px 墨色结构线，也没有 1px 墨色区块线——区块由机面的边给出，表头与行靠 `hairline` 与 `row-line` 的一档深浅分开。**控件边比边线深一档（`ctl-border` 对 `hairline`）＝能点**（⑧）。

### 一种数字

**计数一律 `tabular-nums`（Barlow 的等宽数字），12 `ink-faint`；不写别处已有的分母**（列头只写 `41`，不写 `41/56`——56 已在「全部 56」上）——功能理由：计数在片与列头里上下对齐、变化时不抖。**不零填充**（`026` 更难读，是装饰）。IBM Plex Mono 只给 id、路径、版本号——正文和计数不换等宽。

### 刻字

- 区块小标（`网关` `关于` `建议的来源` `AGENT` `项目`，组件 `SectionLabel`）与自写列头（`名称` `来源`）：`label` Condensed 12 / 600、`ink-mute`（墨面上 `ctl-border`）；区块小标**全应用只有这一种**，可选下 7 一条 1px `hairline`（2026-09-25 裁决，取代「贴 hairline 上方 6」与网关小标 12 / 500 两种写法）。胶囊行的行首标签（`来源` `在用`）不是区块小标，见「组件使用指南 › 容器与层」。汉字字距 0、不变换；拉丁结构词经 `Cap` 大写 + 0.96px（`AGENT`）。
- **只删重复控件已表达的句子**；机器信息（路径、大小、条数）写成读数而不是散句。

### 强调色：一个颜色，一个意思

**橙的含义唯一：「开着 / 在生效」；形态有两种：开关的刻条（滑块让开后露出的那一截）与 6px 指示点（外一圈 2px 同色 14% 的灯罩环——平的色环，不模糊、不发光）。** 同义同色不违反 ⑤（2026-09-24 裁决）。**指示点只出现在看不到开关的地方**（2026-09-25：紧挨开关再点一颗灯，是同一件事说两遍，①）——侧栏 agent 名后（这个 agent 上有能力开着，开关在另一页），让「开着」在离开开关的地方也看得见（⑪）；开关在眼前时由它自己的刻条说。 它不承载文字（橙上的墨字 4.9:1、白字 3.5:1，都不稳），不用在按钮、链接、焦点环、选中、格点、图标、插图、标志、忙碌指示上。

选 Braun 橙 #E0652A 的理由：对机面 3.4:1，过非文字 3:1；黄绿只有 1.9:1，开关状态看不清（⑪）；更深的安全橙向红偏，会被读成告警（⑥），和「开着」相反。

**为什么不违反 ⑤**（「零色彩」原本是 ③ 的手段，不是原则本身）：⑤ 要的是同形同义、异义异形——橙只有一个义、两种形，说的是同一件事，所以同色，全应用没有别处的橙；格子里的 ● 说「这份文件在」（文件事实），开关说「一个正在运行的东西此刻在用这份设置」（运行状态），两件事不同，所以 ● 仍是墨色，涂橙就成了一色两义；③：橙的总面积是几道 8×2 的刻线和 6px 的点，一屏最多两三处，只在「开着」时出现，不会成为第二个主角。

**强调的三档不变，橙不在其中**：次要文字（`ink-mute`）→ 加粗 → 墨面（`ink` 底 `face` 字）。

**破坏性操作靠信息和文案承担分量，不靠颜色。** 删除的确认框写明后果（哪些 agent 不能再用、几条链接一并删除）；主动作写动词（`删除` `删掉` `移除`）而不是「确定」——用户读完就知道会发生什么，再涂红就是吓唬人。橙也不当警示色用。

深色模式本轮不做（材质要整体反转，另起一轮）。

## Typography

### 字族：Barlow + Barlow Condensed + 苹方，等宽只给 id

2026-09-24 产品负责人：「这版的字体和 logo 都不如之前，字体和 logo 都维持原来的设计。」V4 曾换成 Inter + 小写结构词，现回到原字族与原大小写规则；**字号档沿用 V4 的六档**（D1–D14 的布局按这些尺寸推导，不回退）。

- **Barlow 400 / 500 / 600**：正文、按钮、副行、计数（`tabular-nums`）。
- **Barlow Condensed 600 / 700**：页面名、区域小标题、页签、区块小标、列头；字标的字形也取自它（700，见「标志」）。
- **IBM Plex Mono 400 / 500** 只给 id、路径、版本号（`deepseek-chat`、`~/.agents/skills`、`0.1.0`）。
- 三个字族都没有中文字形，汉字回退到苹方：`Barlow, "PingFang SC", "Microsoft YaHei", sans-serif`（Condensed 与 Mono 同样的回退栈）。字体文件打进应用、只收拉丁子集与上面这些字重，不走 CDN。

### 大写是结构的语言，原样是内容的语言

- **我们自己写的、纯拉丁的结构词：Condensed 大写 + 正字距**，只作用于它的拉丁 run：页签 `SKILLS` `MCP`（以后 `SESSIONS`）、侧栏区块小标 `AGENT`、MCP 列头第二行 `LOCAL` `PROJECT`，以及**表格列头里的 agent 名**（`CLAUDE CODE`：列头是 agent 身份，自成一组，图标在上名字在下，⑤ 同形同义）。实现只有一条路：`<Cap>` 组件按脚本把文本切成 run，只给拉丁 run 套 Condensed + 字距 + 大写；数据本身不改；画板里等价于只给拉丁 `span` 写这些属性。本文件正文里提到页签仍写词本身（`skills` `mcp`），界面上以 Condensed 大写显示。
- **被谈论的对象一律原样**：agent 名是专名，列头之外全产品写 `Claude Code` `Codex`——句子、行名、页面名、侧栏项、选择行、设置、托盘；**文件系统来的名字一律原样**（`defuddle` 转成 `DEFUDDLE` 后跟表格里的名字对不上）。
- **中文句子里的拉丁词不大写**：`在以下 agent 开启` `哪些 agent 出现在列表里`——句子是内容，只有独立成词的结构标签才走 `Cap`。
- **按钮不走 Condensed、不大写**：按钮几乎都含汉字，`button` 档 = Barlow 13 / 600 / 字距 0；专名嵌进去原样写（`删 WeiboAP 的`），中西文之间一个普通空格。
- **表头不混排**：我们自己写的汉字列头与区块小标（`名称` `来源` `传输` `项目` `位置`）走 `label` 的字号字重、字距 0、不变换；纯拉丁的结构词与 agent 列头走 `Cap`。
- **skill 名用 `body`，不用 `mono`。** 等宽的理由是路径要对齐、要分得清 `l` 与 `1`；skill 名在列表里是当词读的。

### 字距：汉字永远 0

界面绝大部分文字是中文，会落到苹方。Condensed 大写 + 字距是给 `SKILLS` `MCP` `CLAUDE CODE` 这种**纯拉丁标签**用的；套到汉字上，「删 通用仓库 的」字字散开，窄体大写挨着常宽苹方，同一行像两套系统（评审第 1 轮的最大字体问题）。规则：**`letter-spacing` 与 `text-transform: uppercase` 只经 `Cap`、只作用于纯拉丁的 run，汉字一律 0**（lint 查这条）。字距取原值：`nav` 1.17px、`label` 0.96px、`head` 1.1px；**页面名（`title`）原样、不大写、字距 0**（`添加来源到 CardBox`、`Codex`）；没有负字距。字标是 SVG 资产，字距在资产里（0.095em）。

## Layout

基准 8px，子单位 4 / 12 / 16 / 18 / 24 / 32 / **48**。

窗口的壳（侧栏 + 一块机面）与各屏布局是 Sophia 的产品裁决，见「产品裁决 › 壳」与各屏小节。

### 色块：要不要、多大（2026-09-25 产品负责人：「再审视下全局各种背景色块的使用，首先是是否要用，其次是如果用是统一大小，还是根据文字自适应」）

**要不要：色块只给两种东西**，别的一律不垫底色（① 每个元素都要回答「拿掉它用户会少知道什么」）：
1. **能操作的东西**——键、来源胶囊、模型片、输入框、页签槽、开关槽、浅键。色块就是「这里能按 / 能填 / 能选」（⑧）。
2. **要从正文里拎出来的一句话**——灰面板（有问题要你处理）、新手提示条（告诉你一声）、悬停 / 选中的行带、选择行。色块说「这不是内容本身」或「这一行正被你指着 / 选着」。

只是把一段内容「框起来」的色块不要：抽屉里的详情、确认框里的路径、列表的分组——它们已经靠缩进、行线、等宽字说清了归属，垫一块灰只是多一层要读的东西（2026-09-25 撤掉抽屉与路径铭牌的底色）。

**多大：按它是什么来定，不按字**：
| 色块 | 宽 | 高 | 理由 |
|---|---|---|---|
| 键、胶囊、模型片、浅键 | **随字**（左右留白固定） | 固定档（28 / 26 / 24） | 它是一个东西，大小就是它的名字；同一行里同高（「同一行里的控件同高」） |
| 输入框 | 固定（按用途：筛选 200、表单 360） | 固定 28 | 它装的是还没打的字，不能随字伸缩 |
| 菜单浮层 `Menu`（排序下拉、选目标、同名挑选） | **随内容**（设上限，超了在里面折行；左右留白对称） | 随项数 | 它是一组可点的项，和键一样随字；定宽配短项会在右边空出一大块 |
| 灰面板、新手提示条 | **随网格**（内容宽 776，左右沿与表格一条线） | 随内容（最少 40） | 它说的是这一页 / 这一节的事；随字宽会让右沿参差，一屏几种右沿就是「乱」 |
| 行带（悬停、选中、选择行） | 整行 | 行高 | 它指的是整行 |
| 页签槽、开关槽 | 随里面的滑块排布 | 固定 | 槽是滑块走的轨道 |

## Elevation & Depth

**投影只有一个意思：离机面的高度**（⑤ 同形同义；2026-09-24 物性由「这层浮在页面上面」推广而来）。高度分四档，**同义不同量**——影子越大越软，东西离机面越高：

| 档 | 规格（色一律 `rgba(28,28,26,…)`） | 给谁 |
|---|---|---|
| **凹**：低于机面 | `recess-tabs` / `recess-track`：inset 0 1px 2px .06 + inset 0 0 0 1px .04 | 只剩两处：页签槽（`recess-tabs`）、开关槽（`recess-track`）——槽里有东西在滑，槽的内沿说明滑块在哪条轨道里走，是必要的。输入框、铭牌、抽屉都是平的浅灰面（2026-09-25 产品负责人：「尽量只在必要的时候使用阴影来体现层次」），输入框靠 1px `hairline` 边 |
| **平**：在机面上，无投影 | `hairline` / `row-line` / `ctl-border` 的 1px 边 | 机面、行、片、格点、灰面板、表格——**一切平铺的东西**；禁用的键与开关（按不下的东西不离开机面） |
| **抬起**：离机面一点点，手能碰 | `raise`：0 0 0 1px .07, 0 1px 2px .10, 0 2px 6px .05<br>`raise-hover`：0 0 0 1px .09, 0 1px 2px .12, 0 3px 8px .07<br>`raise-pressed`：0 0 0 1px .09, 0 0.5px 1px .10<br>`raise-ink`：0 1px 2px .28, 0 2px 6px .14<br>`raise-ink-pressed`：0 0.5px 1px .30 | 默认键、墨键、页签选中滑块、开关滑块。静止 / 悬停（手靠近，影子略重、不位移）/ 按下（贴近机面，影子收紧）三态；`raise` 的 1px 环替代 `ctl-border` 描边——边由投影给，不再单画 |
| **浮**：最高 | `float`：0 12px 32px .12 + 1px `hairline` 边（提示框无边） | 菜单浮层、确认框、提示框、提示条 |

- **抬起只给手会碰、会动的三样**（键、页签滑块、开关滑块）：投影在这里说「它离机面有一点高度，能被按下去」（⑧ 可供性），不说「重要」。片是平的——片与键并排时靠形状与抬起区分（胶囊平贴＝选择，矩形抬起＝动作）。唯一的例外是勾选框：只在手靠近时借 `raise-hover` 抬起迎手，静止与勾上都平贴。
- **凹与抬起配对出现**：页签滑块在凹槽里抬起，开关滑块在凹槽里抬起——同一件实物的两面（参考：浅灰槽里一枚带柔和投影的白色滑块）。
- **`rgba()` 只能出现在这些 elevation token 的定义里**；别处一律引用 token。
- **渐变只用于功能，不做装饰**：可滚动区域被裁掉的边缘 16px 渐隐（从它所在的那一面到透明：机面 `face`、浮层内 `paper`、侧栏 `shell`；`+ 项目` 吸底时的上沿改用一条 `row-line`，2026-09-25），提示那边还有内容。开关滑块、按键、机面都不用渐变、高光或内发光。
- 确认框的遮罩是 **`ink` 16%，整面压暗**（见 `DESIGN-components.md`「确认框 Confirm」）。

| 控件矩形 | `control` 7 | 按键、输入框、图标按钮的悬停底、侧栏选中项、菜单高亮项、提示框 | **点了会执行一个动作 / 在这儿输入** |
| 面与浮层 | `face` 12 / `float` 12 | 机面、灰面板、新手提示条；菜单浮层、确认框、提示条、托盘面板 | 一块面（平的或浮起的，由有无投影区分） |
| 槽 | `tab-track` 10（滑块 `control` 7）；开关 `track` 5 / 滑块 `knob` 4 / 刻线 `scribe` 1 | 页签滑槽；开关 | 手会拨的实物 |
| 胶囊 | `pill` 999 | 来源筛选的每一项、Codex 页「在用」的模型片 | **选中 / 在用的一项**（平贴、不抬起，与抬起的键分开） |
| 圆 | `dot` 50% | 状态点、指示点、格子悬停光晕 | 只读状态 |
| 小方 | `mark` 4 | 勾选框、首字母方块 | 记号 |
| 直角 | `none` 0 | 表格行、行带、分隔线、刚点亮的格子反色 | 平铺的结构，不是一块 |

**不在这张表里的值不用**（lint `radius`）。**页签与开关维持圆角矩形的槽与滑块**（2026-09-24 产品负责人看过物性样张：「圆角我还是喜欢这个」——物性只改投影、按压、弹簧与拖动，不改形状；⑦ 尊重已学会的）：它们是手会拨的实物，形状与胶囊片不同，片与槽不混（⑤）。

**有框的都能点。** 不可点的标识（`同名` `Codex 不支持` `无法连接` `已添加`）是**没有框的 12px 文字**，也不加任何装饰线（D21）：强的 `ink` 600，弱的 `ink-mute` 400。第 2 轮评审指出，靠圆角区分「标签」和「按钮」不成立——带框的 `同名` 和行内按钮 `清除` 肉眼不可分。

## 标志与插图

### 标志：字标、应用图标、托盘图标

**标志资产是品牌，不随界面 token 换色**（2026-09-24 产品负责人：「字体和 logo 都维持原来的设计」）。`assets/logo/*` 就是标志的唯一来源，界面与画板引用它们，不重画、不按 V4 色板重新配色；V4 的色板只管界面。标志的构成与生成方法见 `assets/logo/README.md`，下面只写界面怎么用它。

**同一个构成贯穿三处**（⑤ 跨触点一致）：一个大写 `S`（Barlow Condensed 700 的字形轮廓，SIL OFL 1.1，从字体文件取出、不照着描，所以图标的 S 与字标的 S 是同一个字），**左下方**带一重灰色重影，错位是字高的 **(0.25, 0.093)**，主体与重影**重合处用更浅的一档灰**——寓意复制。扁平：没有渐变、阴影和透明度（托盘图标例外，见下）。**标志里没有橙**：标志不是一个开着的状态，橙在标志里就有了第二个意思（⑤）。

**字标**（侧栏顶的字标带，D1 起；位置与几何见「壳 › 字标在侧栏顶」）：
- 整条大写 `SOPHIA`，Barlow Condensed 700 轮廓，字距 0.095em（在资产里）；**只有首字母带重影**，重影与标志同一错位、同一重合处浅一档。
- **用资产，不用纯文本**：`assets/logo/wordmark.svg`（浅底）/ `wordmark-inverse.svg`（深底）；写成 `<h1>Sophia</h1>` 就丢了首字母重影这个识别点。`alt="Sophia"`；字标区不当拖窗区。
- **高 26**：20 时首字母后那层重影只有约 1px 位移，读起来像套印错位；重影要么大到明显刻意，要么不要——产品负责人要它，所以放大。侧栏字标带 44 高放得下。
- 颜色是资产里的（浅底版主体纯黑，重影与重合处两档灰），**不取 `currentColor`、不换成 `ink`**：落在机壳 `shell` 上对比足够。

**字标动效：黑猫与玻璃**（产品负责人定稿，原型 claude.ai/artifact/2fcVo2BxLPdNQrrcskYAYq 第 21 版；V4 起猫与裂纹的取色读界面 token，字母与行为是原版）。这是 ① 里「值得」、⑱ 里「有性格但不喧宾夺主」的那一处细节：**猫只出现在字标动效和空态插图，不进控件、托盘和图标**（⑤；托盘不用猫：产品负责人「和 logo 对不上」）；平时完全静止，只由用户在字标上停留唤起（① 回应的边界）。
- **触发**：鼠标在字标框（命中区见「壳 › 字标在侧栏顶」）上停 0.4 秒才开始，从不自动播放、不循环、首次启动不演示。开了 `prefers-reduced-motion` 时猫不出现，点击也不碎，字标保持静止。
- **猫**：一只黑猫从右边走进来，在字母间穿梭：`S` `P` `I` 在猫后面，`O` `H` `A` 在猫前面。猫身 `ink` #1C1C1A，外面一圈 `paper` 白描边，和墨色字母分开。
  - 造型只用墨、白、灰，矢量绘制：大圆头、脸微侧露出一大一小两只 `paper` 白眼（瞳孔 `ink`）、大三角耳、细须子与鼻头 `ink-mute`（须子不描白边）、身子修长、腿细长配圆爪、尾巴上翘末端卷成螺旋。大小为字标高度的 0.52 倍。**不用橙**（猫不是状态）。
  - 行为：四拍慢步，着地的脚不打滑；走到随机位置停下，约 0.35 秒后坐下；鼠标在身后时转身看你，瞳孔跟着鼠标，偶尔眨眼，停下时歪一下头；鼠标靠近会被吓到、快走几步；点到猫附近它会跳一下。
- **敲玻璃**：点击字标就是敲在玻璃上，从点击处沿放射加同心环方向裂开，裂纹逐步蔓延，并带次级裂纹；裂纹是**白色**（`paper`），主次同色、靠粗细与透明度分——黑字上的裂痕要亮才看得见（V4 一度改成 `ink-mute` / `ctl-edge`，产品负责人：裂纹没之前明显、看不清；随字标回到原设计改回）。随机敲 2～4 下后字标碎开，猫受惊跑走，碎片带物理效果落到**字标带的下沿**（窗口 y 72，看不见的地面；D1 删顶栏前落在顶栏底边），左右不出侧栏、不越进机面、不落进导航项。碎片沿真实裂纹切分，恰好铺满整个字标（含重影），碎片上是字标资产本身的颜色。
- **复原**：鼠标移开时——
  - 没碎：裂纹淡去；
  - 碎了：等碎片落定（最多 1.2 秒），按离敲击点的距离错开托起，用阻尼弹簧弹回原位；基本到位后，完整字标在上面约 0.8 秒渐显，裂纹愈合，全程没有突变。
- **边界**：只在侧栏顶的字标这一处；动画只在悬停和复原期间跑，静止时不占帧。画布对读屏隐藏。动效自己画的东西（猫、描边、眼、须子、裂纹）取色一律读 token 变量（`--ink` `--paper` `--ink-mute` `--ctl-border` `--ctl-edge`），不写字面值；字标本身与碎片是资产原色，不换色（见上）。原型里的慢放开关、状态读数和说明文字只是演示，不进产品。

**应用图标**（Dock、访达、⌘Tab）：**原资产原样**——`assets/logo/app-icon.svg`：1024 画布、824 圆角黑底板居中（四周 100 透明边，贴合 macOS 图标网格），板上白 `S` 与左下灰重影、重合处浅一档，两个 S 的整体外框在板上居中。**不按 V4 重新配色**（不换成 `face` 板、不出血）：标志资产是品牌，不随界面 token 换色（见本节开头）。图标里不画投影、不画渐变。`src-tauri/icons/` 下的位图全部由它生成（`npx tauri icon assets/logo/app-icon.svg`，命令与只收哪些文件见 `assets/logo/README.md`），不手改位图。

**托盘图标**（菜单栏）：**原资产原样**——`assets/logo/tray.svg`，单色模板图（`icon_as_template(true)`，系统按菜单栏深浅着色；只有纯黑 + alpha，透明度保留）：主体 `S` 实心，重影填 **45%** 垫在左下；**水平错位加到标志的 1.6 倍、垂直保持原比例**（按原比例 16pt 下重影只露一道窄边、读成字边发虚；2.4 倍又分成「SS」）；「重合处浅一档」这里不做（小尺寸下主体会碎）；两个 S 的整体外框居中、高占 93%。导出 **44×44**（菜单栏 22pt 的 2x）的 `src-tauri/icons/tray.png`，生成命令照 `assets/logo/README.md`。不用猫（产品负责人：「和 logo 对不上」）。

### 图像（① ⑱ 愉悦与归属感，③ 不与数据抢主角）

- **只用在没有数据、等待、刚开始的时刻**：首次启动与首次扫描、还没有来源、这个位置没有 agent 目录、一个 skill 都没有；筛选无结果不放图。**设置「关于」不放图**——一组标志不回答任何问题，还会被读成「只支持这几个」（⑭）。**有数据的表格视图不放图**。
- **一种风格：品牌小黑猫配线稿文件夹**（产品负责人：原占位图不好看，换成字标动效里那只小黑猫）。猫与字标动效是**同一个角色**，扁平绘制。**物件只画真实存在的东西（文件夹），猫是唯一的角色**；虚线文件夹表示「还不存在、添加时会建出来」。三张图各对一个时刻：
  - **扫描中**：猫走在一排文件夹顶上，低头看下一个（472×150 原样显示，不裁切）。
  - **没有 agent 目录**：猫伸爪碰一个虚线文件夹（250×110）。
  - **这里还没有 skill**：猫扒着空文件夹的沿往里看（250×110）。
- **V4 用色**（只用 token 值）：猫身 `ink` #1C1C1A；眼白 `paper` #FFFFFF、瞳孔 `ink`；须子与鼻头 `ink-mute` #4E4E4A；文件夹 1.4 描边 `ink`、填充 `paper`；虚线文件夹描边 `ink-mute`；地线 `ctl-border` #D4D4CF。**不用橙**。
- **落在机面上，看不出框**：图的底**透明**（首选，PNG 带 alpha），或者恰好等于 `face` #FCFCFB；不允许白底 #FFFFFF 或任何别的底色——在机面上会露出一块方框。边缘不留抗锯齿白边（导出时背景按 `face` 去底）。2x 资源。
- **构图**：见 `DESIGN-components.md`「空态 Empty」。
- **禁止**：发光、景深、假金属、3D 质感、橙与任何彩色、人物（猫之外不加角色）、画面内文字、动效（空闲静止）。

## 组件使用指南

这一节回答「该用哪个组件」：每个组件只做一件事、什么时候用、不要用在哪、和谁容易混。尺寸、状态、token 这些精确规格只在 `docs/DESIGN-components.md`，这里不写。组件名是 `src/ui` 的导出名。

**组件库的边界**（对齐 Claude Design「Set up your design system」与 `/design-sync`）：

- `src/ui` 里的组件只收 props：不调 Tauri 命令、不读页面状态、不自己决定文案。带业务逻辑的共用件放在页面层（见本节末「不进组件库、在页面层合并的」）。
- 颜色、字、圆角、层次、动效只从 `src/tokens.css` 取，组件里不写字面值。
- 每个组件配一组用 Sophia 真实内容写的示例（`重启生效`、`✓ 已加到 Codex · 撤销`、`通用仓库 26`……），覆盖它的各个状态（静止、悬停、按下、焦点、禁用、忙碌）；示例就是活样张。
- 页面不直接写组件的内部类名（`ss-*`），要改长相就改组件；同一种 UI 不在页面里再写一份。

### 键

键的阶梯是墨键（主键）→ 默认键 → 浅键，三档各有一个意思（⑤）：主键＝这一面的主动作，默认键＝在 Sophia 里做一件事，浅键＝离开 Sophia。「次要」「单独出现」都不是换一档的理由；「去了外面」是——点下去之后发生的事不一样（换到访达、浏览器），键就该不一样。

| 组件 | 一件事 | 什么时候用 | 不要用在 | 和谁容易混 |
|---|---|---|---|---|
| 主键 `Button variant="primary"` | 这一面的主动作，一面至多一个 | 确认框的主动作、`添加 N 个来源`、表单的 `保存` | 一般动作；表示「已选中」 | 默认键：主次只靠墨与纸分开 |
| 默认键 `Button` | 在 Sophia 里做一件事 | `重启生效` `再试一次` `管理来源` `检查更新` `撤销` `只留这份` `清除筛选`；`取消` `稍后` 也是它（macOS 惯例：取消是一颗正经的键）；单独出现的动作都用它 | 离开 Sophia 的跳转 | 浅键 |
| 浅键 `Button variant="quiet"` | 离开 Sophia，末尾一律带 ↗ | `打开 ↗` `在访达中显示 ↗` `在访达中显示备份 ↗` `去发布页 ↗` | 应用内的任何动作，包括 `取消` `稍后` | 默认键 |
| 添加键 `AddButton` | 开始一个添加流程，写 `+ 名词` | `+ 来源` `+ 网关` | 提交一次添加（那是主键）；侧栏的 `+ 项目`（那是侧栏的一行） | 默认键：它就是带 `+` 的默认键，不另造长相 |
| 图标键 `IconButton` | 图标词表里有图形的工具动作 | 铅笔 `编辑`、垃圾桶 `删掉`、× `移除` / `关掉`、← `返回` | 词表外的动作（写字，用默认键）；导航项（侧栏 `设置` 的齿轮是导航项） | 默认键：键是「动作」、图标键是「工具」，它不抬起 |

禁用是每种键的一个状态，不是又一种键：平贴、必须带原因（`disabledReason`），按下即说原因。忙碌也不是键的状态，由包在外面的 `BusySlot` 负责。

### 提示与反馈

按「谁开口 × 会不会自己走」分开，一件事只在一处说（① ⑤）；锚在哪、留多久是一套总规则，见「Patterns › 反馈」。

| 组件 | 一件事 | 什么时候用 | 不要用在 | 和谁容易混 |
|---|---|---|---|---|
| 提示框 `Tooltip`（含禁用原因 `ReasonTip`、截断全文 `TruncTip`） | 悬停或键盘焦点时，补一句屏幕上没写的 | 格子的动作说明、禁用原因、被截断的路径与名字、图标键的名字 | 屏幕上已经写着的话；刚做完的结果 | 提示条：提示框是用户去问，提示条是 Sophia 来报 |
| 提示条 `Toast`，放进 `FloatingToast`（锚在触发控件上）或 `CornerToast`（右下，只给后台发生的事） | 刚做完的结果，会自己走 | `✓ 已加到 Codex`、做不成、部分失败、`✓ 已是最新版本`、后台规则做了的事；单格要等时的忙碌 | 要用户处理的事、带下一步的失败 | 灰面板 |
| 灰面板 `NoticePanel`（`scope`：应用级 / 一节 / 一行） | 不会自己走、要你处理 | 应用级故障、`路由没在跑 · 重启路由`、`没重启 Codex · 再试一次`、网关拉不到模型、有新版本 | 一次性的结果 | 提示条；新手提示条 |
| 新手提示条 `HintStrip` | 第一次走到这里时说明这里怎么用，只有 × | 首次扫描后、第一次进 Codex 页 | 报状态、催做事 | 灰面板：新手提示条更浅、没有 `!`、没有动作键 |
| 确认框 `Confirm`（另有托盘里的窄面板形态） | 真正不可逆的决定，问一次 | 删原件、删网关、重启 Codex（全部见「产品裁决 › 哪些要确认」） | 可撤销的操作（给撤销，不问）；说明与提示 | —— |
| 忙碌 `BusySlot` + `Spinner` | 用户发起、正在等的那颗控件原位忙碌，带一句「正在…」 | 重启、检查更新、批量写入、保存网关 | 后台例行读取（不显示忙碌）；没有文字的转动 | —— |

### 选择

| 组件 | 一件事 | 什么时候用 | 不要用在 | 和谁容易混 |
|---|---|---|---|---|
| 开关 `Switch`（另有紧凑形态） | 当场生效的布尔状态，对象就是它所在的那一行 | 第三方模型（Codex 页与托盘）、来源的「以后新出现的自动加到」 | 选择一组东西；需要一次提交的多输入 | 勾选框：开关＝它开着，勾选框＝我选了它 |

| 模型片 `ModelChip` | 一个在用、可以拿掉的值 | `在用` 一行的模型 | 筛选 | 筛选片：差别在 × 与颜色 |
| 菜单 `Menu` + `MenuItem` | 浮层里的一组选项；项有普通、单选（✓）、多选（勾选框）三种，可带副行 | 排序方式、选目标、挑同名的哪一份、托盘的 `打开 Sophia` `退出` | 页面上常驻的列表（那是勾选行或列表行） | 勾选行 |

## Patterns

**这一节只放与产品无关的组织法**——换一个产品、换一批对象，这些规则照样成立。凡是「本产品叫什么、算什么、显示几个、哪一屏放什么」的裁决，一律去「产品裁决」。

### 反馈：浮起＝会自己走，内嵌＝不会自己走（2026-09-23 全局统一）

**这一节是反馈形态、位置与停留的总规则，全文只此一处；别处与它冲突以本节为准。** 来由：全局盘点（约 30 处反馈用了 9 种摆法、12 / 13 / 15 三档字号、3 种淡出写法）+ 产品负责人：「提示一种是悬浮的，一种是内嵌在页面的，悬浮的体验更好，内嵌会让我不确定它是否会消失、何时消失，还会造成遮挡」；「字号会很大，位置有时候出现得奇怪」。

| 形态 | 只表示一件事 | 长相 | 给谁 |
|---|---|---|---|
| **浮起的纸窗**（提示条 `Toast`） | **会自己消失**（⑧ 外观说明行为：浮着的一层天然读作临时） | 纸窗（`paper` + 1px `hairline` 边 + `float` 12 圆角 + `float` 投影），**文字一律 13**，动词 600、名字 400、数字 12 tabular——比表格正文 15 低一档，反馈永远不比它说的内容更重（③）。成功句首 ✓；做不成、部分失败是**同一种纸**，左侧记号栏放 ⊘ / !、动词带否定——2026-09-25 起提示条不用墨（产品负责人：黑条提示都不要了） | 所有「刚做完了什么」：单格、行、批量、添加来源之后、重启 / 启动之后的 `✓ 已生效 / 已启动`、`✓ 已是最新版本`、设置里取消勾选的说明、后台自动规则做的事；单格与一次操作的失败原因 |
| **内嵌的灰面板**（`NoticePanel`） | **不会自己消失**：要你处理，或问题解决了才走 | `surface` 实底的一块面，嵌在页面流里；**大面积不用墨**（一整条黑太重；灰在机面与墨之间，够醒目又不抢），也不用橙 | 要你拿主意的事、**带下一步的失败**（`再试一次` `重启路由`）、持续的状态（路由没在跑、设置被改掉） |

不再有「墨字直接落在机面上、无框无底」的内嵌例行一行——它长得和页面内容一样，读不出会不会走、何时走，还会把内容挤开（2026-09-23 取代「墨字落在机面上的例行成功一行」与单格「就在被点的那一行里，紧跟名字」）。

**锚点**（② 就近、就近不遮挡；硬规则）：**锚在被按下的那个控件上**（不是它所在的行或区域的某个固定角），间距 ≤ 16px（1x）；**不盖住被点的那个控件，也不盖住它所说的那一格 / 那一行**；别处的内容可以暂时盖住，4 秒就走。

| 触发 | 锚点 |
|---|---|
| 一个格子（成功与失败同一个位置） | 那一格正下方 4，水平居中于格；靠近面板右沿时右对齐该格 |
| 一行里的一颗控件 | 那颗控件正下方 4、对齐它（行尾 `×` 就右对齐 `×`）；行被删掉时锚在控件原来的位置（产品负责人：移除来源的提示出在左边很奇怪，删除按钮在右边） |
| 批量（按下选择行里的一个点） | 那个点正下方 4、居中于该列，靠面板右沿时右对齐该列——与单格同一种锚法（⑤） |
| 一颗键引起的结果（重启、启动、检查更新、选文件夹） | 那颗键正下方 4 |
| 不属于任何一处的（后台发生的事） | 右下（`CornerToast`）：右沿对齐机面右沿向内 16、底 16；**全应用只有这一套**（壳上一处，各页不另有一套）。页面贴底有一行动作时整叠抬到那一行上面，不盖住这一页的主动作 |

各屏逐个场合的锚点见「产品裁决 › 反馈在各屏的位置」。

- 行内动作跟在描述后面（网关「再试一次」紧跟「无法连接」8px）。**列表里多行各有动作时，动作成一列**：句子列宽取最长一句的实际宽度（不为假想长句预留，超出换行），行线止于动作列右沿 + 24，动作列紧随其后、固定起点（离句子列右沿 16）——既就近又对齐，扫一列决定时眼睛不用逐行找键（⑥ 惯例压过逐行贴句尾）。
- 开关、它控制的对象、它引起的下一步三者落在同一处（Codex 页：节名 + 开关 + `重启生效` 成组，结果挂在键下）。页面级提交（`添加 N 个来源`）不受 16px 限制。具体准则不能压过它服务的原则：曾把格子提示框挪到面板外 170px 以「不盖任何数据点」，违反了「就近出现」，已撤回。

**出现的那一刻定位，之后钉在窗口上**（产品负责人：新提示不应该随页面滑动）：位置按锚点在出现那一刻的屏幕位置算一次，之后固定在窗口里，不跟着滚动、不被滚动容器裁掉；锚点滚走了它也留在原处，到点淡出；贴窗口四边留 16。

**停留**（⑪）：成功无动作约 4 秒（只是告知；产品负责人：消失得很慢）；带 `撤销` / `查看` 约 6 秒；做不成 / 部分失败 8 秒；**悬停与键盘焦点在里面时停表**；全部用同一个淡出（末尾 120ms 机械缓动）。一次只一条：同一范围里新的替换旧的。
带下一步的失败不用浮窗，用内嵌灰面板（不会自己走）：托盘的「没重启 Codex」也改为灰面板。

**一个组件、一套定位**：所有浮起小窗都是 `Toast`，放在 `FloatingToast`（锚在控件上）或 `CornerToast`（右下）里，定位走同一个锚定函数（`layerPlace`）；各页不再自写 absolute / fixed 偏移。

**忙碌**（⑪ 收到了、正在处理；⑮ 控制权）：
- 结果可预测、可回滚的（开关、勾选、格子）：先按用户的操作画出来，后台写，不显示忙碌；失败回滚并说原因。
- 真要等的：触发它的那颗键**原位**换成刻度 +「正在…」；**统一 0.3 秒门槛**——0.3 秒内完成就不出现（不闪一下），超过才出现；现在「点下去什么都不显示」的（只留这份 / 移除来源的影响预览、删网关、移除来源）一律补上。
- **只锁触发它的那个控件**（和对同一对象的下一次操作——排队）。不把整页变暗，不锁别的行、别的页签、项目切换（取消「来源页移除一个来源整页变暗」「模型页重启时锁页签」这类）。

### 反馈：四个地方会说话，一件事只在一个地方说

| 说什么 | 在哪 | 形 |
|---|---|---|
| 刚做完了什么（会消失） | 提示条 `Toast` | 浮起的纸窗，锚法与停留见上；一次操作汇总成一句，不排队；动作（`撤销` `查看`）行内右置 |
| 不会自己走、要你处理 | 灰面板 `NoticePanel` | 应用级故障在机面顶上、页面头之上；只属于一节 / 一行的挂在那一节 / 那一行里（行内待办条）：一句话 + 紧凑键（需要时 + `稍后`） |
| 要你拿主意，散在几十行里 | 就地记号 | 行上 `×2`、格内异常记号，就地处理（没有收件箱，也没有新问题一次性提示） |
| 第一次来这里要知道的事（关掉或学会就不再出） | 新手提示条 `HintStrip` | 嵌在内容上方的一条浅灰条，一句 + `×` |

悬停补一句屏幕上没写的是提示框 `Tooltip`：它是用户去问，不算 Sophia 开口。上游服务够不着这类失败（网关拉不到模型列表）不是某次点击的结果，是那条链路此刻不通，用户得读完再走：灰面板挂在那一行下，不用会自己走的提示条。

### 撤销：再点一次能不能准确复原（⑬）

- **天然可逆的不另给 `撤销`**：开关、格子这类「再点一次就是准确反操作」的，撤销入口就在光标底下，再放一个 `撤销` 是重复（⑤）。`⌘Z` 照旧可用，但它看不见，不算挽回入口。
- **`撤销` 只留在没有顺手反操作的地方**：再点不能准确复原（会抹掉原来有有无无的状态）、不是用户点的（后台规则做的事）、离开了视线再找回来难（从列表里移除）、删了之后界面上没有别的退路。
- **撤不了就说实话**（⑭）：还原的前提不在了（文件又被改过）时 `撤销` 禁用并说原因，给一个手动兜底。
- Sophia 里具体哪几处给见「产品裁决 › 格子与批量的撤销」「删除原件」「MCP 写入的撤销」。

### 自动发生的事要交代（⑪⑮）

规则在用户没动手时做了事（Sophia：自动加到的规则建了链接）：出一条右下提示条交代（`✓ 自动加到 [Codex] 3 个 · 撤销`——不是用户点的，表上没有一个键能原样撤回，所以带撤销），状态直接变成新样子（不闪、不依次）；在管这条规则的地方能查到最近一次自动操作（提示框 `2 分钟前 · 加到 3 个`），规则开没开由它自己的开关说。

### 视觉优先：文字只负责名字和动词

**状态、关系、后果、进度、位置，一律画出来；文字只负责名字和动词。**（产品负责人：「尽量通过视觉就能理解操作，而不是文字」。）不是把按钮都换成图标——认不出的图标比文字更糟，图标词表之外的动作继续写字。要换掉的是「用句子描述一个本可以看见的东西」。底线：**每个新图形在设计资产板有图例、悬停 `title` 给出文字、屏幕阅读器文本不减**。

Sophia 里逐项怎么画见「产品裁决 › 视觉优先的落实」。

### 说结果，不说机制

软链是我们的实现手段，不是用户的目的。**只在用户需要据此判断时才提软链**——删原件的弹窗要说「2 条链接会因此失效」，因为那正是他要权衡的；其余时候说他能看见的结果。

| 别写 | 写 |
|---|---|
| 添加＝在选中的 agent 下建软链接 | 让这些 skill 出现在「全局」的列表里 |
| 没有需要建立的链接 | `<agent>` 下已经有同名的 `<skill>`，没有覆盖它 |
| 操作失败，请重试 | 无法写入 `<agent>` 的 skills 目录 |

### 文案语域：平实、完整（D24，⑯ ⑥）

**全应用一个语域：平实、完整、不俏皮，接近 macOS 的中文本地化。** 同一个界面里「探明」（书面）与「换一把」「没成」（口语）并存，读起来像几个人写的（⑯ 微文案语气一致）。

- **状态词与失败原因用「无法 + 动词」**，不用口语的可能补语（`写不进` `搬不过去` `连不上`）。
- **句子写完整**：不省到只剩俚语（`出来了` `没成` `换一把`），也不用公文腔（`探明`）、俏皮话（`顺手` `拿主意`）。
- **失败主句的「动词带否定」照旧**（`没加到 [c] · 原因`、`没重启 Codex`）：它平实、完整，而且否定必须落在动词上（见 `DESIGN-components.md`「提示条 Toast」）。
- **保留用户语言**：`原件` `同名` `只留这份` `加到 / 从 … 移除`——那是产品负责人定的用户的词，不是语气问题（⑥）。
- **不指向已经不存在的地方**：删掉的页面、改名的入口，提示里一并改掉（⑨）。
- 旧说法 → 新说法的对照表见「产品裁决 › 文案旧词表」；`scripts/lint-ui.mjs` 的旧词表与它的左列同步，防回潮。

### 命中区与视觉尺寸是两回事

**视觉可以小，命中区不能小于 24×24。** 14px 的勾选框、片上 9px 的 `×`、6px 的指示点——它们的**视觉**尺寸由层级决定，但点击目标要用透明外圈撑到 24px 以上；列表行里的选择记号更进一步：**整行可点**，记号只是告诉你点了会发生什么。

**撑命中区不能改变视觉尺寸。** 用 `padding` 撑的话 `border` 会画在 padding 盒外沿，13px 的框就成了 26px——模型选择器里的勾选框就是这么变大的，和 skill 列表里的一比就露馅。正确做法：视觉元素保持自身尺寸，命中区用伪元素或透明 `outline`/负外边距的包裹层撑，不动 border。**同一个记号在全应用里只能有一个尺寸。**

### 可点的面：hover 怎么表示

V4 里能用的是边的深浅、底色与抬起的影子（橙不参与悬停），按面的形态分三种：

| 面 | 静息 | hover |
|---|---|---|
| 有边的块（输入框、目标小框） | `hairline` / `ctl-border` 边 | 边升一档（`ctl-border` → `ctl-edge`；输入框聚焦 `hairline` → `ink-mute`），**底色不变**——换底色会把里面的片糊掉 |
| 无边的列表行（侧栏项、表格行、列表行、勾选行、菜单项） | 无边 | 底色转 `surface`——整行能点就该有这一层回应 |
| 抬起的键与墨面（默认键、墨键、页签与开关滑块） | 键与滑块抬起（`raise`）；墨面已是最深 | 默认键与滑块 `raise-hover`（手靠近，影子略重、不位移）；墨键内沿加 1px `ink-mute`；按下＝`raise-pressed` + 按压变形 |

第三行是前两条规则的盲区：墨面已经到顶，不能再深，只能在内沿加一圈浅一档的线。

### 什么时候才有按钮

**界面里的改动默认当场生效。** 勾选、开关、改名、删片、筛选——点了就是结果，不需要第二步去确认它。这条原则曾散在四处注释里（「返回即保存」「改一个生效一个」「切换开关即保存」「不给拉取模型单独按钮」），从没被正面写出来，于是新写的浮层又长出一对「保存 / 关闭」。

只有三种情况配得上一个按钮：

1. **要离开当前语境去做一件外部的事**：`重启生效`、`启动 Codex`、`+ 来源`（启用不在这里——它是当场生效的布尔状态，走开关）
2. **多个输入必须一次提交、中途状态没有意义**：网关地址 + 密钥 → `保存`（且保存即拉取）
3. **真会丢东西、需要确认一道**：删原件、MCP 的批量或跨域写入、重启 Codex——全部见「产品裁决 › 哪些要确认」

**「关闭」「取消」「确定」不是动作。** 浮层点外面或 Esc 关；推入页 `←` 或 Esc 回；离开即提交。唯一例外是确认弹窗里的 `取消`——那是在回答一个问题，不是在关一个面，所以它是一颗默认键（D14）。

一句判据：**操作本身已经说明了结果，就不要再放一个按钮教用户怎么完成它。**

### 删掉与移除：从列表里拿掉一样东西只有两种长相（⑤ ⑬ ⑭）

（产品负责人：移除和删除不统一）**删掉**＝东西真的没了（删网关连同钥匙串密钥）→ 垃圾桶图标按钮；**移除**＝只从这里拿掉、磁盘上的原件不动（侧栏移除项目、来源行移除来源）→ × 图标按钮，提示框写明「不动…」。两种都在行尾（或来源行最右）。按挽回成本分级（⑬）：**删网关**与**移除来源**先确认（密钥找不回；撤掉的软链加回来也不是原样），确认的主动作写动词（`删掉` / `移除`）；**移除侧栏项目不确认**，浮起纸窗给 `撤销`（D11：只是离开视线、难找回）。行尾不用写字的 `移除` / `删除` 键。图标选错就是说错后果（⑭）：来源用垃圾桶会被读成删原件。

### 页面还是弹层

**弹层只有一种用途：确认一个决定。** 设置是侧栏目的地；添加来源是一个有起止的任务，在机面里推入一页（侧栏不动）；网关是 Codex 页的一节。**属于某一行的小配置就地展开在那一行下面**（抽屉 `Drawer`：MCP 差异、skill 详情、网关挑模型与编辑表单）；**有起止的多步任务在机面里推入一页**（添加来源、来源管理，`PushedPage`）。不做从窗边滑出的侧滑面板——它也是弹层（和行下拉出的抽屉 `Drawer` 不是一回事）；也不做盖满整窗、藏掉侧栏的二级页（D1）。菜单这类锚在控件上的小浮层不算弹层：它不挡住页面、点外面就关。弹层把用户困在一个小框里，挤出来的信息密度低。

**主动作用墨键，`取消` 是默认键**（D14，macOS 惯例）——主次靠墨与纸分开（第一版两者只差一档描边，主次不分；后来 `取消` 降成文字链，又不像一个回答）。**确认只给真正不可逆的事**（⑬ 能撤销就不弹确认）。确认框的长相与写法见 `DESIGN-components.md`「确认框 Confirm」；Sophia 里哪些事要确认见「产品裁决 › 哪些要确认」。

### 加速器：快捷键、菜单栏、右键菜单（⑥ ⑩）

**macOS 用户在菜单栏里找命令、认快捷键。** 快捷键只写在提示框里等于藏起来。应用菜单与右键菜单都是原生菜单（Tauri `Menu` / `Menu::popup`，不画网页浮层），系统标准项用预置项，名字随系统本地化。

**菜单栏是发现快捷键的地方**（D15，⑥）：凡有快捷键的命令都在应用菜单里有一项、菜单项右侧写着它的键；提示框只在键盘焦点唤起时写 `· 空格` 这类格子上的键，不给新手增加负担。右键菜单是同一组命令的另一个入口。

- **每一项都是界面上已有入口的另一条路**，行为完全相同、同样的确认与反馈，不新增能力（⑩ 加速器只做捷径）。
- **做不了的项**：菜单栏里**灰着、不隐藏**（菜单栏的项靠固定位置找，⑥⑦）；右键菜单里**不出**（只列此刻能做的事，macOS 惯例）。
- **名字与界面上同一个命令同名**（⑤）；要再操作一步的项带 `…`，点了走界面上同一个确认。
- 右键不改变勾选；菜单开着时被右键的那一行出 `surface` 行带（与悬停同），菜单关掉即消失。本身就是开关、没有第二个动作的东西（格子）不挂右键菜单。
- 不做空菜单：没有帮助内容就不做 `帮助` 菜单（①）。

Sophia 的快捷键、菜单项与右键菜单项见「产品裁决 › 快捷键、应用菜单与右键菜单」。

### 光标与文字选取（D23，⑥ ⑯）

- **光标一律是箭头，全应用没有手形**：键（含带 `↗` 离开 Sophia 的）、浅键、图标键、开关、勾选框、来源筛选项、侧栏项、表格的行与格、列头、选择行的点、抽屉拉手、托盘面板里的项。（2026-09-25 起外链并入浅键，手形随下划线一起删除：它们是网页超链接的语言，⑥。）能点由悬停回应（光晕、描边升档、`surface` 带、抬起的影子变重）与抬起说（⑧），不靠换光标。禁用控件也是箭头，不用 `not-allowed`。
- **界面文字不可拖选**：根上 `user-select: none`；只对用户可能要拷走的值放开——**路径、id（模型 id、服务名）、命令**（含来源管理页的短路径、展开区的原件路径、MCP 差异区的值）。输入框照常。放开的文字用文本光标。
- lint：全应用不许出现 `cursor: pointer`。

## 产品裁决

下面几节是 Sophia 自己的决定，**不是设计系统的一部分**。做别的产品时照搬这里的结论没有意义，该照搬的是上面的视觉语言、组件使用指南与 Patterns。

### 壳：侧栏 + 一块机面

窗口默认 1100 × 720，最小 1100 × 560（`tauri.conf.json`）。**没有顶栏**：一条全高侧栏做全部导航，右边一块机面放当前这一页（D1；⑤ 三种导航形态并成一种，⑥ macOS 全高侧栏惯例，⑨ 进任何一页侧栏都在）。

```
┌ 侧栏 208（机壳上，无线）──┬ 机面（face、1px hairline、12 圆角；上右下离窗沿 10，左贴侧栏）─┐
│ ● ● ●         ← 28 拖动区 │  页面头（高 34）：这一页自己的主控件 ｜ 这一页的动作          │
│ SOPHIA        ← 字标带 44 │                                                           │
│ AGENT                     │  内容（宽 776，左沿＝机面内左沿）                            │
│  ⎔ Codex             •    │                                                           │
│ 项目         最近活跃 ▾   │                                                           │
│  全局                     │                                                           │
│  CardBox             ×    │                                                           │
│  …                        │                                                           │
│  [+ 项目]                 │                                                           │
│                           │                                                           │
│ ⚙ 设置                    │                                                           │
└───────────────────────────┴───────────────────────────────────────────────────────────┘
```

- **窗体是机壳**：`body` 背景 `shell`。侧栏直接落在机壳上，**不画任何分隔线**（侧栏右、侧栏底都没有线；分区由机面的边给出）。
- **内容是一块机面**：`face` 底、1px `hairline` 边、12 圆角、无投影；上、右、下离窗沿 10，左沿紧贴侧栏。机面内边距 16 24 0；1100 宽时机面宽 882、内宽 834。滚动边缘的渐隐与吸顶行的底色都用 `face`。
- **所有页面都在这块机面里**：位置页、agent 页、设置、添加来源都只替换机面的内容，**侧栏始终在，侧栏的选中项就是「你在哪」**（⑨）。不再有盖满整窗、不渲染侧栏的二级页（D1、D6）。
- **页面头**（`PageHead`，规格见 `DESIGN-components.md`）：左端是这一页的主控件或页面名（位置页＝`skills ｜ mcp` 滑槽，页签以 `SKILLS` `MCP` 显示；agent 页＝图标 + 名字；设置＝`设置`；推入页＝`←` + 页面名），右端是这一页的动作。
- **窗口标题栏不显示产品名**（macOS：`titleBarStyle: Overlay` + `hiddenTitle`）：侧栏顶的字标已经说了是谁。
- **红绿灯**内缩到侧栏的内边距上（全高侧栏惯例，不贴窗角）：侧栏最上面 28 **留空**，红绿灯直径 12、圆心 y 15，左沿对齐侧栏文字左沿 20（20 / 40 / 60；`trafficLightPosition` 设定）。拖窗区见下「拖窗区」。
- **应用级故障**（灰面板 `NoticePanel` 的应用级）在机面顶上、页面头之上，满内容宽。右下提示的位置见「Patterns › 反馈」。

**侧栏**（208 宽，自上而下，D1）：

| 段 | 规格 |
|---|---|
| 红绿灯行 | 高 28，留空、可拖窗；红绿灯左沿 20 |
| 字标带 | 高 44；字标框高 26、垂直居中（窗口 y 37–63），框左沿 13：主体 `S` 左沿落在 20（与红绿灯、侧栏文字同一条左沿），重影向左下错 (5.1, 1.9)，左沿落在 15。见下「字标在侧栏顶」 |
| `AGENT` | 区块小标：`label` Condensed 12 / 600 `ink-mute`，拉丁结构词经 `Cap` 大写 + 0.96px；行高 26、左右 20、上距 14。下面**每个有可配置能力的 agent 一项**：15px agent 图标 + 名字（原样大小写 `Codex`）+ 右端 6px 指示点。今天只有 `Codex` |
| `项目` | 同样的区块小标（上距 14），右端排序下拉 `最近活跃 ˅`；第一项固定 `全局`，下面是项目，列表末尾 `+ 项目` |
| `设置` | 贴侧栏底（底距 10）的一项：16px 齿轮 + `设置`；`⌘,` 与应用菜单「设置…」直达 |

- **项**：高 34，左右外距 10、内距 10（文字左沿 20，与区块小标对齐），图标与字间距 8；15 `ink-mute`；**选中** `ink` 600、一小块机面（`face` 底 + 1px `hairline` 环、`control` 7 圆角）；悬停 `surface`。三段是**同一种项、同一个选中**：全侧栏一次只有一项选中，它就是机面里正在显示的那一页（⑤⑨）。
- **agent 段只列有能力节的 agent**（能力节＝可配的，如第三方模型；或可看的，如以后的用量）：没有能力节的 agent 不列，也不灰着列——灰项回答不了任何问题（①）。一个 agent 一页，页内按能力分节（见「agent 页」）；哪天某个 agent 有了能力节，它才出现在这里。名单与节由一张 agent 注册表生成，侧栏、agent 页、托盘同源（见「扩展预留：用量与会话」）。
- **agent 名后的 6px 指示点＝这个 agent 上有能力开着、在生效**（`accent`；与开关的橙刻条同一个意思，⑤）。什么都没开时不画点——不画灰点：侧栏不是开关，灰点只会被读成「坏了」。离开 Codex 页也看得见第三方模型开没开（⑪）。
- **`项目` 段**：写 `项目`，不写「位置」（产品负责人：这里都是项目）。第一项固定是 `全局`，不参与排序；下面是项目。项只写项目名（`CardBox`），不加 `项目 ·` 前缀，小标已经说了。
  - **同一份列表、同一个选中**：项目列表是 skill 与 MCP 两边发现的项目加上手动添加的项目的并集，切 `skills ｜ mcp` 时侧栏不变、选中不变。某个项目在当前页签下什么都没有时，机面出空态（「这个项目里还没有 MCP」），不把它从侧栏藏掉——侧栏随页签变，用户会以为项目丢了（⑤）。
  - **排序**：小标题行右端一个文字下拉 `最近活跃 ˅`（12 `ink-mute`，箭头同拉手那一枚；点开是两项的菜单 `Menu`：`最近活跃` / `最近创建`，单选、当前项前打 ✓）。默认最近活跃；选择记在本机，下次打开照旧。
    - **最近活跃**＝最近一次有 agent 在这个项目里干活的时间：Claude Code 会话记录（`~/.claude/projects/<编码后的项目路径>/` 下最新文件的修改时间）与项目里各 agent 目录（`.claude` `.codex` `.agents` 等）最新修改时间取较晚的；都没有时用项目文件夹本身的修改时间。
    - **最近创建**＝项目文件夹的创建时间；取不到时用它加入 Sophia 的时间。
    - 时间不写在侧栏上（侧栏只放名字），悬停项目名的提示框给完整路径和「活跃于 3 天前」。
  - **`+ 项目` 是项目列表的最后一项，长了就吸底**（① 加在它要加进的地方；2026-09-25 产品负责人：「可以学习 Dia 的设计，项目少的时候是跟在项目后，项目多的时候就在底部」）。**长相是侧栏的一行，不是键**：14px `+` 图标 + `项目`，字 `ink-mute`，行高与项目行相同，悬停同项目行的 `surface` 带——侧栏里能点的都是行（项目、`全局`、agent、`设置`），它是这一列里的最后一行，同形（⑤）；不带省略号；点它出系统选文件夹。**项目少**：紧跟最后一个项目，和列表之间没有分隔。**项目多到侧栏中段要滚时**（中段＝ `AGENT` 段与项目列表一起滚，只有字标与 `设置` 固定）：它停在中段可见区的底边（`设置` 上方，`position: sticky; bottom: 0`），底色 `shell`，**上沿出一条 1px `row-line` 横线**（左右与侧栏项同宽）——横线只在吸底时出现，说「上面的列表在滚，这一行不动」；不再用渐隐（Dia 同样只用一条线，线比渐隐干净，②⑧）。应用菜单「文件 › 添加项目…」是另一条路。
  - **移除手动加的项目**：悬停该项时行尾出 `×` 图标键（提示框「从侧栏移除 · 不动磁盘上的文件」）；自动发现的项目没有 `×`。**不确认**；移除后在 `×` 原来的位置下方浮起纸窗 `✓ 已移除 WeiboAP · 撤销`（6 秒，悬停停表），`撤销` 把它放回原来的位置（D11，⑬：只从侧栏拿掉、不动磁盘，可逆；但它离开了视线，再找回来要重新选文件夹，属于「可逆但难找回」——给撤销，不给确认）。移除的正是当前选中的项目时，选中落到 `全局`。
- **默认落点**（D2，④）：第一次启动落在 `全局 · skills`——扫描一完就是用户已经装着的 skill，一打开就有价值；新用户还没有网关，落在 Codex 页第一眼只有一个按不动的开关。之后**记住上次停在哪**（侧栏选中项 + 位置页的 `skills ｜ mcp`），下次打开照旧；记着的项目不在了就落 `全局`。
- **机面的转场**：侧栏之间切换即时替换，不做动画（侧栏切换是跳到另一处，不是空间里移动）；只有推入页（添加来源、来源管理）从右推入、返回滑回（200ms 机械缓动，reduced-motion 即时，⑨），而且只在机面里推，侧栏不动。

**字标在侧栏顶**（产品负责人：黑猫与玻璃的动效必须保留，作为彩蛋）。字标从顶栏搬到侧栏的字标带，**动效原样保留**（行为见「标志 › 字标动效」），它依赖的几何如下（碎片落在字标带下沿，见「标志 › 字标动效」）：
- **字标框的几何**（资产 `assets/logo/wordmark.svg`，viewBox 3304 × 916，按高 26 等比缩放，1 单位 ≈ 0.0284px）：框 26 × 93.8，窗口 x 13.1–106.9、y 37–63（在 44 高的字标带里上下各留 9）。框内：主体 `S` 左沿 x 6.9、顶 y 2.8，字形高 20.3；重影 `S` 左沿 x 1.8、底 y 25.1，相对主体向左 5.1、向下 1.9（字高的 0.25 / 0.093，资产里的原比例）；`A` 右沿 x 92.3。换到窗口：主体左沿 20、重影左沿 15、`A` 右沿 105.4。**对齐取主体不取重影**：重影是影子，像悬挂标点一样挂在文字左沿外（⑯ 对齐按读者看到的字，不按外框）。
- **命中区**＝字标框（含左下重影）：窗口 x 15–109（重影左沿到 `A` 右沿 + 4）、y 37–63。悬停计时与敲击只在这块里算；它上面的红绿灯行仍是拖窗区，字标带里字标之外的地方不接收点击。

**拖窗区**（D17，⑥：D1 删掉顶栏后，原来整条顶栏承担的拖窗要重新给出，否则整窗几乎没有能拖的地方）：

### 术语

**把一样东西放进一个位置，全应用一个动词：「添加」。** `添加 skill` `添加 MCP` `添加项目` `添加网关`。曾经 skill 叫「导入」、MCP 叫「引入」，用户先要求统一，再问"要不要干脆不叫导入"——「导入」暗示从外面拷一份进来，实际做的是建链接 / 写一条配置，用户看到的结果就是"这里多了一个"，那就说「添加」。没选「新增」：它和自动规则那句里的"新出现"撞词（`此来源新出现的 skill 自动新增`）。

**页签是名词，不是动作**：`skills` `mcp`（界面上经 `Cap` 以 Condensed 大写 `SKILLS` `MCP` 显示）。侧栏原来的「模型」段改名 `agent`（D1；界面上是区块小标 `AGENT`）：一个 agent 一页、页内按能力分节，「模型」只是其中一种能力的名字（`第三方模型`）。第一版 MCP 页签叫「导入 MCP」是为了和二级页「导入 skill」错开，现在动作只在按钮上出现，页签就不用扛它。

**界面文案里不说「矩阵」，说「列表」。** 「矩阵」是我们对那张表的叫法（行 × 列），用户看到的是一个 skill 列表，每行后面几个开关。设置页那句是 `哪些 agent 出现在列表里`。

界面文案里**不出现「harness」**，一律 agent。代码标识符不动（`disabled_harnesses` 是已落盘的键、`matrix` 是组件名）。

### 来源的名字

来源的标签是**用户认得的名字**，不是路径：

| 来源 | 标签 |
|---|---|
| 通用仓库 | `通用仓库` |
| agent 的全局目录 | agent 名 |
| 项目 | 项目目录名 |
| 应用包内的目录（`/Applications/ego lite.app/…/ego-skills`） | **应用名** `ego lite`——从 `.app` 那一级取，去掉后缀 |
| 应用数据目录（`~/Library/Application Support/WeiboAP/…`） | **应用名** `WeiboAP`——`Application Support` 下一级 |
| 其余外部目录 | 从末尾往上找**第一个不是泛称的分量**：`~/.local/share/ego/skills` 叫 `ego` 不叫 `skills`。末尾一级几乎总是 `skills` 这类泛称，光取它三个来源会撞成一个名字 |

路径放 `title`。绝对路径**不出现在任何可见文案里**，除非用户正要据此做判断（只留这份的确认框写出两份路径）。

**矩阵「来源」列不给外部来源挂「外部」标签。** 用户要知道的是它叫什么、在哪，`ego lite` 这个名字已经说完了；「外部」是我们的分类词，对用户没有信息量。添加页的来源栏保留分类，那里是在挑来源、分类有用。

### 问题在哪看得见、在哪处理

**没有收件箱、待处理页、「忽略」，也没有新问题提示**（产品负责人：问题都在行上显示了，收件箱没有存在的必要；2026-09-25：「这个提示的功能可以去掉」）。问题只在一处出现：**就地常显**——在它发生的那一行、那一格上一直看得见，并且就在那里处理，见下表。原来扫描后右下弹一条 `! 发现 3 处需要你处理 · 查看`，是同一批问题的第二处说法（①），而且在用户没做任何事时主动打断（⑩）。代价写明：不在眼前的页签、没选中的位置里新出现的问题，要走到那里才看得到——问题都不紧急（同名两份、链接失效、放不进去），不值得为它打断。

页签与侧栏项上不加计数。同名原件两份各自在列表里成行：行视角的事（删哪个）在行上问；格视角的事（这一格为什么点不动）由格子提示框说。

| 问题 | 在哪看得见 | 在哪处理 |
|---|---|---|
| 同名原件 | 两行名字后 `×2`（纯文字记号） | 点 `×2`、名字或拉手拉开这一行的抽屉，抽屉末尾 `只留这份`，先确认（写出两份路径）|
| 链接失效，原件还在 | 该格虚线环 | 点格＝重新链接 |
| 链接失效，原件已不在（孤链） | **矩阵里照样成一行**：名字 + 来源写 `不在了`（`ink-mute`），该 agent 格虚线环 | 点格＝清除这条链接（提示框「原件不在了，点一下清除这条链接」；不确认——链接本来就指向空处） |
| 整个文件夹是链接 | 该列各格的整列记号 + 列头提示框 | 点该列任一格 → 确认「拆开 Codex 的 skills 文件夹？」+「把链接换成真文件夹，里面的内容原样复制过来」+ 主动作 `拆开` |
| 无法写入 | 该格斜杠环 ⊘ | 点格＝再试一次 |
| MCP 两份不一样 | 名字后 `2 份不一样`（纯文字记号） | 点它（或名字、拉手）拉开这一行的抽屉，差异是抽屉里的一段（见下条）|
| MCP 位置无效 | 该格斜杠环 + 提示框原因 | 点格＝在访达中显示那个配置文件 |
| Codex 正由别的工具管理 | Codex 页「第三方模型」节里的行内待办条「Codex 正由 agents-manager 管理」 | 条上 `接管` |
| Codex 配置被外部改过 | Codex 页「第三方模型」节里的行内待办条「Sophia 写进去的设置被改掉了」 | 条上 `重新写入` |
| 某家网关无法连接 | Codex 页那一家网关行的第二行 `无法连接 · 原因` | 行尾 `再试一次` |

Codex 页的三条行内待办条（接管、重新写入、路由没在跑）怎么写见「agent 页：Codex › 第三方模型」。

- **MCP 同名多份时就地挑一份写进去**（取代旧添加页里的挑选）：某一格是空的，而已订阅的来源里有几份**不一样**的同名定义时，格子照常是 ○，点它不直接写，出一个锚在格子上的菜单（`Menu`）：标题 `notion 有 2 份不一样的，写进哪一份？`，每项一行＝来源位置名 + 与其他份差在哪（`url 不同`，同「只标差异」的字段名写法），点一项就写进这一格（例行一行 `✓ 写进 [图标] · 撤销`）。格子提示框写「有 2 份不一样的同名 notion · 点一下挑一份」。不替用户挑（⑮），也不另开页（⑨）。
- **MCP「两份不一样」只标差异**（不覆盖、不合并）：位置页 MCP 表该服务名后的 `2 份不一样`（纯文字记号，2026-09-25 评审）可点 → 拉开这一行的抽屉，差异是抽屉里接在传输 / 命令 / 原件之后的一段（不开新页、不弹窗、不另开一格，⑨），只列**不同的字段**：字段名 ｜ 位置 A 的值 ｜ 位置 B 的值，三列对齐，相同字段不显示；值用 mono 12，值内不同的那一段加粗标出（不用反色，反色已是「刚变化」）。**headers、env 里的令牌与密钥不显示原值**，只显示「不同 · 末 4 位」，悬停提示「出于安全不显示原值」（⑭）；认证头运行时才生成的，写一句「认证头要到运行时才生成，无法逐字比对」，不假装比过。`在访达中显示 ↗` 降为展开区末尾的次要浅键。主视图该服务行的 `2 份不一样` 提示框里给出差异字段名（`url 不同`）。

### 来源：订阅、移除、添加来源

#### 移除一个来源

- 来源管理页那一行最右的 `×` → 确认框，写明影响：`从 CardBox 移除 WeiboAP？` + 会撤掉的软链「这 5 个 skill 在 Claude Code、Codex 下的软链会撤掉：excalidraw、notion…」（多于 5 个写「等 N 个」）；一条都没链时写「它的 skill 会从列表里拿掉，没有软链要撤」；主动作 `移除`（墨键）、`取消`（默认键）。确认后这一行收起，`✓ 已移除 WeiboAP` 浮在 × 原来的位置下；回到位置页时来源筛选里不再有它（若正勾着它，勾选随之去掉）（不给撤销：撤掉的软链一条条链回去不等于原样，⑭ 撤不了就不假装）。
- **原件在这个项目里的来源不能移除**：× 禁用，按下即出「它的原件就在 CardBox 里，删掉原件才会消失」。**项目自己的 skill 也是一个来源**（名字 `CardBox · 通用仓库`）：它不是订阅来的，但「以后新出现的自动加到」对它同样有用，所以它在来源筛选里有一项、在来源管理页有一行，只是 × 禁用。

- 没有绝对路径常驻：来源管理页写 `~` 开头的短路径，完整路径进提示框；位置名写法 `Claude Code · User`。

**「不支持」按目标 agent 判断，不按服务一刀切**（产品负责人：mcp 为什么搬不过去，转成 claude 写法也不行吗；界面词 D24 起由 `搬不过去` 改为 `不支持`）。用命令生成请求头的服务（Codex `http_headers_helper`、Claude Code `headersHelper`——两家官方文档语义一致：运行一条命令，命令往标准输出写一个「请求头名 → 字符串」的 JSON 对象）在这两家之间**照常互搬**，写入时换成目标那一家的字段名；只有目标 agent 不支持这种写法时，那一格才受阻（⊘）——不能静默丢掉这个字段（丢了就是一份没有凭据的坏配置，⑭）。比较是否一样：命令字符串相同即相同，静态请求头照常逐项比。表格里那一格点不了、原因写「Cursor 不支持用命令生成请求头」；添加来源页的 `不支持` 标签只在**显示的 agent 里一家都接不住**时才出（提示框写原因：`显示的 agent 都不支持用命令生成请求头`）。

**来源名全应用一个写法**（产品负责人：两个页面的来源名字不一致）：筛选片、`来源` 列、添加来源页的行名、移除确认里的名字，都出自同一个起名函数——`通用仓库`、`WeiboAP`、项目自己的仓库写 `CardBox · 通用仓库`；同名来源用区分片段 `WeiboAP · 1776…`。**区分片段先去掉同名几个共有的开头再截短**（`agent_1776847465710_…` 与 `agent_1787890675056_…` 共有 `agent_17`，片段取 `1776…` / `1787…`），名字本身不被挤成 `W…`。项目自己的仓库不再另叫「CardBox 自己的 skill」。

### 删除原件：点原件格，确认后才删（2026-09-25）

产品负责人：「我想增加删除 skill 本体和 mcp 的功能，只是需要二次确认……就是点击这种按钮的时候提示」（指原件格 ⦿）。取代「原件格不能点」：原来用户只能自己去访达删，删完还剩一排断链要回来清（④ 复杂度由设计者承担）；二次确认 + 能找回（skill 进废纸篓、MCP 可撤销）同样守住 ⑫。

**原件格可点**：悬停出光晕（与开关格同一种回应），提示框是动词——skill `删除原件…`，MCP `从 Codex 删除…`（`…` 表示还要确认一步，macOS 惯例，⑥）。点下去（或空格）**不直接删**，先弹确认框（窗口正中）；与「只留这份」同一个组件：标题一问 + 正文一句后果 + `取消` / `删除`，不写路径。焦点默认在 `取消`，Esc 收起。skill 的批量（选择行）不删原件，照旧跳过；MCP 的批量能删，先确认一次（见「MCP 格子只有两种」）。

**撤销怎么做到**：macOS 不允许程序把东西从废纸篓放回原处，所以删除时原件先挪进 Sophia 自己的暂存目录（应用数据目录下，同一磁盘上是一次改名），并记下每条链接的处理（清掉的写着什么、改指的原来指向哪）。撤销机会到下一次删除原件或重新打开 Sophia 为止；过了，暂存的原件再移进废纸篓，访达里照样找得回。原件和暂存目录不在同一磁盘时（外接盘）挪不过去，退回直接进废纸篓、不给 `撤销`，提示条照实写 `✓ 已删除 defuddle · 在废纸篓里`。只留这份删掉的那一份同样给 `撤销`。

core：别处没有同名原件可改指时，指向它的链接**一起清掉**（删前逐条重校验仍是软链、仍指进被删的原件），不再原样留成断链——删了原件还剩一排断链，等于把收尾推给用户。别处有同名原件时照旧改指（只留这份走的就是这一支）。每条链接的结果逐条上报，不偷偷跳过。

### 格子与批量的撤销、一次只一条

- **单格操作出例行一行，不带撤销**：点格子加上 / 移除（skill 的 `加到` / `从 … 移除`）成功后，格子照旧闪一下（120ms 反色），同时出一行 `✓ 加到 [Codex]`。**不给 `撤销`**（产品负责人：再点一下就恢复了）——格子本身就是开关，撤销入口就在光标底下，再放一个 `撤销` 是重复（⑤）。`⌘Z` 照旧可用。造句与批量共用 `toastFor`，组件同一个 `Toast`。

### 哪些要确认

确认只给真正不可逆的事（⑬ 能撤销就不弹确认）；确认框的长相与写法见 `DESIGN-components.md`「确认框 Confirm」，都在窗口正中。

- **删原件**（skill 原件格 ⦿）：见「删除原件」。
- **删 MCP 的最后一份**：单格删的是这个位置里最后一份，或批量里有一行会删到最后一份时（见「MCP 格子只有两种」）。
- **只留这份**（删掉另一份原件）：删的是用户的原件文件夹、低频；确认框写清哪份进废纸篓、几条链接改指（写出两份路径）。确认后直接执行，例行一行带 `撤销`。

- **移除来源**：撤掉它建的软链（见「来源 › 移除一个来源」）。
- **拆开**：整个文件夹是链接时，把链接换成真文件夹。
- MCP 的**批量或跨域**写入：跨域会把请求头和令牌一并复制过去。
- **重启 Codex**：会结束正在运行的进程、打断进行中的对话（见「agent 页 › 改动待生效」）。

#### 模型列表的写法（网关行里的勾选列表，①⑥⑧）

真实网关多半不给友好名，`azure/gpt-4.1` 与 `default-azure-gpt-4.1` 并排是同一串字的重复，`default-azure-` 还是网关内部路由命名。

- **只有友好名存在且与 id 明显不同时**（`DeepSeek V3.2` 对 `deepseek-chat`——从名字推不出 id），行尾才显示 id（`mono` `ink-faint`）；`Opus 4.6` 对 `anthropic/claude-opus-4-6`、`Kimi K2` 对 `moonshotai/kimi-k2-0905` 属于「不同不明显」，不显示。判断写死在一个函数里：名称与 id 都去掉常见前缀（`default-`、服务商名）和分隔符（`/ - _ .`）、转小写后，若名称是 id 的子串 → 视为「不同不明显」，不显示。

**图标只做一件事**（产品负责人：左键和双指点出来是两个不同的菜单，怎么设计合理）：左键、右键（双指）都弹出同一个面板，再点一次收起。不挂原生的「打开 Sophia / 退出」右键菜单——面板里就有这两项；面板万一出不来，Dock 图标与 ⌘Q 仍能打开和退出。

```

第三方模型                         [重启生效]  [开关]
─────────────────────────────────────────────── row-line
打开 Sophia
退出
```

- **一条左沿**（2026-09-25 产品负责人两次说托盘「很乱」「可以再简化，不展示模型了」）：块头图标、能力行的名字、菜单项的字都从面板内 16 起（菜单项是外距 6 + 内距 10），不再把能力行缩进到名字下面——320 宽的面板里三条左沿就是乱。

- **键位**（条件）：`重启生效` / `启动 Codex` / `卸下后台服务` 占同一位——**能力行里、开关左边 12**（默认键紧凑 24），与 Codex 页一样紧挨开关（⑤），不另起一行。规则同 Codex 页。确认用确认框的窄面板形态，在面板里当场展开（`DESIGN-components.md`「确认框 Confirm」）：`重启 Codex？` + `有 2 个对话正在进行，会中断` + `取消` / 主动作。拨开关同 Codex 页：拨了就写、不确认、乐观翻转，写成了键位按状态出 `重启生效` / `启动 Codex`（键位在能力行里、开关左边 12）；没写成滑回，键位原位灰面板 + `再试一次`。

### 扩展预留：用量与会话（未实现，只定结构）

产品负责人 2026-09-24 计划的两项功能：**菜单栏展示用量**（参照 [CodexBar](https://github.com/steipete/CodexBar)、[ClaudeBar](https://github.com/tddworks/ClaudeBar)：各 agent 本时段 / 本周额度用了多少、何时重置），**会话管理与跨 agent 恢复**（参照 [cross_agent_session_resumer](https://github.com/Dicklesworthstone/cross_agent_session_resumer)、[session-migrate](https://github.com/xhluca/session-migrate)：Claude Code 里开的会话，换到 Codex 里接着做）。本节只定**落点与分层**，让本轮外壳、agent 页、托盘、位置页的结构直接容得下，届时只加内容、不改骨架。数据源与细节（字段、刷新频率、转换的保真度）实现那一轮再核实、再定。

**按归属定落点**（⑨ 东西放在它属于的地方；⑤ 同一类东西同一个家）：

| | 属于谁 | 落在哪 | 骨架里现在就要有的 |
|---|---|---|---|
| 用量 | agent（额度按账号 / agent 计） | agent 页的 `用量` 节（排在 `第三方模型` 上面：只读、最常看）；托盘该 agent 块里的 `用量` 行；菜单栏图标右侧可选的一个数 | agent 注册表：每个 agent 带一串「能力节」，侧栏、agent 页、托盘三处都从它生成；托盘按 agent 成块、能力成行 |
| 会话 | 项目（每个会话有工作目录） | 位置页第三个页签 `sessions`（`skills ｜ mcp ｜ sessions`，⌘3） | 页签由一张 domain 列表生成，⌘1…⌘n 与应用菜单「显示」里的项同源；落点记忆存 domain id |

- **页签名用 `sessions`**：与 `skills` `mcp` 同为拉丁结构词，界面上经 `Cap` 显示为 `SESSIONS`；产品负责人自己就这么叫它（⑥ 用用户的词）。
- **agent 段的入选条件**从「有可配能力」放宽为「有能力节（可配或可看）」：有了用量，`Claude Code` 会作为第二项出现在侧栏，它的页届时只有 `用量` 一节。
- **用量节**（草案）：每个额度窗口一行——名字（`本时段` / `本周`）+ 一条横向用量条（凹槽 `track`、填充 `ink`）+ `已用 42% · 2 小时 13 分后重置`。**不用橙**（用量不是「在生效」）、**不涂红**（快用完靠文字 `剩 8%` 600 承担分量）。数据从哪来、多久前读的写在节尾一行 12 `ink-faint`（`读自 Codex 本机记录 · 3 分钟前`，⑭ 诚实）。
- **菜单栏的数**（草案）：图标右侧最多一个数＝所有 agent 里最紧的那个窗口的已用百分比（`42%`，系统菜单栏字体、单色）；一个图标、不按 agent 各挂一个（克制）；设置里可关。
- **sessions 页签沿用表格的词汇**（⑤，不另造一套）：一行一个会话（标题或第一句、时间），列是 agent。会话在哪个 agent 里开的，那一格是 **⦿ 原件**；已经转成另一个 agent 能接着用的副本＝**●**；没有＝**○**；转不过去＝**⊘**（悬停给原因）。点 ○ 就是 `加到 Codex`（写一份 Codex 能原生恢复的会话），选择行、批量、撤销、提示条全部照 skills 页。行尾动作 `在 Codex 里继续` 打开终端、在项目目录里跑该 agent 的恢复命令。`全局` 下列不属于任何侧栏项目的会话（与 `全局` 的意思一致：不在任何项目里）。

**分层（避免重复实现）**：

- **会话**：`crates/core` 新增只读扫描各 agent 会话存档、归一成一份中立表示；转换写入一律走 `atomicfile`，与 skill / MCP 一样先出计划、再执行。各 agent 的会话存档位置、恢复命令模板写进 `data/harnesses.json`，不在代码里写死。侧栏「最近活跃」现在自己读 Claude Code 会话目录——届时改为读这一个模块，只留一处。
- **用量**：只读本机文件的部分可以进 core；需要联网或读钥匙串的（部分 agent 的额度只能问服务端）放进异步 crate（与 `crates/gateway` 同一层，core 保持无异步无网络），钥匙串复用 gateway 的 `keychain`。
- **前端**：agent 注册表（侧栏 agent 段、agent 页的节、托盘的块与行）与 domain 列表（位置页页签、⌘ 数字键、菜单「显示」）是仅有的两个扩展点；加功能＝往表里加一项、写一个节 / 页签组件。节上带两种画法：agent 页的 `Component`、托盘的 `trayRow`（可选，不给就不进托盘）——托盘面板按表画行，加「用量」不改面板。

| 托盘里的失败 | 灰面板 | 托盘键位原位 |

## Do's and Don'ts

### Do

- 一次操作只汇总成一句提示条
- 禁用的控件同时给原因（`disabledReason`：悬停与按下都出提示框；原生 `title` 只作读屏兜底）
- 需要用户拿主意的事就地显示、就地处理，一直看得见
- 数字带单位
- 「已选中」：表格行、添加页、设置页用勾选框；来源筛选用墨色胶囊（筛选里的选中是「正在看这些」，不是「要对这些做事」）；「开着 / 在生效」只用开关的橙刻条，看不到开关的地方用指示点
- 图标按钮带提示框文字
- 能按的键抬起（`raise` / `raise-ink`），按下贴近机面、松开弹簧回位；按不下的平贴：实线 `hairline`、无投影、按下不动
- 会移动的滑块（页签、开关）用 `--spring-slide` 弹簧停靠；颜色与透明度用 120ms `--ease-mech`
- 有快捷键的命令放进应用菜单，菜单项右侧写着键
- 自写的纯拉丁结构词（`SKILLS` `MCP` `AGENT` `LOCAL` `PROJECT`）与表格列头里的 agent 名（`CLAUDE CODE`）经 `Cap` 走 Condensed 大写 + 正字距；侧栏与托盘的标志用 `assets/logo/` 原资产

### Don't

- 不涂红。破坏性靠信息承担分量
- 不让橙色出现在开关与它的指示点以外，不让它承载文字
- 不用投影表示「重要」或「是一块面」——投影只说离机面多高：抬起只给键、页签滑块、开关滑块（勾选框手靠近时例外），浮只给浮层；机面、行、片、表格不投影，格点不加凹坑，机面不凸起
- 不拟物：不做拉丝、金属、螺丝、纹理、渐变高光、内发光、发光 LED、3D 倾斜、多层硬影或长投影堆出的厚度、声音、页面级视差；不给颜色、透明度用弹簧；弹簧不许肉眼可见地「弹」（过冲 ≤ 3%）
- 不在 `Cap` 之外写大写或正字距：不给汉字加字距，不把句子里的拉丁词、按钮、页面名、文件系统来的名字大写；agent 名只在表格列头里 Condensed 大写，别处原样（`Claude Code`）
- 不用网页手感：不用手形光标（全应用），不画下划线，不让界面文字能被拖出选区（路径、id、命令除外），不出悬停列带
- 不用点状下划线表示「可悬停」，不用虚线表示「不可用」
- 不在按钮上写宾语（`重启 Codex` → `重启`）
- 不给词表之外的动作发明图标
- 不在列头放灯。看不懂的记号比没有记号更糟
- 不把选择行退化成两个总按钮，「针对某个 agent」这一维不能丢
- 不显示绝对路径，除非用户正要据此做判断
- 不写「操作失败」「请重试」「没有需要建立的链接」
- 不给「拉取模型」「改选模型」单独的按钮——保存即拉取，整块区域可点
- 不给浮层配「保存」「关闭」——点了就生效，点外面就关
- 不让命中区跟着视觉尺寸缩——14px 的勾选框，24px 的目标
- 不说「同步」——自动规则只新增，从不覆盖也不删除
- 不在文案里说「矩阵」「导入」「引入」「harness」
- 不做装饰：装饰性编号「01」「02」、装饰性网格线、对位刻度、满屏十字准星、数字零填充、对话框装饰边
- 不为了「科技感」把正文换等宽，不为了「机械感」把开关换成要想一下的造型
