# Sophia 设计系统

**本文件是实现的唯一依据。** 画布「SymSync 界面重构」（改名前的画布，名字未改）是视觉参照，两者不一致时以本文件为准；改组件先改这里，再改代码，再同步画布。`scripts/lint-ui.mjs` 把本文件的硬性约束变成了可执行断言，接在 `make lint` 里。

历史裁决与每条规则背后的推理在 `docs/specs/2026-09-21-ui-decisions-log.md`，本文件只写结论。

## Overview

**像一件器物，不像一张线框图。** 参照 teenage engineering TP-7：极简、现代、机械感、工艺品。色调仍是黑白、零色彩零阴影零渐变，logo 不动。2026-09-22 产品负责人判定前两版「过于简陋」——提示条是白底 1px 线框盒，全产品只有一种材料（白底上的 1px 线），规则再严也像没上材质的草图。下面「材料与工艺」一节是这一版的总纲，其余各节与它冲突时以它为准。

## 设计原则：尊重用户的注意力与判断

**这是此后一切评审的标尺**（产品负责人，2026-09-22）。用户依次付出注意力 → 理解 → 行动 → 信任，对应四根支柱、13 条原则。下文「材料与工艺」「视觉优先」和各节裁决都是它们的具体化；冲突时以本节为准。

| 支柱 | 原则 | 在 Sophia 里意味着 |
|---|---|---|
| **一 不浪费注意力** | ① 信息在对的时间、对的位置出现：就近出现、就近不遮挡、局部就近全局全局、严重程度决定打断程度；判断标准是「此时此刻对这个用户重不重要」 | 单格操作不出提示条（格子一闪即反馈）；批量提示贴在选择条下；待处理页提示贴在被处理那一行；只在挑模型时有用的说明放进模型下拉 |
| | ② 视觉权重与重要性一致，一个界面一个主角 | 表格是主角；分组头开关、图标键都让位于主动作 |
| | ③ 默认值本身就是设计，复杂度由设计者承担 | 见「默认值」表 |
| **二 降低理解成本** | ④ 统一性：相同形式承载相同含义，不同含义不长得一样 | 黑色体块＝机器在说话；黑色小键＝已按下或已选中——实心黑不再加新义 |
| | ⑤ 符合用户已有心智模型，用用户的语言 | 界面说「原件」不说「本体」、说「同名」不说「撞名」、说「整个文件夹是链接」不说「整个文件夹是链接」（lint 旧词表拦回潮） |
| | ⑥ 外观说明如何操作，文字提供确定性 | 格子悬停预览点下去的结果；文字确定性由「提示框」承载，不用原生 title |
| | ⑦ 保持上下文连续，用户始终知道在哪，认出而非回忆 | 确认框不盖掉正在决定的那一行 |
| **三 行动轻松且安全** | ⑧ 操作成本与频率、风险匹配，为熟练用户提供高效方式 | 见「键盘」 |
| | ⑨ **产品在和用户对话，而不是静态地等待**：用户做了什么，系统回应「收到了、正在处理、成功了或失败了」；用户想做什么（悬停、聚焦、靠近），系统也回应「这里能做什么、做了会怎样」。回应强度与意图的确定程度相称：悬停是试探，回应要轻；按下是决定，回应要明确；完成要确认。最好的回应常常是足够快 | 格子十字带 + 悬停预览、列头 / 组头悬停（轻）；按下 1px 压扁（明确）；刚点亮反色闪 120ms（确认）；细弧指示器 + 一句忙什么（持续）；乐观更新 |
| | ⑩ 预防错误优先于处理错误 | 添加时就地解决同名，不把冲突推进待处理 |
| | ⑪ 允许犯错，能撤销就不弹确认，只有不可逆才打断 | 删原件进废纸篓＝可逆 → 直接删 + 撤销；确认只剩两件 |
| **四 守护信任** | ⑫ 诚实不操纵 | 忽略可在「已忽略」找回；「只建链接，不动源文件」 |
| | ⑬ 用户始终保有控制权 | 自动规则的每次动作可见可撤销；重启给「稍后」 |

### 怎么用这套原则

- **地基**：核心理念「尊重用户的注意力与判断」。四层：理念 → 支柱 → 原则 → 具体准则（本文件其余各节）。
- **原则冲突时，向上裁决**：两条原则矛盾，或体验与商业目标冲突时，回到理念问——哪种做法更尊重用户的注意力与判断？是在帮用户判断，还是在干扰用户判断？
- **新经验出现时，向上归位**：先问它属于哪条原则、服务哪根支柱；找不到归属，要么它不重要，要么体系有缺口、值得补——作为「体系缺口」上报产品负责人。
- **评审与改动说明都标原则编号**（①–⑬）。

已裁决的冲突：

| 冲突 | 裁决 |
|---|---|
| ⑥ 对 ⑤：自创的格内异常记号偏离惯例 | 保留——它帮用户一眼扫完 56×4 个状态；**成立前提**是格子悬停预览 + 提示框兜底（这两条从改进升为前提） |
| ⑨ 对 ①：单格操作要不要提示条 | 不要——格子一闪已在注意力所在处反馈；批量才出 |
| ⑪ 对 ①：删原件要不要确认 | 撤销代替确认 |
| ① 对 ⑨：回应的边界 | 没有意图就没有回应——空闲时界面静止，无呼吸、无循环动画、无吸引注意的晃动，回应只由用户唤起；`prefers-reduced-motion` 下动效退化为即时状态变化，信息不减 |
| ③ 对 ⑬：要不要自动重启 Codex / 做成设置项 | 都不做——重启的是用户正在用的另一个应用，看似空闲也可能有未发草稿与上下文，替用户选中断时机是被产品裹挟（⑬）；做成设置项是回避决策（③）。重启时机归用户，Sophia 把键放在对的地方、如实说出代价 |
| ⑫ 对 ①：「改动待生效」怎么表达 | 不给稍后、不用黑块、不配读数、不做可关闭提示——按钮即状态，Codex 重启后自动消失 |
| ⑤ ④：收件箱装什么 | 先裁「只管当前页签」，后改为「全局 + 落在当前段」——顶栏是应用级位置，同一个图标随页签装不同东西不符合心智模型，从 MCP 页进去却到不了 skill 的事 |
| ⑪：删网关连带删钥匙串密钥、本身不可逆 | 做成延迟提交 + 撤销，而不是弹确认 |
| ① 就近：待重启提示锚在哪 | 触发有两个（开关、改模型），锚在它们共同的对象——agent 名字下 |
| ① 逐行就近 对 ⑤ 固定动作列 | 多行列表的动作成一列（句子列定宽、动作列紧随），不逐行贴句尾 |
| 产品负责人第 1 轮「待处理栏贴底」 对 ① ④ ② | 本轮推翻，删除贴底待处理窗：它的「就地带动作」已搬进表格行，只剩导航；它和顶栏收件箱是同一信息却放在对角两端（④ 同一信息两种形态、① 远离问题本身），又是页面上最重、信息最少的元素（②） |
| ⑥ 视觉优先 对 ⑤ 惯例：组头开关 | 须带文字限定「以后新出现的」——不带会被读成「一键开关整组」，误判代价高时文字必要（⑥）；与添加页「以后新出现的也加」同一措辞（④） |
| ⑥ 视觉优先 对 ⑤ 惯例：同名怎么标 | 自创括线「[」没有足够理由，改用惯例 `×2`；动作「只留这份」按用户在想的事命名 |
| ① 就近 对 ① 不遮挡：格子提示框放哪 | 只保护正在操作的格与行，其余允许暂时遮挡——紧贴光标、移开即消失，比放到 170px 外更尊重注意力 |
| ⑤：「本体」一词 | 已改为用户语言「原件」（产品负责人定）；代码标识符（`own` 等）不动 |
| ① 对 ⑤⑧：同一功能放几个入口 | **信息只说一次（①）；功能可以有多个入口**——入口长在用户自然产生这个念头的地方（⑤⑧），各入口同组件、同状态、同行为（④ 是多入口的前提，不是反对它的理由）。产品负责人：「同样一个功能可以在两个地方有，只要用户不觉得奇怪；只放在一个地方，用户反而奇怪。」据此：自动添加规则在主视图组头可直接开启（添加页入口保留）；选模型在模型下拉与网关抽屉；重启生效在模型页与托盘 |
| ⑦ ① ④：网关放在什么容器里（最终裁决） | **Codex 行下就地展开**。此前两次更改：独立页 → 抽屉（整页替换丢上下文、跳转突兀 ⑦；常驻右栏无任务时大片空白 ①）→ 就地展开（抽屉是弹层，违反「弹层只有一种用途：确认一个决定」；就地展开是体系已有交互 ④；需要时才出现、不大面积占位 ①⑦）。同一宗旨用于 skill 详情：不做右侧常驻详情栏，点名字该行就地展开 |

## 材料与工艺

**总约束（产品负责人原话）：「依然服务于功能，易用，给人惊喜又符合直觉，剔除不增加价值的任何元素。」** 每个元素都过一道检验：**拿掉它，用户会少知道什么、或少能做什么？答不上来就删。** 每个交互先满足惯例（开关像开关、链接像链接、可点的看得出可点、不可点的不像可点），再在手感和响应上超预期。惊喜放在**行为**上——点格时指示灯即时点亮（乐观更新）、失败时弹回并由黑窗说明原因、撤销一键复原、停转的阻尼——不是多一个图形。任何需要用户学习的新图形语言都算缺陷，除非它换来明确的效率。

**TP-7 的极简不是少画，是：两种材料的大块对比、一个会动的主角、极小而精确的刻字、每个控件都有行程。** 翻译成界面，不拟物——没有金属渐变、螺丝、内阴影、发光灯、橙色点缀。

### 两种材料

| 材料 | 是什么 | 给谁 |
|---|---|---|
| **白面板**（`canvas`） | 放内容、放数据的面 | 表格、表单、列表、对话框的板 |
| **实心黑体块**（`ink`） | 机器在跟你说话的显示窗 | **提示条、错误横幅**（功能理由：「机器对你说话」与「你的数据」用材质分开，一眼可辨、显著性够）；主动作键；删原件弹窗的路径「铭牌」（路径是这次决定里最关键的信息，给它最高显著性） |

**实心黑只有两种意思，不再加新义**：黑色体块＝机器在说话（显示窗、铭牌、提示框）；黑色小键＝已按下或已选中（主动作、点亮的键、选中片、刚变化的格子闪一下）。靠形状分得开。

黑是体块，不是墨水。黑面上的字：主 `canvas`，次 `ink-faint`；黑面上的分隔线 `ink-mute` 1px；黑面上的按钮是 **白描边键**（1px `canvas` 描边、`canvas` 字，2px 圆角）。

- **侧栏是白的**（产品负责人看定调稿后裁定：「黑侧边栏不如白的舒服」）。实心黑只给显示窗、路径铭牌、主动作键与点亮的键。
- **提示条 = 显示窗**：`ink` 实心板，0 圆角，无外框，宽 ≤ 400。左侧 40×全高**指示窗**（右边 1px `ink-mute` 竖线）放 16px 状态记号（✓ / ⊘ / !，`canvas` 线稿）。主行 = **一个动词（600）+ agent 图标 + 名字（400）**：`清除 [Cursor] defuddle`、`写进 [Codex] excalidraw、notion`、`开启 [CC][Codex][C] obsidian-cli`。**动词不能省**——文字只负责名字和动词，提示条 6 秒就消失，动词放 title 等于没有（第 5 轮评审：`✓ [Cursor] defuddle` 读起来和「开启了」一模一样）。名字至多两个，超过写 `+5`（等宽 15/500）；做不成必须带一句能行动的原因（可加副行路径），**动词带否定**：`没开启 [Codex] defuddle · 已有同名`——失败态里写「开启」会被一眼读成已开启。右侧 `撤销` 白描边紧凑键 + `×`。
- **全局收件箱，打开时落在当前页签那一段**（产品负责人）：一个待处理页，顶部分段 `Skills 3 · MCP 1 · 模型 2`（选中段反色，胶囊分段片），从哪个页签进就默认选中哪段；`已忽略 N` 在每段内、不计入数字、可恢复——不想看到，但能找到。顶栏图标数字 = 三段未处理之和；为 0 时不显示数字、图标仍在。页标题就是「待处理」。每条可跳回对应页签的对应行并让该行闪两下（⑦）：`surface` 行带亮 → 灭 → 亮 → 灭，各 240ms；整列的问题闪列头。**跳转定位不用黑**——黑只有两义（机器在说话 / 已按下已选中）。
  模型页的待处理类别（要用户拿主意、且不在某一行上就地出现的）：① **Codex 正由别的工具管理**（检测到 agents-manager 接管）→ `接管` / `忽略`；② **Codex 配置被外部改过**，Sophia 写入的设置不见了 → `重新写入` / `忽略`；④ **某家网关连不上** → `再试一次` / `忽略`（网关页那一行同时就地显示）。「改动要重启 Codex 才生效」不进收件箱——它已在该 agent 行上就地出现，一件事只在一处说。**路由服务没在跑**不进收件箱：它是影响整页的故障（所有第三方模型都用不了），「忽略」毫无意义（⑫ 不给假选项）——先让系统自愈（launchd 拉起、应用启动时自动重试一次），自愈失败才在模型页顶部出页级错误横幅「路由没在跑，第三方模型用不了」+ 紧跟文字的 `重启路由`，不自动消失、不可忽略，恢复后自动收起。
- **MCP「两份不一样」只标差异**（不覆盖、不合并）：待处理页 MCP 段这一条给文字链 `看两边差在哪` → 该行**就地展开**（不开新页、不弹窗，⑦），只列**不同的字段**：字段名 ｜ 位置 A 的值 ｜ 位置 B 的值，三列对齐，相同字段不显示；值用 mono 12，值内不同的那一段加粗标出（不用反色，反色已是「刚变化」）。**headers、env 里的令牌与密钥不显示原值**，只显示「不同 · 末 4 位」，悬停提示「出于安全不显示原值」（⑫）；认证头运行时才生成的，写一句「认证头要到运行时才生成，没法逐字比对」，不假装比过。`在访达中显示 ↗` 降为展开区末尾的次要文字链。主视图该服务行的 `2 份不一样` 提示框里给出差异字段名（`url 不同`）。
- **没有贴底待处理窗**：问题就地显示（行上 `×2`、格内异常记号，悬停即处理）；全局只有一个入口——顶栏收件箱 + 计数 → 待处理页，每条可跳回对应行并让该行闪一下。
- **对话框**：无外框白板，**锚在触发它的那一行附近**；遮罩是 `canvas` 80%（`opacity: .8` 的白层，不用 rgba），**触发行抬到遮罩之上**——用户始终看得见自己正在决定的那一行（⑦）。删原件的路径写在**铭牌**里：`ink` 底、等宽 12 `canvas` 字、内边距 10 12。**承载后果与安全信息的句子必须留**（「这不是关掉一条链接，是把这个目录移走」「跨域会把请求头和令牌一并复制过去」）——那是功能。
- **忙碌态**：只在用户发起、正在等的地方出现，细弧 + 一句「忙什么」（见「忙碌指示」）。

### 提示与反馈锚在触发它的控件上（① 硬规则）

**提示与反馈的锚点 = 触发它的控件；间距 ≤ 16px（1x）；只保护触发控件与其所在行不被遮挡。** 逐张测量后的落实：

- 分组头规则：`▾ 通用仓库 26 · 以后新出现的 → [图标组] [紧凑开关]`（最左 `▸ / ▾` 折叠，见「主视图」）——限定语、目标、开关连读，开关在末尾、离目标图标 8。没有规则的来源静止时只有名字 + 计数；**悬停（或键盘焦点）组头时显示灰色（`ink-faint`）`以后新出现的 → [默认目标图标] [开关]`，可以直接在这里开启规则**——第一次打开时目标默认＝这个来源上次用的目标，没有则已安装的前两个（③）；开启后这一段转墨色常驻。**点目标图标组改目标**：就地弹出与添加页同一组 agent 图标键（同组件、同状态），点亮 / 熄灭即改，至少留一个。规则关闭时这一段整体 `ink-faint`，保留开关以便重开；开关提示框「只管以后新出现的，现有的不变」。添加页底部的规则入口保留（多入口同组件同行为，见冲突表）。
- 批量提示条：左对齐到**被按下的那颗键**，超出面板右沿时右对齐到该键右沿。
- 行内动作跟在描述后面（网关「再试一次」紧跟「连不上」8px）。**列表里多行各有动作时，动作成一列**：句子列宽取最长一句的实际宽度（不为假想长句预留，超出换行），行线止于动作列右沿 + 24，动作列紧随其后、固定起点（离句子列右沿 16）——既就近又对齐，扫一列决定时眼睛不用逐行找键（⑤ 惯例压过逐行贴句尾）。
- 模型页 / 托盘：`名字 + 开关 + 配置网关` 一组。
- 添加页：`以后新出现的也加` 开关离目标键组 16。
- 筛选无结果：筛选框内 ✕ 清除（8px 内），空态按钮只是次要入口。
- 明确的跳转（贴底窗 `›`）、页面级提交（`添加 N 个`）、主从布局（网关「改」→ 右栏表单）不受 16px 限制。 开关、它控制的对象、它引起的提示三者落在同一处（模型页：agent 名 + 开关成组，待重启黑窗挂在名字格下方）。第 8 轮曾把格子提示框挪到面板外 170px，是用具体准则「不盖任何数据点」压过了它服务的原则「就近出现」——没有向上裁决，已撤回。

### 列头与组头的悬停（⑨ 试探要有回应）

- **列头悬停**：整列出列带（与格子十字带同一语言），提示框 `Claude Code · 41 个已开启`。
- **组头规则悬停**：规则作用的那几列列头轻亮（列带淡显），把「以后新出现的会开在哪」与它作用的位置连起来；提示框「只管以后新出现的，现有的不变」。

### 格子悬停预览（⑥ 外观说明如何操作）

核心操作「点格开关」必须看得出能点：**悬停格子时画出将来的状态**——未开启：原环不动、环内填 40% 的实心（`opacity: .4`，不用 rgba）；已开启：实心褪去、只剩环（即显示 ○）。开和关的预览必须长得相反（第 8 轮评审：两者都画成灰实心点是语义事故，灰实心点在「操作进行中」里另有含义）；`cursor: pointer`。原件格、无此格、异常格悬停时不预览（它们点了不是开关），`cursor: default`，由提示框说明。

### 提示框（⑥ 文字提供确定性）

原生 `title` 是系统灰底小框、约 1 秒延迟、位置不受控、无法排版——**不再作为唯一说明**，只作 aria 兜底。提示框是组件：

- **材质**：黑窗，白字 12/400，重点词 600；圆角 0；无阴影无箭头；内边距 6 8；最大宽 240，超出换行。
- **内容**：表格格子只一行 = **动词 + 快捷键**：`点一下开启 · 空格` / `点一下关闭 · 空格`——agent 由列头与列带说明、结果由悬停预览画出，不再重复。表格外元素：一行「是什么」+ 可选一行「按下会怎样」+ 可选快捷键（等宽 12 `ink-faint`，右对齐）。例：禁用键 `Claude Code · User` / `已选的都定义在这里`；待处理记号 `同名：有两份`。
- **位置**（① 就近）：**锚点是触发它的控件，间距 ≤ 16px**。只保护触发控件与它所在的行：列头标签被暂时盖住可以接受（模型页重启提示框右对齐、盖住 `agent` 列头——用户正停在这一行上，此刻最不需要列头）。格子：正上方 6px、水平居中于格子；**允许暂时盖住上一行的邻格，只保护悬停的那一格和它所在的那一行**；首行放不下时放格子正下方。表格外元素（按钮、标签）：上方 6px、水平居中，居中会出窗时对齐外侧边，上方放不下才放下方。
- **可悬停但不可点的触发点用点状下划线**（1px dotted `ink-faint`，同 abbr 惯例）：`同名`、`2 份不一样`、`Codex 不支持`、待处理左列记号。实线下划线只属于文字链（可点）。
- **时机**：表格内停留 **700ms** 才出现，在格与格之间移动时不出现、不追着鼠标（追着走是噪音）；键盘焦点到达后 700ms 出现。表格外的按钮 / 标签 400ms。移开立即消失。
- **与悬停预览配合**：预览是视觉答案，提示框是文字确定性，同时出现、不重复——预览已画出会变成 ●，提示框只写对象和动词。
- **可访问性**：内容同时作 `aria-describedby`，不依赖悬停。
- **承载后果或安全信息的文字一律不截断**（⑥）：限制说明、替换 / 删除的后果、安全提示先缩文案，仍放不下就折行，不用 `text-overflow: ellipsis`——被截掉的往往正是关键那半句（第三方模型「不支持图片」、替换说明）。可以截断的只有名字与路径这类可在提示框里看全的标识，且提示框必须给出全文。

### 键盘（⑧ 熟练用户的快捷路径）

`⌘F` 筛选、方向键在格间移动、空格切换当前格、`⌘Z` 撤销、`⌘A` 全选当前组、`Esc` 取消选择 / 关浮层。键盘焦点在格子上时：1px `ink` 焦点环在格上（偏移 2），十字带跟随焦点。快捷键写进对应控件的提示框，不给新手增加负担。

| 地方 | 默认 |

| 「以后新出现的也加」 | 关；同一来源连续两次选同一组目标时，开关旁轻提示（12 `ink-mute`「每次都选这两个？可以打开」） |

### 自动发生的事要交代（⑨⑬）

规则在背后建了链接时：出黑窗提示条 `自动开启 [Codex] 3 个 · 撤销`，被开启的格子依次闪一下；分组头规则旁的提示框里可看最近一次自动操作（`2 分钟前 · 开启 3 个`）。

### 提示条分两档（① 严重程度决定打断程度；② 处处强调等于没有强调）

黑块只表示「这里需要你注意」：

| 档 | 形 | 给谁 |
|---|---|---|
| **需要注意** | 黑显示窗 | 错误横幅、部分失败、做不成、单格失败原因、自动同步在背后做了事（⑬）、可撤销的删除（删原件 / 删网关 / 只留这份）、悬停提示框（小、短，深色提示框是惯例） |
| **例行成功** | 一行文字：`✓ 写进 [Codex] excalidraw、notion · 撤销`，墨色字直接落在白底上，无框无底，贴触发控件；`撤销` 是文字链 | 就地出现的例行成功（写进 / 开启 / 清除 / 拆开）——结果已由格子闪烁表达，这行只提供撤销入口 |

### 提示条的位置（① 就近）

- **单格操作不出提示条**：格子一闪即反馈；撤销用 `⌘Z` 或格子提示框里的 `撤销`。失败时格子弹回 + 就近（格子下方）出一个小黑窗说原因。
- **批量操作**：提示条是单行（高 32）、内容宽，贴在**被按下的那颗键**正下方 4px，**右对齐该键右沿、向左展开**——不盖住被按下的键所对应那一列的列头（用户按完正要确认是哪一列变了），可以暂时盖住其他列头；被改动的格子同时闪一下，键上的读数随之翻转（`○ Cursor +2` → `● Cursor −2`）。提示条的动词必须和按下的键一致（按 `−2` 是移除、按 `+2` 是写进）。
- **二级页里处理一行**（待处理页）：提示条出现在被处理那一行的位置（行消失处）。
- **无关位置的全局事**（自动规则、后台失败）：右下，右沿对齐面板右沿。

### 视觉优先：文字只负责名字和动词

**状态、关系、后果、进度、位置，一律画出来；文字只负责名字和动词。**（产品负责人：「尽量通过视觉就能理解操作，而不是文字」。）不是把按钮都换成图标——认不出的图标比文字更糟，图标词表之外的动作继续写字。要换掉的是「用句子描述一个本可以看见的东西」。底线：**每个新图形在设计资产板有图例、悬停 `title` 给出文字、屏幕阅读器文本不减**。

| 以前用句子说的 | 现在画出来 |
|---|---|
| 贴底栏「defuddle 有两份原件，删掉哪个？」 | 两行名字后紧跟 `×2`（等宽 12 tabular `ink-faint`）＝有两份，零学习（⑤）。**静止态不放任何按钮**。悬停（或键盘焦点）任一行 → 两行同时出行带，每行名字右侧出现判断用读数（13 `ink-mute`：`改于 9月20日 · 3 个文件`）+ 文字按钮 `只留这份`；点下去另一份进废纸篓，提示条 `只留 通用仓库 的 defuddle · 撤销` 贴在该行下方；按钮提示框「另一份进废纸篓，可撤销」。贴底窗 `defuddle ×2 · 1/3 ›`。（第一版用自创括线「[」+ 无宾语的「删这个」，看不懂也不美观，已删） |
| 链接失效 / 写不进 / 同名被挡：格里不常驻，事后提示条解释 | **在它发生的那一格看得见**，同一个 10px 环的骨架：**失效＝虚线环**（4 段、段间 1.5px 空）——单缺口环像转到一半的加载圈，而「转」是全产品唯一的忙碌语言；虚线在空态里已经教过「虚线＝目标不在」（虚线列头＝这一列还没有目录），链接失效就是「指向的东西不在了」，同一个视觉词只学一次；**写不进＝斜杠环**；**同名被挡＝环内一短横**。悬停出黑窗说原因，点击就是修复动作。 |
| 规则句「新出现的自动同步到 Claude Code · Codex」 | 图式：**来源片 → 箭头 → agent 图标组 + 开关**，不写字（`title` 写全句）。添加页底部的规则同样画成「来源 → 目标」。 |
| 添加页「在以下 agent 开启 ☑ Claude Code ☑ Codex」 | 一排 **agent 图标键**：图标在上、名字在下，与表格列头同一造型；按下＝点亮（反色）。表格里已学会「这个图标＝这一列」，这里复用。 |

### 三种线（层级是功能：哪里是区块边界、哪里只是行）

| 线 | 规格 | 给谁 |
|---|---|---|
| 结构线 | **2px** `ink` | **只给表头底**（面板的上沿） |
| 分组线 | 1px `ink` | 表格里来源分组之间、区块起止 |
| 刻度线 | 1px `hairline` | 行与行、顶栏底（顶栏不是面板） |

### 一种数字

**计数一律等宽（IBM Plex Mono）、tabular；不写别处已有的分母**（列头只写 `41`，不写 `41/56`——56 已在「全部 56」上）——功能理由：计数在片与列头里上下对齐、变化时不抖。**不零填充**（`026` 更难读，是装饰）。等宽只给数字、路径、ID——正文不换等宽。

### 刻字

- 区块小标（`位置` `来源` `已连的网关`）：12，拉丁 Condensed 大写 +0.96px / 汉字 600 字距 0，`ink-mute`（黑面上 `ink-faint`），**贴区块 2px 结构线下沿 6px**。
- **只删重复控件已表达的句子**；机器信息（路径、大小、条数）写成等宽读数而不是散句。

### 表格 = 面板

- **通道条表头**：每个 agent 列头三层——16px 图标 / Condensed 大写名字 / 等宽计数 `41`（`ink-faint`，这个 agent 下开着几个——真实信息）；下面是 2px 结构线。
- **面板要紧凑、有四条边**：`名称` 列定宽 280，agent 列紧随其后各 88；**所有横线、分组线、悬停带止于最后一个 agent 列右沿 + 24**，工具行的 `+ skill` 右对齐到同一条边——右侧留白是真正的留白，不是空列。agent 多到放不下时面板才长到窗口宽、横向滚动。**悬停瞬态内容可越过面板右沿，行带随之延伸；静止态不越界**——同名两行的读数与 `只留这份` 要两行同时比较（⑦ 认出而非回忆），越界部分由行带连回本行（①）。降级：窗口右侧放不下时，改在 `×2` 的提示框里同时列两份读数（`这份 改于 9月20日 · 3 个文件` / `WeiboAP 那份 改于 8月30日 · 2 个文件`），`只留这份` 留在名字格 `打开 ↗` 之后。同名两行名字后写 `×2`，动作只在悬停时出现（见「视觉优先」）。
- **行高 34**（原 40）：一屏多看几行是功能；整格仍是命中区。
- **悬停十字带**：悬停一格时，这一行和这一列同时出 `surface` 带（列带跳过组头行——组头不是数据行）——宽表格里读「这个点属于哪个 agent」的真实辅助。
- **指示灯**：三种外径一致 **10px**，中心对准列头中线：已开启＝10 实心；未开启＝10 外径 1.5px 环 `ink`；原件＝10 外径 1.5px 环 + 4px 实心芯；无此格＝8×1.5 短横 `ink-faint`。

### 忙碌指示：只在用户等的地方，带文字

- **后台例行读取不显示任何忙碌**：页面刷新、文件监听重扫、网关轮询、收件箱计数——用户没有在等，出现转动只会被读成出了问题（①）。**顶栏没有全局忙碌指示。**
- **用户发起、正在等的操作，就地显示并带文字**（⑨ 回应强度与意图相称）：首次扫描「正在读 3 个位置」（内容区居中）、批量写入时行内指示 + 格子依次点亮、重启键原位「正在重启 Codex」、网关保存时按钮原位「正在拉模型」。指示器说在忙，文字说忙什么；没有文字的转动不允许。
- **指示器是惯例细弧**（⑤）：一段 270° 缺口圆弧，1.5px 线宽 `ink`，匀速转 1 圈 / 0.9s 线性；尺寸 14（行内、按钮内）/ 24（内容区居中）。失效是虚线环，静止、不转，两者不混淆。完成即消失，不做停转动画。
- `prefers-reduced-motion` 下不转，改为细弧不动 + 文字后跟 `…` 每 500ms 增减一点。
- busy 期间受影响控件的处理见「空态与忙碌态」。

### 控件有行程

| 控件 | rest | hover | pressed | focus |
|---|---|---|---|---|
| 主动作键（实心黑） | `ink` 底 | 键面内缩 1px 的 `canvas` 内描边（键帽边缘反光） | **下移 1px 且高度压扁 1px**，像键帽被压下 | 外 2px 处 1px `ink` 环 |
| 默认键（描边） | 1px `ink` 描边 | `surface` 底 | `surface` 底 + 下移 1px | 同上 |
| 开关 | 见下 | 轨外缘 1px `ink-mute` | 旋钮压扁 1px | 同上 |
| 复选框 | 12 方 | 描边转 `ink` | `surface` 底 | 同上 |

- **紧凑开关 24×14**（旋钮 8）给行内的规则状态——分组头、添加页的「以后也自动」。它是一条规则的状态，不是本页主角；标准 32×18 只给页面级开关（模型页启用）。
- **开关保持一眼认得出是开关的形态**（胶囊轨 32×18 + 圆旋钮 12，符合直觉优先于像拨杆）；机械感只做在行程和停靠上：切换 120ms、末端 1px 过冲回弹，按下时旋钮压扁 1px。
- 所有状态变化 80–120ms 机械式缓动（`cubic-bezier(.2,.8,.2,1)`），不要弹性果冻，不要 300ms 淡入淡出。

### 别做

拟物（拉丝、螺丝、内阴影、发光 LED、有彩色点缀）；装饰性编号「01」「02」；装饰性网格线、对位刻度、满屏十字准星；数字零填充；对话框装饰边；为了「科技感」把正文换等宽；为了「机械感」把开关换成要想一下的造型。

## Colors

**整个界面零色彩。** 七个**中性**灰阶（R=G=B），没有任何有彩色的值。第一版灰阶照搬 SpaceX 的偏蓝灰（`#f0f0fa` `#e0e0e8`…），评审指出那是「零色彩」里唯一的色相——要么承认它，要么换中性。换了。规范规定色彩全部来自照片，工具里没有照片，所以一个色都不用。

强调只有三种手段，按强度递增：**次要文字（`ink-mute`）→ 加粗 → 反色（`ink` 底 `canvas` 字）**。红色不是其中之一。

**破坏性操作靠信息和文案承担分量，不靠颜色。** 删除弹窗给出完整路径、目录大小、受影响的链接数、git 状态；按钮写「删到废纸篓」而不是「确定」——用户读完就知道会发生什么，再涂红就是吓唬人。

| Token | 用途 |
|---|---|
| `canvas` | 画布 |
| `surface` | 次级面：侧栏选中、悬停、**勾选中的行**（不反色——多选列表里反色行太重） |
| `hairline` | 分隔线、选择片描边、无格态短横 |
| `ink` | 主文字、实心圆点、按钮描边 |
| `ink-mute` | 次要文字、文字链 |
| `ink-faint` | 弱文字、空心圆点描边、hover 前的排序箭头 |
| `disabled` | 禁用描边 |

## Typography

### 三个字族都没有中文字形：字距与大写只给纯拉丁

界面绝大部分文字是中文，会落到系统 CJK 字体（macOS 苹方）。Condensed 大写 + 字距是给 `SKILLS` `MCP` `CLAUDE CODE` 这种**纯拉丁标签**用的工业感；套到汉字上，「删 通用仓库 的」字字散开，「添加 SKILL 到「全局」」窄体大写挨着常宽苹方，同一行像两套系统。评审第 1 轮的最大字体问题。规则：

1. **`letter-spacing` 与 `text-transform: uppercase` 只作用于纯拉丁的 run。** 汉字一律 `letter-spacing: 0`。实现：`<Cap>` 组件按脚本把文本切成 run，只给拉丁 run 套 Condensed + 字距 + 大写；画板里等价于只给拉丁 `span` 写这些属性。lint `cjk-tracking` 查这条。
2. **按钮不走 Condensed。** 界面是中文，按钮几乎都含汉字：`button` 档 = Barlow / 苹方 13 / 600 / 字距 0 / 不大写。专名嵌进去原样写（`删 WeiboAP 的`），不再需要开洞。
3. **页面名 `display` 不大写、字距 0**：`添加 skill 到「全局」`、`Codex 的网关` 原样写。28 / 700，拉丁部分落到 Barlow Condensed，汉字落到苹方。
4. **中文句子里的拉丁词不大写**：`在以下 agent 开启` `哪些 agent 出现在列表里`——句子是内容，只有独立成词的结构标签（页签、agent 列头、模型页的 `AGENT` 列头）才 Condensed 大写。
5. **表头不混排**：我们自己写的列头一律中文（`名称` `原件位置` `传输`），走 `micro-cap` 的字号字重、字距 0。agent / 位置列头是专名，纯拉丁，走 Condensed 大写——它们自成一组（图标在上名字在下）。
6. 顶栏页签 `模型` `SKILLS` `MCP`：汉字页签字距 0，拉丁页签 Condensed 大写 + 1.17px。
7. **例外：agent 图标键跟随列头字体。** 添加页底部的 agent 键、选择条动词键里的 agent 名，和表格列头是同一个对象（agent 身份，④ 同形同义），是可切换的身份键、不是动作按钮——agent 名用 Condensed 大写，与列头一致；键里的中文动词（`开启` `关闭`）仍是按钮字。

### 层级：五档，相邻至少差一倍的视觉重量

| Token | 字号 / 行高 | 用在哪 |
|---|---|---|
| `display` | 28 / 1.1 | 二级页面名、区域大标题 |
| `wordmark` | 20 / 1.0 | 顶栏 wordmark |
| `body` | 15 / 1.6 | 表格、说明、条目名、选择片文字 |
| `button` / `caption` | 13 | 按钮（600）；副行、文字链、选择片、提示条副行 |
| `micro-cap` | 12 / **2.0** | 区域标签、列头、方标签 |
| `mono` | 12 / 1.6 | 路径与计数（嵌在 body 行里，行高跟行走，不撑 2.0） |

**五档之外有两个 `body` 档的变体，它们不是第六档**——字号行高与 `body` 完全一致，变的是字族、字重、字距与大小写：

| 变体 | 写法 | 用在哪 |
|---|---|---|
| `nav-cap` | Condensed 15 / 700 / +1.17 / 大写（只给拉丁页签） | 顶栏页签（一级导航），可点高度 32，在 56 内容区里居中，选中下划线离底 12 |
| `head-cap` | Condensed 15 / 600 / +1.1（`--track-head`） | 区域小标题、弹窗标题 |

**第一版的错**：20 / 15 / 14 / 13 / 12 五档挤在 8px 里，14 与 15、13 与 12 眼睛分不出来，整页读起来像一张密排的表。参照 `DESIGN-spacex.md`：display 到 body 是三倍以上的跳跃，小字靠**行高 2.0** 撑出呼吸感而不是靠字号。所以：页面名拉到 28；砍掉 14 这一档；12px 的标签行高 2.0（占 24px 高，与 SpaceX 的 `micro-cap` 一致）。

### 大写是结构的语言，不大写是内容的语言

大写只给**我们自己写的、纯拉丁的结构词**：页签 `SKILLS` `MCP`、agent 列头。被谈论的对象一律不大写——agent 名出现在选择片、行标题、页面名、句子里时都写 `Claude Code`。

**文件系统来的名字一律原样，不做大小写转换。** `defuddle` 转成 `DEFUDDLE` 后跟表格里的名字对不上。

**skill 名用 `body`，不用 `mono`。** 等宽的理由是路径要对齐、要分得清 `l` 与 `1`；skill 名在列表里是当词读的。`mono` 只给路径与计数。

## Layout

基准 8px，子单位 4 / 12 / 16 / 18 / 24 / 32 / **48**。

### 壳

**顶栏的 wordmark 用 `assets/logo/wordmark.svg`，不用纯文本。** 字标的首字母带和图标同样的重影——那是这个标志的识别点，写成 `<h1>Sophia</h1>` 就丢了。高度 **26px**——20px 时首字母后面那层灰影只有 1px 位移，读起来像套印错位；重影要么大到明显刻意，要么不要。产品负责人要它，所以放大（顶栏内容区 56 高放得下），`currentColor` 取色。

**窗口标题栏不显示产品名**（macOS：`titleBarStyle: Overlay` + `hiddenTitle`）。顶栏自己已经有 wordmark，系统标题栏再写一遍 "Sophia" 是重复。

红绿灯浮在窗口左上角那 28px 里——**那一排留空**，只当拖动区；字标与页签在它下面的 56px 里。第一版把字标和红绿灯挤在同一排，用户反馈"太靠上"。顶栏总高 84 = 28 空 + 56 内容，整条可拖动窗口。**二级页面的头同一条规矩**（它是 `position: fixed` 盖满整窗的）。

**侧栏底部 `+ 项目`**：默认按钮（见「添加只有两种长相」），不带省略号。第一版是带省略号的胶囊，"和其他的格格不入"；第二版降成灰色文字链，评审指出独立的创建动作权重过低。

### 留白：往大了给

| 尺度 | 值 | 用在哪 |
|---|---|---|
| 区域之间 | `huge` 48 | 页面里的大区块（模型页的「agent 行区」与「限制说明」之间） |
| 组之间 | `xl` 24 | 筛选行与表格、表格与待处理栏、表单字段之间 |
| 行内 | `sm` 12 | 同一行里元素之间 |
| 页边 | `xxl` 32 | 内容区左右内边距（SpaceX 的 grid gutter） |

**矩阵行高 40px**，不是 30。密排的表格是"文字很密集"这个观感的主要来源——skill 名、位置名、圆点之间要有空气。

**壳**：顶栏 84 = 28 留空 + 56 内容，底边 hairline；侧栏与内容区之间 hairline；侧栏项高 36px。**二级页面**占满整窗、不渲染侧栏，顶栏换成 `←` + 页面名（`display` 28px）。

## Shapes

**形状承担语义，四种形各管一件事**：

| 形 | 值 | 给谁 | 语义 |
|---|---|---|---|
| 描边矩形 | `control` 2px | 动作按钮、输入框、图标按钮的悬停底 | **点了会执行一个动作 / 在这儿输入** |
| 胶囊 | `pill` 32px | 分段片（待处理页）、模型片、开关轨道 | **一个可切换 / 可移除的状态** |
| 圆 | `dot` 50% | 状态点、开关旋钮 | 只读状态 |
| 直角 | `none` 0 | 复选框、卡、弹窗、横幅、其余一切 | 容器，不是记号 |

第一版「pill＝可点」把动作按钮、筛选片、添加项目、设置页 agent 片全做成 32px 胶囊，评审指出"会执行动作"与"已选状态"形状不可分、胶囊泛滥。现在：**胶囊只留给片**，动作一律 2px 矩形。**有框的都能点。** 不可点的标识（`同名` `2 份不一样` `连不上` `已添加`）是**没有框的 12px 文字**：强的 `ink` 600，弱的 `ink-faint` 400。第 2 轮评审指出，靠 0 圆角对 2px 圆角区分「标签」和「按钮」不成立——1px 黑框的 `同名` 和行内按钮 `清除` 肉眼不可分。

## Components

### 按钮

2px 描边矩形，高 28（行内、提示条、选择操作条里 24），`button` 档文字。三个变体加一个禁用：

| 变体 | 形 | 给谁 |
|---|---|---|
| 主动作 `button-primary` | `ink` 底 `canvas` 字 | 一个面里**至多一个**：确认弹窗的主动作、添加页的 `添加 N 个`、表单的 `保存` |
| 默认 `button` | `ink` 描边、透明底 | 其余动作：`重启` `配置网关` `清除` `拆开` `删 WeiboAP 的` |
| 文字链 `button-link` | 13 `ink-mute` 下划线；**命中区高 24、左右各 6**（视觉不变） | 退路与次级：`取消` `忽略` `撤销` `稍后` `取消选择` `显示未安装的 32 个` |
| 禁用 | `disabled` 描边与文字 | **必须同时给 `title` 说明原因**，类型上强制 |

**同一行里的控件同高。** 工具行与选择操作条是 28 的一行：输入框、动词键、图标按钮、按钮全是 28。表格行、待处理栏、提示条、行内待办条是 24 的一行：按钮 24、模型片 24。胶囊片和矩形按钮并排时靠形状区分，不靠高度差。

**文字链有两种，长得不一样。** 应用内的次级动作（`取消` `忽略` `撤销` `稍后` `添加项目`）：13 `ink-mute` 下划线。**离开 Sophia 的链接**（`打开目录` 去访达、`检查更新` 去网页）：同样的字，末尾跟一个 10px 的 `↗` 线性箭头（1.4 描边，`ink-mute`，左间距 3）。旧规范写「离开 App 是唯一可以用文字链的地方」，这一轮把次级动作也降成了文字链，所以要靠 `↗` 把两种分开。

**没有 hairline 描边的按钮。** 线上画布一度有一档 `#e0e0e8` 描边的「次级按钮」，评审指出它比旁边的开关弱一档、读起来像禁用态。次级就是文字链，不再有第三种描边。

**按钮里的专名不靠空格断词**：`删通用仓库的`、`删 WeiboAP 的`（中西文之间一个普通空格是排版惯例，汉字之间不加）。

**按钮上只写动词，不写宾语。** 宾语是它所在的那一行：Codex 行上写 `重启`。宾语只在按钮离开了它的对象、或单一个动词说不清去哪时才回来——空态 `添加 skill`、`配置网关`、`添加网关`。

**能画出来的动作不写字**，见「图标」词表。

### 图标按钮 `button-icon`

16px 图形、**1.4 描边**、**28×28** 命中区（与按钮同高）、无描边无底、悬停 `surface` 底 2px 圆角。**必须带 `title`**（同时是 `aria-label`）。顶栏的待处理入口与设置齿轮是同一个组件、同一个尺寸；待处理数用 `mono` 12 跟在图标右侧 4px。

### 开关 `Switch`

**一个当场生效的布尔状态，对象就是它所在的那一行**，用开关，不用「启用 / 已启用」两态按钮。轨道 32×18 pill、旋钮 12px 圆：关＝白底 ink 描边、旋钮 ink 在左；开＝ink 底、旋钮 canvas 在右。零色彩，无过渡以外的动效（120ms 位移）。**开关旁边不写「已启用」**——它自己就是状态。

用在哪：模型卡的启用、自动同步 / 自动添加那一行、添加页顶部的「新出现的自动添加」规则。**不用在哪**：选择（那是 12px 方形复选框——方＝我选的，开关＝它开着）、需要一次提交的多输入。

开关都不需要确认：曾经「开启自动同步」要确认一道，是因为它会把来源里现有的几十个一次建完；现在规则只管以后新出现的，规模问题没了。

曾经的 Don't 写「不用滑动开关（iOS 语言，必带圆角）」，作废：胶囊在这套系统里是「一个可切换的状态」，开关正好落在这个语义上。

### 状态与动效

| 项 | 取值 |
|---|---|
| 可点元素高度 | `--control-h: 28px` / `--control-h-compact: 24px`，**一律偶数**——奇数高会让 pill 端帽只有 75% 覆盖，同一圈描边一半实一半虚，读起来就是「锯齿」 |
| 命中区下限 | `--hit-min: 24px` |
| 焦点 | 只认 `:focus-visible`：1px `ink` 外框、偏移 2px；反色面上转 `canvas`。**不要系统默认的蓝色焦点环**——那是零色彩界面里唯一闯进来的彩色 |
| 过渡 | 只有一档 `--motion-fast: 120ms`，且 `prefers-reduced-motion` 下全部关掉 |
| 数字 | `font-variant-numeric: tabular-nums`，计数跳动时不抖 |
| 字形渲染 | `-webkit-font-smoothing: antialiased`，关掉 macOS 次像素渲染的彩边（零色彩系统里它是真能看出来的） |

### 选择片 `Chip`

胶囊，高 28，文字 `caption` 13（不大写，内容是专名），计数 `mono` 12。未选中 hairline 描边，选中**反色**，不可选灰描边灰字。图标 14px 在左，间距 6px。用在：待处理页的分段（`Skills 2 · MCP 0 · 模型 0`）。主视图不再有来源筛选片（见「主视图」），选择操作条是动词键（见「选择操作条」）。**不用来选「哪些 agent」这类设置**——那是复选框列表（见「设置页」）。

### 状态点 `StateDot`

格回答两件事：**填充＝这个 agent 能不能用它，外环＝它在这儿是原件还是一条软链。**

| 状态 | 形 |
|---|---|
| `linked` 已开启 · 软链 | 9px 实心 |
| `missing` 未开启 | 9px 空心 `ink-faint` |
| `own` 已开启 · 原件 | 13px 外环 + 6px 内实心 |
| 无格 | 8px `hairline` 短横，不可点 |

**前三行是状态，第四行不是**：「无格」说的是这儿根本没有这一格，不是某种状态。常驻的状态只有那三种。异常态（链接失效、指向别处、同名被占、整个文件夹是链接、写不进去）**画成空心**，但点击行为与文案分叉——由提示条说原因，需要拿主意的进待处理栏。

勾选中的行用 `surface` 底，圆点不变色。空心圈描边 `ink-faint` 1.4px（第一版用 `disabled`，白底上过淡）；「无格」短横 8×1.4px `ink-faint`（第一版用 `hairline`，融进了行分隔线）；原件点 13px 外环 + **6px** 内芯。

### 矩阵列头

**16px 图标在上、名字 `micro-cap` 在下，堆叠。** 列宽约 84px。

**列头没有灯。** 曾经在图标右上角放一盏 6px 的灯表示目录状态，用户看不懂。目录不存在这件事在点击那一刻由提示条说（「已经建出来」），写不进去的进待处理栏——列头不需要再说一遍。

### 图标

所有图标同一套画法：16px 画布、`currentColor`、1.4 描边。**设置的入口必须是有齿圈的齿轮**——第一版画成圆心加八根放射线，那是太阳，用户看成了「切换日间模式」。看不懂的图标比没有图标更糟，这条和列头灯是同一课。

**词表——只有这几个动作有图标，别的一律写字**：

| 动作 | 图形 | `title` |
|---|---|---|
| 设置 | 8 齿齿轮 | `设置` |
| 改 | 铅笔（45° 斜置） | `改` |
| 删掉 | 垃圾桶（带盖） | `删掉` |
| 添加 | `+` | `添加网关` 这类带宾语的全名 |
| 关掉 / 移除一片 | `×` | `关掉` |
| 返回 | `←` | `返回` |
| 搜索 | 放大镜（输入框内） | — |

判据：**离开这个界面，用户在别的软件里见过同一个图形做同一件事**。「重启」没有这样的图形（循环箭头是"刷新"），「拆开」「忽略」「再试一次」更没有——这些写字。

### agent 图标 `AgentMark`

单色 inline SVG，`currentColor` 取色。**不用品牌色。** **Codex 用 OpenAI 绳结标志**（识别特征：中心六边形空洞 + 六段逐段旋转 60° 的交织弯折）：第一版六瓣软轮廓在 16px 下读成云 / 齿轮，认不出比没有更糟，又不能退回首字母（「C」已给 Cline）。取官方 SVG 转单色；16px 糊时宁少一层交织，保住中心六边形与外轮廓六个圆角。所有出现处走同一个定义。 光学补偿：Claude Code 的星形是放射实线，同尺寸下比其他线性图标重——描边降到 1.2、视觉尺寸比其他小 1px。 实现时用各项目官方 SVG 转单色路径，不手画。取不到的用**首字母方块**（14px，hairline 描边、`ink` 字母；未启用时字母随名字退到 `ink-faint`）——它是图标缺席时的占位，**永远和名字一起出现**：已安装的 9 个里首字母就撞了 3 个 C、2 个 G。

### 选择操作条

勾选一个以上 skill 后，**顶替工具行**（同一个 28 槽位）：`已选 N 个` + 每个 agent 一颗**动词键** + `全部开启` / `全部关闭` + `取消选择`（文字链）。

每颗是**默认按钮（2px 矩形，28，compact）**，内容 = **动词 + agent 图标 + agent 名**，语义是「对已选的 skill，在这个 agent 下做这件事」：

| 已选的在这个 agent 下 | 键上写 | 点一下 |
|---|---|---|
| 全部开着 | `关闭 ✳ Claude Code` | 全部关掉 |
| 有没开的 | `开启 ⎔ Codex` | 把没开的补齐 |
| 受影响数 ≠ 已选数时 | 末尾加数量：`开启 ⎔ Codex · 2 个` | — |
| 没有能做的（都是原件、或这个 agent 整个文件夹是链接） | 禁用；提示框说原因（`已选的都是原件` / `Cursor 的 skills 整个文件夹是链接`） | — |

- **agent 用列头同一枚图标标识，不用圆点**：圆点在按钮上读成「已选中」，`−1` 读成负数——都要用户解码（⑤⑥）。第 5 轮的「状态点 + 增量」写法已撤回。
- `全部开启` / `全部关闭`：已选的在所有 agent 下都开着 → `全部关闭`；否则 `全部开启`（补齐缺的）；受影响数 ≠ 已选数 × agent 数时同样补数量。
- 键上 agent 名跟随列头字体（Condensed 大写），见「Typography」的例外；动词是中文按钮字。
- 结果：例行一行提示条贴在被按下的那颗键下方（见「提示条的位置」），动词与键一致；键随之翻转（`开启 ⎔ Codex` → `关闭 ⎔ Codex`）。
- **`全部` 的效果恰好等于某一颗 agent 键时，隐藏 `全部` 键**（两颗键做同一件事是噪音）。
- 放不下时（agent 很多）：先按上一条省掉重复的 `全部`；再把键距收到 4；仍放不下 `已选 N 个` 缩成 `N 个`（最后手段——光写「2 个」看不出是什么的 2 个，⑥）；再放不下，agent 名只留图标，名字进提示框。

第一版用胶囊片（反色＝全开），和同槽位的筛选片同形不同义；第二版「状态点 + 增量」要解码。现在键上直接写动词。**不要**退化成只有「开启 N」「关掉 M」两个按钮——那丢掉了「针对某个 agent」这一维。

### 「添加」只有两种长相

- **提交一次添加**（`添加 6 个` `保存`）：主动作，反色。
- **开始一个添加流程**（添加 skill / MCP / 项目 / 来源 / 网关）：**默认按钮，`+` 图标 + 名词**：`+ skill` `+ MCP` `+ 项目` `+ 来源` `+ 网关`。`+` 是 12px 1.4 描边线性图形，与名词间距 6。它是独立的创建动作，不是次级——不用灰色文字链，也不用光秃秃的图标按钮。

### 空态与忙碌态

四种空态（扫描中、这个域没有目录、筛选无结果、一个都没有）各自说明现状与下一步；两个动作时**只有一个是按钮**，另一个降文字链。busy 期间受影响控件 `opacity: .45`，**五个豁免**：设置、筛选输入框、取消选择、提示条关闭、表头排序——保持 `opacity: 1`，不加聚焦态，对比本身就说明它还能用。

### 表头排序

默认无箭头（`visibility: hidden` 占位，hover 时行不跳）、hover 出 `ink-faint` 箭头、激活转 `ink`。busy 期间不禁用。

## Patterns

**这一节只放与产品无关的组织法**——换一个产品、换一批对象，这些规则照样成立。
凡是「本产品叫什么、算什么、显示几个」的裁决，一律去 `## 产品裁决`。

### 说结果，不说机制

软链是我们的实现手段，不是用户的目的。**只在用户需要据此判断时才提软链**——删原件的弹窗要说「2 条链接会因此失效」，因为那正是他要权衡的；其余时候说他能看见的结果。

| 别写 | 写 |
|---|---|
| 添加＝在选中的 agent 下建软链接 | 让这些 skill 出现在「全局」的列表里 |
| 没有需要建立的链接 | `<agent>` 下已经有同名的 `<skill>`，没有覆盖它 |
| 操作失败，请重试 | `<agent>` 的 skills 目录写不进去 |

### 命中区与视觉尺寸是两回事

**视觉可以小，命中区不能小于 24×24。** 12px 的方形复选框、片上 9px 的 `×`、6px 的圆点——它们的**视觉**尺寸由层级决定，但点击目标要用透明外圈撑到 24px 以上；列表行里的选择记号更进一步：**整行可点**，记号只是告诉你点了会发生什么。

**撑命中区不能改变视觉尺寸。** 用 `padding` 撑的话 `border` 会画在 padding 盒外沿，12px 的框就成了 24px——模型选择器里的复选框就是这么变大的，和 skill 列表里的一比就露馅。正确做法：视觉元素保持自身尺寸，命中区用伪元素或透明 `outline`/负外边距的包裹层撑，不动 border。**同一个记号在全应用里只能有一个尺寸。**

### 可点的面：hover 怎么表示

零色彩系统里能用的只有描边和反色，按面的形态分两种：

| 面 | 静息 | hover |
|---|---|---|
| 有 `hairline` 描边的块（区块、输入框、未选中的片） | `hairline` 描边 | 描边转 `ink`，**底色不变**——换底色会把里面 canvas 底的片糊掉 |
| 无描边的列表行（侧栏项、表格行） | 无描边 | 底色转 `surface` |
| **静息就已经是 `ink` 描边的面**（按钮、选中的片） | `ink` 描边或反色 | 描边已经到顶，**改底**：ghost pill 铺 `surface`、按下转 `hairline`；反色面退到 `ink-mute` |

第三行是前两条规则的盲区：描边只有 hairline → ink 一档可升，升满了就没有下一档，所以只能改底。

### 什么时候才有按钮

**界面里的改动默认当场生效。** 勾选、开关、改名、删片、筛选——点了就是结果，不需要第二步去确认它。这条原则曾散在四处注释里（「返回即保存」「改一个生效一个」「切换开关即保存」「不给拉取模型单独按钮」），从没被正面写出来，于是新写的浮层又长出一对「保存 / 关闭」。

只有三种情况配得上一个按钮：

1. **要离开当前语境去做一件外部的事**：`配置网关`、`重启`、`添加 skill`（启用不在这里——它是当场生效的布尔状态，走开关）
2. **多个输入必须一次提交、中途状态没有意义**：网关地址 + 密钥 → `保存`（且保存即拉取）
3. **真会丢东西、需要确认一道**：删原件、MCP 的批量或跨域写入、重启 Codex——与「页面还是弹层」那三处确认同源

**「关闭」「取消」「确定」不是动作。** 浮层点外面或 Esc 关；二级页面 `←` 或 Esc 回；离开即提交。唯一例外是确认弹窗里的 `取消`——那是在回答一个问题，不是在关一个面。

一句判据：**操作本身已经说明了结果，就不要再放一个按钮教用户怎么完成它。**

### 反馈：四个地方会说话，一件事只在一个地方说

| 说什么 | 在哪 | 形 |
|---|---|---|
| 刚做完了什么（会消失） | 提示条 `toast` | 右下浮层（**右沿对齐面板右沿**，没有面板的页面对齐页边 32；底 16）；有触发控件时按「提示与反馈锚在触发它的控件上」），一次操作汇总成一句，不排队。6 秒（做不成 8 秒）。可逆的给 `撤销` |
| 应用级故障（不会消失） | 错误横幅 `banner-error` | 顶栏之下通栏反色 |
| 要你拿主意，散在几十行里 | 就地记号 + 顶栏收件箱 → 待处理页 | 行上 `×2` / 格内异常记号悬停即处理；收件箱计数常驻，进完整列表，每条可跳回对应行 |
| 要你拿主意，就挂在这一行上 | 行内待办条 `row-notice` | 一句话 + 紧凑按钮 + `稍后`（文字链） |

**二级页面自己渲染提示条**（待处理页已经这么做）。壳上的提示条只服务主视图。二级页面里上游服务够不着这类失败（网关拉不到模型列表）走错误横幅——它不是某次点击的结果，是那条链路此刻不通，用户得读完再走。

**提示条里的动作（`撤销` `查看`）行内右置**，与 `×` 同一行，不掉到第三行。

**MCP 写入的撤销**（⑪ 能撤就给撤销，⑫ 撤不了就说实话）：MCP 写入前 core 用 atomicfile 在同目录留一份快照备份；提示条给 `撤销`，从快照原子还原——**只有目标文件仍等于写入后的指纹（写完没人改过）才能撤**，还原同样走 atomicfile（写用户配置文件的唯一通道）。指纹对不上时 `撤销` 禁用，提示框「写入之后文件又被改过，没法安全撤销」，提示条里另出一个次要文字链 `在访达中显示备份 ↗` 作手动兜底（能撤时不出现）。备份只保留最近一份：**撤销窗口＝提示条存活期，且在下一次写入同一文件之前**。批量写入涉及多个文件时先查全部指纹，任一对不上整笔不撤。「看看备份」一词删除。

**提示条的四种形态**（都是黑显示窗）：成功（✓ + agent 图标 + `+2` + 名字 + `撤销`）、成功多项（✓ + 多个 agent 图标 + 名字）、做不成（⊘ + 一句能行动的原因）、部分失败（! + `2 ✓ · 1 ⊘` + 哪里没成 + `查看`）。

**待处理栏里每一类都带自己的动作**：

| 类 | 一句话 | 动作 |
|---|---|---|
| 同名原件 | `<skill> ×2` + 两份各在哪 | `只留 <位置A> 的` / `只留 <位置B> 的` / `忽略` |
| 链接失效 | `<skill> 在 <agent> 下的链接指向的位置没了` | `清除` / `忽略` |
| 整个文件夹是链接 | `Codex 的 skills 文件夹整个链接到了 WeiboAP，拆开后才能逐个开关`（`拆开` 的提示框：「把链接换成真文件夹，里面的内容原样复制过来」） | `拆开` / `忽略` |
| 写不进去 | `<agent> 的 skills 目录写不进去` | `再试一次` / `忽略` |

同名原件那条：**两份原件各自仍在列表里成行**，待处理栏只负责问删哪个。不要用"指向别处、没有覆盖"这种格视角的话——那是点格时提示条说的，待处理栏说的是行视角的事。

**「忽略」记的是这一条具体状况**，不是记这个 skill：涉及的位置发生变化后重新提示。key 由前端与 core 按同一公式算（`tests/issue-key-contract.test.ts` 与 `store.rs` 两边钉死）。

### 页面还是弹层

**弹层只有一种用途：确认一个决定。** 设置、添加、待处理是二级页面。**属于某一行的配置就地展开在那一行下面**（网关在 Codex 行下、skill 详情在该行下），不另开页面，也不做抽屉——抽屉也是弹层。弹层把用户困在一个小框里，挤出来的信息密度低。

**主动作用反色，`取消` 是文字链**——第一版两者只差一档描边，主次不分。**确认只给两件真正不可逆的事**（⑪ 能撤销就不弹确认）：**删网关也不确认**——该行立即消失，就地提示条 `删掉 openrouter.ai · 撤销`；提示条消失（8 秒）或离开网关页时才真正删配置与钥匙串密钥（应用退出时立即提交），撤销则原样恢复。**删原件不再确认**——进废纸篓可恢复，直接删 + 黑窗提示条 `删到废纸篓 [■] defuddle · 撤销`（撤销时一并还原改指过的链接；后果示意图放在提示条的展开态）。确认只剩：MCP 的**批量或跨域**写入（跨域会把请求头和令牌一并复制过去）、**重启 Codex**（会结束正在运行的进程）。开关链接、清除失效链接、**MCP 同域的单格写入**都不确认。

## 产品裁决

下面几节是 Sophia 自己的决定，**不是设计系统的一部分**。做别的产品时照搬这里的结论没有意义，
该照搬的是上面的 Foundations / Components / Patterns。

### 术语

**把一样东西放进一个位置，全应用一个动词：「添加」。** `添加 skill` `添加 MCP` `添加项目` `添加网关`。曾经 skill 叫「导入」、MCP 叫「引入」，用户先要求统一，再问"要不要干脆不叫导入"——「导入」暗示从外面拷一份进来，实际做的是建链接 / 写一条配置，用户看到的结果就是"这里多了一个"，那就说「添加」。没选「新增」：它和自动规则那句里的"新出现"撞词（`此来源新出现的 skill 自动新增`）。

**页签是名词，不是动作**：`模型` `Skills` `MCP`。第一版 MCP 页签叫「导入 MCP」是为了和二级页「导入 skill」错开，现在动作只在按钮上出现，页签就不用扛它。

**界面文案里不说「矩阵」，说「列表」。** 「矩阵」是我们对那张表的叫法（行 × 列），用户看到的是一个 skill 列表，每行后面几个开关。设置页那句是 `哪些 agent 出现在列表里`。

界面文案里**不出现「harness」**，一律 agent。代码标识符不动（`disabled_harnesses` 是已落盘的键、`matrix` 是组件名）。

### 来源的名字

来源的标签是**用户认得的名字**，不是路径：

| 来源 | 标签 |
|---|---|
| 通用仓库 | `通用仓库` |
| agent 的全局目录 | agent 名 |
| 项目 | 项目目录名 |
| 应用包内的目录（`/Applications/ego lite.app/…/ego-skills`） | **应用名** `ego lite`——从 `.app` 那一级取，去掉后缀 |
| 应用数据目录（`~/Library/Application Support/WeiboAP/…`） | **应用名** `WeiboAP`——`Application Support` 下一级 |
| 其余外部目录 | 从末尾往上找**第一个不是泛称的分量**：`~/.local/share/ego/skills` 叫 `ego` 不叫 `skills`。末尾一级几乎总是 `skills` 这类泛称，光取它三个来源会撞成一个名字 |

路径放 `title`。绝对路径**不出现在任何可见文案里**，除非用户正要据此做判断（删原件的确认弹窗）。

**矩阵「原件位置」列不给外部来源挂「外部」标签。** 用户要知道的是它叫什么、在哪，`ego lite` 这个名字已经说完了；「外部」是我们的分类词，对用户没有信息量。添加页的来源栏保留分类，那里是在挑来源、分类有用。

### 主视图：表格是主角，表头在第一屏的上四分之一

评审第 1 轮量过：待处理横幅 + 说明横幅 + 筛选行 + 自动同步框四层叠在表格上面，首行数据落在窗口高度 54% 处，56 个 skill 只露 8 行。现在内容区从上到下只有**两样**：

1. **工具行**（高 28，上下各 16）：筛选框（弹性，最小 200，放大镜在框内，占位 `筛选`）+ 右端 `+ skill` / `+ MCP` 按钮，右沿对齐面板右沿。**没有来源筛选片**：表格已按来源分组，筛选片与组头重复表达同一信息（①④）；收进下拉违反 ⑦（选项保持可见）。按来源看靠**组头折叠**（▸ / ▾，⑤ 惯例），总数 `全部 N` 并入 `名称` 列头（`名称 58`，计数 `mono` `ink-faint`）。MCP 同理。
2. **表格**：表头紧跟工具行。1100×720 的窗口里表头 y ≤ 200。

其余三样各归其位：

- **自动添加规则在组头**（见「材料与工艺」的分组头规则），不在工具行。
- **点 skill 名字，该行就地展开详情**（不做右侧常驻详情栏）：名字前 12px `▸ / ▾`；展开区左沿与名字对齐、不跨进 agent 列，内容：描述（取自 `SKILL.md` frontmatter 的 `description`，`ink-mute` 13，不截断）、原件路径（`mono` `ink-faint`）+ `打开 ↗`、`改于 9月20日 · 3 个文件`。再点或 Esc 收起；一次只展开一行。读不到描述时这一行不写，不写「无描述」。
- **组头可折叠**：组头最左一个 12px `▸ / ▾`（整条组头是命中区，Enter / 空格切换），折叠后只剩组头一行；折叠状态按来源记住（每个查看者本地）。筛选时自动展开有命中的组。
- **工具行、列头吸顶，当前组头吸在列头下方**（⑦ 长列表滚动后仍知道每列是哪个 agent、自己在哪个来源；工具行与选择条共用槽位，滚动时要够得着）：工具行在最上，列头连同 2px 结构线紧贴其下；滚过某组时，该组组头吸在列头正下方，被下一组组头顶走。吸顶时不加阴影，靠 `canvas` 底色盖住下面的行。
- **勾选了 skill 时，选择操作条顶替工具行**，同一个 28px 槽位：`已选 2 个` + 动词键 + `取消选择`（文字链），`+ skill` 随工具行一起让位。不另起一行。**默认一行不选，选择条不出现。**
- **没有待处理栏**：问题在行上就地显示与处理，汇总入口是顶栏收件箱（见「材料与工艺」）。
- **没有常驻说明条。** 「列表里只出现两种 skill：原件…软链…」是机制说明，放列头 `名称` 的 `title`。

**MCP 的表头与 Skills 同高**：全局位置下 scope 恒为 User，位置列头只写 agent 名一行（图标在上）；项目位置下才出现第二行 `LOCAL` / `PROJECT`。**MCP 没有「来源位置」列**——定义住在哪由原件环点表达（同一套圆点语言）。侧栏项只写项目名（`CardBox`），「位置」小标题下本来就都是项目，不加 `项目 ·` 前缀。

**表格列**：`名称` 吃掉剩余宽度；`原件位置` 120，紧挨 agent 列；agent 列各 84。第一版 `原件位置` 到第一个 agent 列之间一大段死白。MCP 的 `传输` 列只写真实的传输方式（`HTTP` `stdio`）；「某位置不支持」不是传输方式，在服务名后挂 `tag-weak`。

### 计数口径

一页上出现的数字口径必须一致。侧栏域名右侧＝该域有格可点的 skill 行数；列头 agent 名下＝该 agent 下能用的格数；添加页来源栏「未添加」列＝未添加数，列表头 `· N 个原件`＝原件总数，**两个数不共用位置**；自动同步行＝下一轮会新建的条数，**带单位写成 `N 条待建`**，裸的 `+N` 会被读成「还有 N 个 agent」。

### 列的存废

看「用户还有没有别的入口」，不看「文件存不存在」。Skill：目录不存在的 agent 照样成列（藏了用户就没别的地方能把目录建出来）。MCP：Claude Code 在一个项目里的第二个空位置藏起来（它仍是「添加」的显式目标，入口没丢）。

### 模型页

**一张表，一个 agent 一行**，与 Skills / MCP 同一种列表语言（线上画布评论里定的：卡片在只有一个 agent 时很丑、满宽卡内容撑不满）。页面上没有解释段落。

表头 `AGENT` ｜ `生效模型` ｜ `启用`。一行：

| 列 | 内容 |
|---|---|
| agent（232） | 24px 图标 + 名字（`wordmark` 档 20/700，不大写）+ **启用开关紧跟名字右侧**（名字 + 开关成组）；待重启黑窗挂在名字格下方 |
| 生效模型（504） | 一个常驻的 hairline 框，里面是模型片（显示友好名 `Opus 4.6`，完整 id 进 `title`；带 `×`）；框尾端等宽 `103`（可选模型数，`title` 写全）+ 展开记号——放在下拉框尾自然读成「这里有 103 个可选」；整框可点，点开时框线转 `ink`，选择器浮层从框下方展开、**与框同宽左对齐** |
| 行尾 | `配置网关`（默认按钮，紧凑 24） |

**三个主视图怎么对齐**：左沿与顶部结构线（列头底 2px）一致；**右沿随各自内容**——Skills / MCP 随 agent 列数变，模型页取自身宽度（agent 列 324 + 24 + 生效模型列最小 360 + 24）。第 5 轮的「模型页右沿对齐 MCP」已放弃：真实数据下 MCP 只有两列（552），对齐就放不下模型框。

**没有版本、路由状态、网关几家**这些内部事实。**「改动待生效」由一个按钮表达，按钮即状态**：`needsCodexRestart` 比的是 Codex 启动时加载的配置与现在——用户用任何方式重启 Codex 都会自动变回一致，Codex 没在跑也不出现，它永远说实话。所以 agent 同一行、`配置网关` 之后 12 放一个紧凑描边键 `重启生效`（同高 24）；提示框「重启 Codex 桌面应用让改动生效，进行中的对话会中断」（只写点击的后果与代价，不替设计解释为什么关不掉；「桌面应用」是 ⑫ 分支——目前只检测得到桌面应用拉起的 Codex，终端里的 `codex` 检测不到也不会被重启，**CLI 检测补上后去掉「桌面应用」**）；点击出锚定确认（打断对话，⑪），次按钮 `取消`；确认框不重复提示框原话——能检测到进行中的对话就写「有 2 个对话正在进行，会中断」，检测不到写「会结束 Codex 正在运行的进程，进行中的对话会中断」；Codex 被以任何方式重启后键消失。不配读数、不给「稍后」、不用黑块、不做可关闭的提示——按钮出现 / 消失本身就是状态。（不加 ↻ 图形：循环箭头是「刷新」，图标词表之外写字。）

**点了「重启生效」之后**（⑨）：确认后键位原地换成 14px 细弧 + 「正在重启 Codex」；成功——键消失，原位一行例行成功文字 `✓ 已生效`，约 4 秒后淡出（reduced-motion 下直接消失）；失败——黑块「做不成」+ 原因（`Codex 没能在 15 秒内重新打开`）+ `再试一次`。状态规则不变：Codex 被以任何方式重启或退出 → 键消失；Sophia 重开时若 Codex 仍在用旧配置 → 键照常出现（⑫）。

**选择器**：搜索框 + 列表，已选置顶，12px 方形复选框；整行可点，勾选当场写盘，没有保存 / 关闭按钮；底部一句 `已选 2 个模型`。

**网关在 Codex 行下就地展开**（不是页面，也不是抽屉）：点 `配置网关`，这一行向下展开（键为按下态，展开 / 收起 200ms 机械缓动，reduced-motion 即时）；再点或 Esc 收起。模型下拉里的 `管理网关 ›` / `还没有网关 · + 网关 ›` = 收起下拉并展开这一行的网关区。不配置时不占位（① 需要时才出现），配置出现在所属 agent 正下方（⑦ 不跳页不遮挡），就地展开是体系已有的交互（④：MCP 差异、同名替换、组头折叠）。展开区三层，逐层按需：
- **网关切换**：分段片（与待处理页同组件）`ap-gateway 103 · openrouter 连不上 · + 网关`，选中反色。
- **连接**：已连上的只显示一行摘要 `https://ap-gateway… · 已连 · 改`，点 `改` 才展开 `地址` `密钥` 表单（`保存` 主动作、保存才生效、保存即拉取，保存中原位细弧 +「正在拉模型」；`取消` 文字链复原）+ 只读 `本机端口` `协议`。新加网关直接显示表单。连不上：`连不上` + 8px `再试一次`。删网关：摘要行尾垃圾桶图标键，就地提示条 `删掉 openrouter.ai · 撤销`（延迟提交，见「页面还是弹层」）。
- **从这个网关选模型**（段头下是限制说明，不截断）：与模型下拉同一组件的勾选列表，只列本网关的模型，**勾选即生效**；超过约 8 行在自身范围内滚动，带筛选框；底部 `已选 N 个模型`。新加网关保存成功后这一段原地出现，新模型各闪一次。
- 上方行内的模型框是结果摘要：勾选实时增减模型片；需要重启时 `重启生效` 出现在同一行。
- 收起时 `连接` 有未保存的改动：不收起，就地一句「地址改动没保存」+ `保存` / `丢弃`（⑪⑫）。
- 模型页下拉仍列全部网关的全部模型；展开区只列本网关的子集，同组件同状态。**没有「选模型 ›」跳转**。

**`重启`**：结束这个 agent 的常驻进程。会中断进行中的对话，**确认一道**——弹窗标题 `重启 Codex？`，正文说全后果，主动作只写 `重启`。没有禁用态。

### 添加页（skill 与 MCP 共用一套骨架）

二级页面，两列 + 底部一个块。两页**逐句对称**，只换名词：

| 位置 | skill | MCP |
|---|---|---|
| 页面名 | `添加 skill 到「全局」` | `添加 MCP 到「全局」` |
| 左栏列头 | `来源` / `未添加` | `来源` / `未添加` |
| 左栏一行 | 名字一行 + 范围第二行灰字（`全局` / `项目` / `外部`）+ 右端未添加数（为 0 时 `ink-faint`，排到列表后面）。**同名来源**（如三个 `WeiboAP · 外部`）第二行改写能区分它们的路径片段——只显示路径里不同的那一级（`外部 · agent_1776…`），提示框给完整路径 | 同左，名字是位置名 `Claude Code · User` |
| 左栏底 | `+ 来源`（默认按钮，**固定在来源栏底部**，来源列表在其上方独立滚动；列表可滚时底部与按钮之间出 1px hairline，不滚时不显示——与侧栏 `+ 项目` 同一做法）。0 个来源时**不分栏**：内容区居中一块，「还没有来源」/「先添加一个放 skill 的文件夹」（`ink-mute`）/ 反色 `+ 来源`，垂直紧排（间距 8 / 16）；有了第一个来源才出现两栏 | —（MCP 的位置是发现出来的，没有添加入口） |
| 列表头 | `通用仓库 · 24 个` + `全选`（复选框） | `Claude Code · User · 5 个` + `全选` |
| 列表行 | **只列未添加的**：复选框 + 名字；同名的行尾 `tag` `同名`。已添加的收进列表最后一行 `已添加 25 个 ▸`（12 `ink-mute`，可展开）；展开后已添加项**不渲染复选框**，名字 `ink-faint`，悬停没有可点的反馈（外观不能说「可点」却点了没反应，⑥⑩）。未添加为 0 时右栏只写一句「通用仓库里的都已添加」+ 下面那行 `已添加 25 个 ▸` | 同左，另有一列 `传输` 灰字 |
| 底部块第一行 | **一组目标**：agent 图标键一排（**高 32，图标 14 + 名字同一行**，宽随内容；点亮反色）…… 同一行末尾（间距 24，不加连接短横）`[紧凑开关] 以后新出现的也加` …… 右端 `添加 N 个`（主动作，同高 32）。规则目标 = 本次目标，不另画一排图标（两种样式会被读成两组独立设置）（图标 + 名字）…… 右端 `添加 6 个`（**主动作**） | `写进以下位置` + 位置复选框 …… `添加 2 个` |

- **页面只有两段**：上面挑什么，底部块说加到哪。规则开关和目标在同一个块里——规则的目标就是上一行勾的那些。它是开关不是复选框：当场生效的常驻规则，不随 `添加 N 个` 提交。
- **规则只管以后的**，拨开不批量添加现有的，所以不确认。
- **同名在添加时就地解决**（⑩）：同名行勾选时就地展开两个选择 `替换现有的`（现有的进废纸篓，可撤销）/ `跳过`，默认不勾；能在源头消掉的冲突不留到待处理。
- **来源自己不能当目标**：添加 MCP 时，来源位置对应的那个位置键禁用（`title`「这就是来源」）。
- **整个文件夹是链接＝环内一支向右的箭头**（环＝这个 agent 的 skills 目录，箭头＝整个指到了别处；箭头穿出环外会读成 ♂，不用）。
- 一个目标都没勾时 `添加 N 个` 禁用（`title` 说原因），不另写「至少选一个」。
- 没有 `取消`（`←` 或 Esc 回）；没有绝对路径；右上不重复写「N 个与已有同名」——行尾的 `同名` 标签已经说了。
- 列表行没有分隔线（两页一致）；左栏宽 268（skill）/ 300（MCP，位置名长）。
- 位置名全应用一个写法：`Claude Code · User`，不带 `MCPs` 后缀。

### 设置页

二级页面。**复选框列表，不是选择片**：第一版 5 个实心黑胶囊是全产品最重的视觉质量，承载的却是最不重要的设置；41 个 agent 也本来就适合列表。

`哪些 agent 出现在列表里`（区域标签，agent 小写正文体）下面三列排开，一行 = 12px 复选框 + 16px 图标 + 名字（`body`），行高 36；默认只列已安装的 9 个，下面 `显示未安装的 32 个`（文字链）。勾选当场生效；「取消勾选只是不在列表里显示，已建好的链接原样留着」不常驻——**取消勾选那一刻在该行旁出现**（12 `ink-mute`，4 秒后淡出）。再往下 48px：`关于`——`版本 0.1.0`（`mono`）+ `检查更新`（文字链）。不展示路径。

### 托盘面板

与模型页同一行的缩小版：`24px 图标 + Codex + 开关`，没有状态句。`needsCodexRestart` 时开关后 12 出紧凑键 `重启生效`，确认在面板里当场展开。菜单三项 `打开 Sophia` `设置` `退出`，悬停 `surface` 底。

## Do's and Don'ts

### Do

- 一次操作只汇总成一句提示条
- 禁用的按钮同时给 `title` 说原因
- 需要用户拿主意的事进待处理栏，各带自己的动作
- 数字带单位
- 用反色表示"现在开着"（选择片）；布尔状态用开关
- 图标按钮带 `title`

### Don't

- 不涂红。破坏性靠信息承担分量
- 不在按钮上写宾语（`重启 Codex` → `重启`）
- 不给词表之外的动作发明图标
- 不在列头放灯。看不懂的记号比没有记号更糟
- 不把选择操作条退化成两个总按钮，「针对某个 agent」这一维不能丢
- 不显示绝对路径，除非用户正要据此做判断
- 不写「操作失败」「请重试」「没有需要建立的链接」
- 不给「拉取模型」「改选模型」单独的按钮——保存即拉取，整块区域可点
- 不给浮层配「保存」「关闭」——点了就生效，点外面就关
- 不让命中区跟着视觉尺寸缩——12px 的记号，24px 的目标
- 不说「同步」（MCP 页）——它只新增、从不覆盖也不删除
- 不在文案里说「矩阵」「导入」「引入」「harness」
