## 拆分

全部重构拆成三份可独立交付的 spec，共用同一套组件规范：

| | 范围 | 状态 |
|---|---|---|
| **本份** | Skill 主视图、导入页、待处理页、设置页 | 本次 |
| 第二份 | MCP 页 | 待写 |
| 第三份 | 模型页 | 待写 |

第一份先做，因为组件规范的大部分条款要在它身上首次落地；后两份只是把同一套语言套到别的内容上。

**后两份已知的输入**（画稿阶段发现，写 spec 时直接用）：

- **模型页的 `重启` 后端没有命令。** `api.ts` 现有 `gateway_state / save_provider / fetch_models / select_models / enable / restore / takeover`，没有重启。用户点名要这个按钮，实现时需新增——按文案「重启 Codex 才生效」，指的是重启 Codex 进程而非 launchd 路由。
- **`codex_models/settings.rs` 的 `protocol`（chat/responses）与 `port` 现在 UI 完全没暴露。** 画稿把它们作为只读事实放进配置页。要不要做成可改是待决问题，默认假设：只读。
- **MCP 的格状态比 skill 多**（`连接一致` / `同一服务（端点一致）` / `缺失` / `差异，不会覆盖` / `配置无效` / `格式不支持`），需要一张对应 §8 的映射表。其中 `差异，不会覆盖` 与 skill 的「同名被占」形似而神不同——它是配置内容不同、用户可能想合并，归属需单独判断。

## 需求

### R1 一个 skill 在一个 agent 下能不能用，格子一眼看得出

矩阵的格只有三种形：实心（能用，是软链）、空心（不能用）、外环（能用，本体就在这儿）。后端的七种 `CellState` 归并到这三种。

### R2 点了没成，说清楚是什么挡住了

四种异常态（链接失效、指向别处、同名被占、整目录链到别处）画成同一个空心圆，但**点击行为与文案必须分叉**。现有实现对这四种统一弹「没有需要建立的链接」，这句话对它们全是错的。

### R3 「拆开整目录链接」要有入口

新表头取消了「整目录链接」徽标与「拆成逐项链接」按钮。这个能力必须改挂到待处理栏，否则永久触达不到。

### R4 需要拿主意的事集中到待处理栏

三类问题（同名本体、链接失效、目录不可写）进待处理栏，各带自己的动作。忽略记的是**这一条具体状况**，涉及的位置变化后重新提示。

### R5 做完了什么，用一句话说清，可撤销

提示条四种形态，一次操作只汇总成一句，不排队。可逆操作给撤销。应用级故障走独立的错误横幅，不自动消失。

### R6 设置改成二级页面，只回答一个问题

设置从弹层改成占满整窗的二级页面。内容是 agent 选择片网格，**不展示路径**，默认只列已安装的。关掉一个 agent 只是不在矩阵里显示，不删已有链接。

### R7 导入改成二级页面

导入从弹层改成二级页面。原来挤在 720px 里的三栏铺开，skill 列表不再截断。

### R8 自动同步行只读一行，顶多关掉

不展开。建规则在导入页那个勾，排除/恢复在矩阵点圆点，关掉在这一行右侧——都是已有能力，不新增入口。

**连带修一处不一致**：矩阵里点圆点关闭会写排除，但再点开不解除排除，结果是链接建着却仍被标记排除，下一轮自动同步不再维护它。

### R9 删本体：新增能力，带硬性安全约束

删除本体目录突破了此前「只建删软链、绝不碰真实目录」的边界。必须：删到废纸篓、git 仓库内的不代删、删完把指向它的链接改指留下的那个、确认弹窗给出做决定所需的全部信息。

### R10 空态与忙碌态各有话说

五种空态各自说明现状与下一步。busy 期间五个控件豁免不置灰。

### R11 排序保留，但表头看起来是读的

默认无箭头，hover 出淡箭头，激活转黑。

### R12 视觉与文案规范落地

零色彩、三个字族、圆角白名单、术语统一 agent、文案说结果不说机制、计数口径一致、agent 图标单色。

## 设计

### 状态映射放在哪

`CellState` 是后端事实，**不改**。归并发生在前端：新增一个映射函数，输入 `CellState` + `Target`，输出 `{ dot: "own" | "linked" | "missing", onClick, reason }`。放在 `src/cellState.ts`（新文件），因为它同时被矩阵、待处理栏、提示条三处用到，不能塞在组件里。

**关键点**：现有 `link()` 用 `acts.length === 0` 判断"没什么可做"，这是错的——它把四种不同原因塌成一句话。改成**先查格状态再决定文案**，动作数组只用来执行。

### `Unwritable` 改名

`CellState::Unwritable` 的含义是「目标整目录链到别的本体位置」（`models.rs:198`、`skills.rs:331`），不是「目录只读」。改名 `WholeLinked`。「目录只读」是待处理栏新增的一类问题，现有代码没有检测，本次新增 `ReadOnly`。

这是 core 的破坏性改名，涉及 `models.rs` / `skills.rs` / `src/types.ts`，不涉及落盘数据（`CellState` 不进 `settings.json`）。

### 删本体的实现路径

core 新增 `sync::trash(path) -> Result<()>`，用 `trash` crate（跨平台废纸篓）。**不用 `fs::remove_dir_all`**。

前置检查在 core 里做，返回一个 `DeleteSourcePlan`：完整路径、条目数与总字节、受影响的链接列表、是否在 git 仓库内（向上找 `.git`）。UI 拿它渲染确认弹窗。git 仓库内时 `plan.in_git = true`，UI 禁用主按钮。

删完的链接改指：复用现有 `create_link`，对每条受影响的链接先 `remove_link` 再 `create_link` 指向留下的本体。

### 二级页面的路由

现在 `App.tsx` 用 `activeTab` 切三个 tab。新增一层 `subPage: null | "settings" | "import" | "pending"`。非空时渲染二级页面、不渲染侧栏。Esc 与 `←` 都置回 null。不引路由库。

### 忽略的持久化

待处理栏的「忽略」要跨重启生效，且**记的是具体状况不是 skill**。`Settings` 新增 `ignored: Vec<IgnoredIssue>`，`IgnoredIssue { kind, key, at }`，`key` 由涉及的路径拼成——路径变了 key 就变了，自然重新提示。这是 `settings.json` 的**新增字段**，serde 默认值保证旧文件能读。

### 不做的

- 不改扫描逻辑，`skills::scan` 产出的事实不变。
- 不引路由库、不引组件库、不引 CSS-in-JS。
- 不做移动本体。

## 风险

1. **`trash` 在 Tauri 打包后的行为仍未验证**。本机 `cargo test` 里可用已确认，但打包成 .app、带上沙箱与签名之后能否调用系统废纸篓，只能在 `make build` 产物上验证。AC14 的真实验证必须在打包产物上做，不能只在 `make dev` 里做。
2. **三个字族都没有中文字形**（组件规范 §1.2.1）。界面绝大部分文字是中文，会落到系统苹方。后果：`text-transform: uppercase` 对中文完全无效，中西文混排一行里字重会略有差异。**实现时第一件事是把真实文案放进真实字体里看一眼**——画稿用的是英文 agent 名和少量中文，比例与真实界面不同。
3. **`Unwritable` 改名是破坏性的**，涉及 core、Tauri 层、前端三处。好在不落盘，一次改干净即可。
4. **删本体是不可逆操作**（即便进废纸篓）。AC14–AC16 的真实验证必须在真机上做，代理验证全绿不足以放行。

## 待决问题

- **41 个 agent 的图标**目前只有 4 个有形状参照。默认假设：其余用首字母方块，实现时按需去取官方 SVG。
- **`ReadOnly` 的检测时机**。默认假设：扫描时不检测（避免每次扫描都试写），在实际写失败时才产生这条待处理项。
