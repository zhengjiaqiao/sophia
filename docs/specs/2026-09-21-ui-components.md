# 界面组件规范

设计稿（画布 `SymSync 界面重构`）是视觉参照，**本文件是实现依据**。两者不一致时以本文件为准；改动组件先改这里，再同步画布。

视觉源自 `docs/DESIGN-spacex.md` 的 **shop 面**（`canvas-light` 那一组）。marketing 面那套（纯黑、全幅照片、80px 大写标题、一个 band 一个 CTA）对工具界面不成立，不采用。

## 1. Token

### 1.1 色

| 用途 | 值 | 来源 |
|---|---|---|
| 画布 | `#ffffff` | `colors.canvas-light` |
| 次级面（选中、悬停） | `#f0f0fa` | `colors.canvas-cool` |
| 分隔线 | `#e0e0e8` | `colors.hairline-on-light` |
| 主文字 | `#000000` | `colors.ink` |
| 次要文字 | `#5a5a5f` | `colors.ink-mute` |
| 弱文字与空心描边 | `#9a9aa2` | **偏离**：空心圆与未勾选框要比分隔线重、比正文轻，规范里没有这一档 |
| 待办 | `oklch(0.62 0.15 70)` | **偏离**：规范规定色彩全部来自照片，工具里没有照片 |
| 失败 | `oklch(0.55 0.19 25)` | 同上 |

**后两色只出现在提示条与待处理栏，表格本身没有颜色。**

### 1.2 字

六档，相邻至少差一档才读得出层级。Barlow Condensed 替 D-DIN（比规范建议的 Inter 更接近 DIN 的工业感），Barlow 作 UI 正文，等宽只给路径与计数。

| 档 | 字族 / 字号 / 字重 / 字距 | 用途 |
|---|---|---|
| 标题 | Condensed 20 / 700 / 1.9px / 大写 | wordmark |
| 列头 · agent 名 | Condensed 14 / 600 / 1.1px / 大写 | 顶栏 tab、列头 |
| 按钮 | Condensed 15 / 700 / 1.17px / 大写 | 所有按钮 |
| 正文 | Barlow 15 / 400 | 表格、说明 |
| 次要 | Barlow 13 / 400 | 副行、徽标 |
| 区域标签 | Condensed 12 / 0.96px / 大写 | **只给区域用**；按钮和链接不用它，否则大写小字从点题变成底噪 |
| 等宽 | IBM Plex Mono 12 | 路径、计数 |

**偏离**：规范写「No mono」。路径要对齐、要分得清 `l` 与 `1`，保留等宽。

### 1.3 间距与形状

- 基准 8px，子单位 4 / 12 / 16 / 18 / 24（`DESIGN-spacex.md` §Layout）。
- 圆角：输入框 `4px`、按钮 `32px`（pill）、其余 `0`。
- **零阴影、零渐变**（规范 §Elevation：不用 drop shadow / blur / glow / gradient）。

## 2. 状态点 `StateDot`

**格回答两件事：填充＝这个 agent 能不能用它，外环＝它在这儿是本体还是一条软链。**

| 状态 | 形 | 含义与点击行为 |
|---|---|---|
| `linked` 已开启 · 软链 | 9px 实心 `#000` | 这个 agent 下是一条指向本体的软链。点一下关闭，只删链接，不动本体 |
| `missing` 未开启 | 9px 空心 `1px #9a9aa2` | 点一下开启，在这个 agent 下建一条软链；目录不存在就顺手建出来，建完提示条说明 |
| `own` 已开启 · 本体 | 13px 外环 `1px #000` + 6px 内实心 | skill 本身住在这个 agent 下，不是链接。关不掉 |

环在哪一列，与「本体位置」列说的是同一件事。

本体环**不提供"挪走"入口**——「移动本体」本期不做。点本体环时提示条说明「本体在这儿，不是链接」。

**只有这三种常驻。** 同名被占、链接失效、目录不可写**不进格**——点下去做不成时由提示条说原因，需要拿主意的进待处理栏。这是与旧实现最大的差别：旧实现有 7 种格状态。

选中行反色时三种形的取值：实心与外环转 `#ffffff`，空心描边转 `#6a6a72`。

## 3. 按钮

**只有一种：ghost pill。** 规范里没有填充按钮（§Do：ghost outlined pill 是唯一 CTA）。

| 变体 | 边框 / 文字 | 用途 |
|---|---|---|
| 默认 | `1px #000` / `#000` | 所有常规动作 |
| 禁用 | `1px #c8c8d0` / `#9a9aa2` | 不可用；**必须同时给 `title` 说明原因**，不可只置灰 |
| 破坏性 | `1px oklch(0.55 0.19 25)` / 同色 | 确认删除类。**用红描边，不用红填充** |
| 文字链 | 无边框 / `#5a5a5f` + 下划线 | 取消选择、关闭这类次级动作 |

两种尺寸，按所在容器的高度选，不按重要性选：

| 尺寸 | 内边距 / 字号 | 用在哪 |
|---|---|---|
| 常规 | `7px 20px` / 15px | 弹窗、空态、独立成行的动作 |
| 紧凑 | `4px 14px` / 12px | 挤在一行里的内联动作（待处理栏、自动同步行、提示条） |

### 3.1 pill 是可点的记号

**圆角 32px 的 pill 只给可点的东西。** 不可点的标识——agent 名标签、状态徽标、分组标记——一律**零圆角方标签**：`1px solid #000` + Condensed 12/600/0.96px/大写。

这条是形状在承担语义：界面里唯一的圆角就是"这里可以按"，所以圆角不能出现在按不动的东西上。

### 3.2 行的展开态

可展开的行（自动同步行、待处理条目）展开时外框从 `1px #e0e0e8` 转 `1px #000`，箭头翻转。借的是选择操作条的黑线逻辑：**黑线＝此刻正在操作它**。

## 4. 反馈：两处会说话

**提示条说「刚做完什么」，待处理栏说「还要你拿主意」。** 二者职责不重叠：能自动完成的事进提示条，需要人做决定的进待处理栏。

### 4.1 提示条 `Toast`

右下角浮层，`position: fixed; right:16px; bottom:16px`，宽上限 480px。**不排队——一次操作只汇总成一句**，新的替换旧的。

| 形态 | 内容 | 停留 |
|---|---|---|
| 成功 | 一句话总结 + 副行等宽统计（`新建了 1 个目录 · 1 条链接`）+ `撤销` | 6 秒 |
| 成功·多项 | 汇总成一句（`在 3 个 agent 下开启了 obsidian-cli`），不逐条罗列 | 6 秒 |
| 做不成 | 说原因，不说失败：`Codex 下已经有同名的 defuddle，没有覆盖它` / `Cline 的 skills 目录只读` | 8 秒 |
| 部分失败 | `开启了 2 个，1 个没成——Cline 的目录只读` + `查看`（跳待处理栏） | 8 秒 |

`撤销` 只在该操作可逆时出现：建链、删链、删本体（废纸篓）可逆；清除失效链接不可逆，不给撤销。

### 4.2 错误横幅 `ErrorBanner`

**与提示条的区别：提示条是某次操作的结果，横幅是应用级故障**（扫描失败、配置读不出、后台进程掉了）。顶栏之下通栏，`1px` 红描边、白底，左侧错误原文、右侧 `关闭`。不自动消失。

### 4.3 待处理栏 / 待处理页

主视图底部常驻一条（待处理页的快捷版：一次一条，处理完跳下一条），完整列表在「待处理」页。

三类问题各自带动作：同名本体（`删 X 的` / `删 Y 的` / `忽略`）、链接失效（`清除` / `忽略`）、目录不可写（`再试一次` / `忽略`）。

**「忽略」的语义（必须按此实现）**：记的是**这一条具体状况**，不是记这个 skill。涉及的位置发生变化后会重新提示一次。「已忽略」页是同一张列表，右侧动作换成 `恢复提示`，副行写忽略时间。

## 5. 确认弹窗 `Confirm`

**只有会造成不可逆或难以察觉后果的操作需要确认，且只确认一道**——不做"确认了再确认"。

| 操作 | 是否确认 | 弹窗必须给出 |
|---|---|---|
| 开启 / 关闭链接 | 否 | —（可逆，提示条里给撤销） |
| 删本体 | 是 | 见 §10 第 2 条 |
| 清除失效链接 | 否 | —（删掉零损失，待处理栏已列出条数与路径；不给撤销，重建一条指向不存在路径的链接没有意义） |
| 开启自动同步 | 是 | 会立刻建多少条链接、涉及哪些 agent |

结构：标题（Condensed 15/700）、说明正文（Barlow 15）、条件性警告段（有才出现）、右下 `取消`（文字链）+ 主动作（ghost pill，破坏性用红描边）。背景点击与 Esc 等同取消。

**一条正确性要求**：关闭链接时若该 skill 在自动同步规则覆盖范围内，必须**先写入排除、再执行删除**，否则下一轮扫描会立刻把链接补回来。这一点即使不弹确认也要做，且要在提示条里说明「已不再自动同步」。

## 6. 空态与忙碌态

| 场景 | 表现 |
|---|---|
| 首次扫描中 | 表格区居中一行次要文字 `扫描中…`，不用 spinner |
| 这个域没有 agent 目录 | 居中说明 + `导入 skill` 按钮 |
| 筛选无结果 | 居中 `没有匹配的 skill` + `清除筛选` 文字链 |
| 一个 skill 都没有 | 居中说明本体位置在哪、怎么加 |
| 操作进行中（busy） | 受影响控件置灰；**不受 busy 约束的**：设置、筛选输入框、取消选择、提示条关闭、表头排序 |

## 7. 表头与排序

表头**看起来是读的**：默认无箭头、无按钮态。hover 时右侧浮出淡箭头，激活后箭头转黑。可排序的列：skill 名、本体位置、每个 agent 列（按状态）。

排序状态是视图局部的，重扫后重置——这是现状行为，保留。

## 8. 状态映射：7 种 `CellState` → 3 个圆点

**这是实现最容易出错的一节。** 圆点只有三种形，但后端 `CellState` 有七种；归并后**形相同、点击行为必须分叉**。现有代码对这四种异常态点击会弹「没有需要建立的链接」，这句话对它们全是错的。

| `CellState` | 圆点 | 点击做什么 | 提示条文案 |
|---|---|---|---|
| `Own` | 本体环 | 什么都不做 | `本体就在这儿，不是链接` |
| `Linked` | 实心 | 删这条链接（自动同步覆盖时先写排除） | `关掉了 <skill> 在 <agent> 下的链接` |
| `Missing` | 空心 | 建链接；目录不存在先建目录 | `在 <agent> 下开启了 <skill>` |
| `Broken` 链接失效 | 空心 | **不建链接**——路径已被一条断链占着。进待处理栏 | `<agent> 下这条链接指向一个不存在的地方，先清掉它` + `去清除` |
| `Foreign` 链接指向别处 | 空心 | **不建链接**——同名链接已指向另一个本体。进待处理栏 | `<agent> 下同名的 <skill> 指向 <另一个本体>，没有覆盖它` |
| `Duplicate` 同名被占 | 空心 | **不建链接**——那里有真实文件/目录 | `<agent> 下已经有同名的 <skill>，没有覆盖它` |
| `Unwritable` 整目录链接 | 空心 | **不建链接**——这个 agent 的目录整个链到了别的本体。进待处理栏 | `<agent> 的 skills 目录整个链到了 <本体>，要逐条开关得先拆开` + `拆开` |

**四条共同约束**：

1. 后四种**不是**"未开启"，只是画得一样。`propose_links` 对它们返回空动作数组，前端**必须先判状态再决定文案**，不能凭动作数组为空就说「没有需要建立的链接」。
2. 后四种都**进待处理栏**（`Duplicate` 除外——它是用户自己放的文件，只在点击时说一次）。
3. **`Unwritable` 是命名陷阱**：它的含义是「目标整目录链接到别的本体位置」（`models.rs:198`、`skills.rs:331`），**不是**「目录只读」。待处理栏新增的「目录不可写」是另一回事，现有代码没有检测。实现时把 `Unwritable` 改名 `WholeLinked`，「只读」另起 `ReadOnly`。
4. **`拆开` 是 `split_whole_link` 唯一的入口。** 旧表头的「整目录链接」徽标和「拆成逐项链接」按钮在新设计里都没了，如果这里不给入口，这个能力就永久没法触达。

**无格态**（该 target 在这一行没有 cell，例如本体属于另一个域）：画一条 8px 的 `#e0e0e8` 短横，不可点，`title` 说明「这个 agent 不在当前域」。

## 9. agent 灯（列头）

列头 agent 名左侧一个 6px 圆点。**它说的是目录，不是 skill**——skill 的情况整列的圆点已经说完了，灯再说一遍就是噪音。

| 灯 | 含义 |
|---|---|
| 实心 `#000` | 这个 agent 的 skill 目录存在且可写 |
| 空心 `1px #9a9aa2` | 目录还不存在——开启任一 skill 时会顺手建出来 |
| 实心 `oklch(0.55 0.19 25)` | 目录存在但写不进去（只读、或整目录链到别处） |

## 10. 破坏性操作的通用规则

删除本体目录是这次重构**新增**的能力，突破了旧实现「只建删软链、绝不碰本体目录」的边界。因此：

1. **只确认一道。** 开关链接是可逆的轻操作，不加确认；删除类确认一次，不做"确认了再确认"。
2. 确认弹窗必须给出做决定所需的信息，而不只是问「确定吗」：完整路径、目录内容摘要、**有多少条链接会因此失效**、是否在 git 仓库内。
3. **删到系统废纸篓**，不彻底删除。
4. **git 里的不代删**——检出到仓库内的本体，提示用户自己处理。
5. 删完把原本指向它的链接**改指向留下的那个本体**。
6. 提示条里仍可撤销。

## 11. 计数口径

界面上出现数字的地方必须口径一致，否则用户会把两个都不信。

| 出现处 | 数 的是什么 |
|---|---|
| 侧栏域名右侧 | 该域**有格可点的 skill 行数**（含异常态，不含无格态） |
| 筛选片「全部 N」 | 当前域的 skill 行数，与上一条同源 |
| 列头 agent 名下 | 该 agent 下**实心＋本体环**的格数，即「这个 agent 现在能用几个」 |
| 引入弹层标题 | **本体总数**（不是未导入数）。两个数不能共用一个位置 |
| 自动同步行的计数 | 该规则**下一轮会新建的链接条数**，不含已存在的 |

**自动同步行的那个数必须带单位，写成 `2 条待建`，不能写成裸的 `+2`。** 原稿的 `+2` 紧跟在 `Claude Code · Codex` 后面，会被读成「还有 2 个 agent 没列出」；带上单位歧义就消失了。同理，agent 列表在这一行**完整列出、不截断**——全app只有四个 agent，那一行大片留白，没有截断的理由。

**`…还有 N 个` 是滚动提示，不是截断**——列表完整渲染，这行只是告诉用户下面还有。所以它不改变上面任何一条的口径。

## 12. 不是设置项（别加回来）

实现时容易"补全"出来、但**故意不做**的：

- **链接方式（相对 / 绝对）不可调**。`skills.rs:379` `link_style` 按「本体是否在目标项目内」自动判：项目内用相对路径（随 git 走），项目外用绝对路径。这是正确性判断，不是口味问题，暴露给用户只会让人选错。
- `Settings` 结构体当前只有 `disabled_harnesses / manual_sources / auto_links / mcp_auto_imports / codex_gateway`（`store.rs:11`）。**设置弹层里只有 harness 启用开关一项**，其余入口在各自的上下文里（来源在导入弹层、自动同步在主视图那一行）。

## 13. 已决（2026-09-21）

- 排序**保留**，改为表头 hover 才出箭头（§7）。
- **「移动本体」本期不做**。
- 确认只剩两处：**删本体**（真会丢内容）与**开启自动同步**（一次批量建几十条，规模用户看不见）。**清除失效链接不确认**——删掉零损失，待处理栏已把条数和路径摆在眼前。
- 所有确认**只有一道**，不做"确认了再确认"。
- 侧栏**去掉「全部」域**，默认进「全局」。连带：跨域一键清失效链接的能力消失，筛选片降为单域一组。
- **「删本体」本期做**（用户：冲突时提示用户，用户决定是否删除，也可以忽略不再提示）。这突破了旧实现「只建删软链、绝不碰本体目录」的边界，因此 §10 的六条安全规则是硬约束，`sync.rs` 需要新增删除路径。
- `Unwritable` 改名 `WholeLinked`；「目录只读」是另一种状态，需新增检测（§8 约束 3）。
- `split_whole_link` 的入口移到待处理栏的 `拆开`（§8 约束 4）。
