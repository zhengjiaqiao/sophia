# 界面组件规范

设计稿（画布 `SymSync 界面重构`）是视觉参照，**本文件是实现依据**。两者不一致时以本文件为准；改动组件先改这里，再同步画布。

视觉源自 `docs/DESIGN-spacex.md` 的 **shop 面**（`canvas-light` 那一组）。marketing 面那套（纯黑、全幅照片、80px 大写标题、一个 band 一个 CTA）对工具界面不成立，不采用。

## 1. Token

### 1.1 色

| 用途 | 值 | 来源 |
|---|---|---|
| 画布 | `#ffffff` | `colors.canvas-light` |
| 次级面（选中、悬停） | `#f0f0fa` | `colors.canvas-cool` |
| 分隔线 | `#e0e0e8` | `colors.hairline-on-light` |
| 主文字 | `#000000` | `colors.ink` |
| 次要文字 | `#5a5a5f` | `colors.ink-mute` |
| 弱文字与空心描边 | `#9a9aa2` | **偏离**：空心圆与未勾选框要比分隔线重、比正文轻，规范里没有这一档 |
| 禁用 | `#c8c8d0` | **偏离**：禁用描边要比分隔线略重、又明显轻于正文 |

**整个界面零色彩。** `DESIGN-spacex.md` §Color 规定色彩全部来自照片，工具里没有照片，所以一个色都不用——这也正是设计稿的事实：Main / Pending / Import 三张稿里没有任何非灰色值。

强调只有三种手段，按强度递增：**次要文字 → 加粗 → 反色**（黑底白字）。红色不是其中之一。

**破坏性操作靠信息和文案承担分量，不靠颜色。** 删除弹窗给出完整路径、目录大小、受影响的链接数、git 状态（§10 第 2 条），按钮写 `删到废纸篓` 而不是 `确定`——用户读完就知道会发生什么，再涂红就是吓唬人。

### 1.2 字

六档，相邻至少差一档才读得出层级。Barlow Condensed 替 D-DIN（比规范建议的 Inter 更接近 DIN 的工业感），Barlow 作 UI 正文，等宽只给路径与计数。

| 档 | 字族 / 字号 / 字重 / 字距 | 用途 |
|---|---|---|
| 标题 | Condensed 20 / 700 / 1.9px / 大写 | wordmark |
| 列头 · agent 名 | Condensed 14 / 600 / 1.1px / 大写 | 顶栏 tab、列头 |
| 按钮 | Condensed 15 / 700 / 1.17px / 大写 | 所有按钮 |
| 正文 | Barlow 15 / 400 | 表格、说明 |
| 次要 | Barlow 13 / 400 | 副行、徽标 |
| 区域标签 | Condensed 12 / 0.96px / 大写 | 区域标签**与堆叠列头**（§9.1）；**按钮和链接不用它**，否则大写小字从点题变成底噪 |
| 等宽 | IBM Plex Mono 12 | **只给路径与计数** |

**skill 名用正文档（Barlow 15），不用等宽。** 等宽的理由是路径要对齐、要分得清 `l` 与 `1`；skill 名在列表里是当词读的，等宽反而更难读，而且会和旁边同行的标签字号打架。设计稿（Main / Import）一直是这么画的。目录名出现在**路径里**时随路径走等宽。

**大写是结构的语言，不大写是内容的语言。** 大写只给**我们自己写的结构词**：区域标签、列头、按钮。被谈论的对象一律不大写——agent 名出现在选择片、行标题、句子里时都写 `Claude Code`，不写 `CLAUDE CODE`。唯一的例外是**矩阵列头**：那里 agent 名承担的是列标签的职能，随列头走大写。

**文件系统来的名字一律原样、等宽，不做大小写转换。** skill 名、路径、目录名是标识符，`defuddle` 转成 `DEFUDDLE` 后跟表格里的名字对不上，用户得在脑子里做一次翻译。所以弹窗标题里嵌了 skill 名时，整个标题不加 `text-transform`，名字本身用等宽。大写只给**我们自己写的词**：区域标签、列头、按钮。

**偏离**：规范写「No mono」。路径要对齐、要分得清 `l` 与 `1`，保留等宽。

### 1.2.1 这三个字族都没有中文字形

界面绝大部分文字是中文，会落到系统 CJK 字体。所以上表的字族选择**只对西文生效**——skill 名、路径、数字、agent 名。三条推论，实现时必须知道：

1. **`text-transform: uppercase` 对中文完全无效。**「自动同步」「本体位置」不会有任何变化。它只在 `SKILL` `CLAUDE CODE` 这类西文标签上起作用。
2. **`letter-spacing` 对中文有效**，但那是字间距不是字母间距。区域标签的 0.96px 用在中文上读起来是「疏排」，这是想要的效果，保留。
3. **字重要靠字族提供。** 中文落到苹方后，`font-weight: 600` 取的是苹方的中黑，与 Barlow Condensed 的 600 不是同一个视觉重量。中西文混排的一行里两边粗细会略有差异，这是可接受的代价，不要为此改成 700。

字体栈写全，CJK 回退显式指定：

```css
--font-ui:   Barlow, "PingFang SC", "Microsoft YaHei", sans-serif;
--font-cond: "Barlow Condensed", "PingFang SC", "Microsoft YaHei", sans-serif;
--font-mono: "IBM Plex Mono", ui-monospace, "PingFang SC", monospace;
```

**字体文件打进应用，不走 CDN。** 桌面应用不该联网取字体。用 `@fontsource/*`，**只引用到的 latin 子集与字重**（Barlow 400、Barlow Condensed 600/700、IBM Plex Mono 400），不要整包引入——整包含全部字重与西里尔/越南语等子集，各约 1.5MB。

### 1.3 间距与形状

- 基准 8px，子单位 4 / 12 / 16 / 18 / 24（`DESIGN-spacex.md` §Layout）。
- 圆角：输入框 `4px`、按钮 `32px`（pill）、其余 `0`。
- **零阴影、零渐变**（规范 §Elevation：不用 drop shadow / blur / glow / gradient）。

## 2. 状态点 `StateDot`

**格回答两件事：填充＝这个 agent 能不能用它，外环＝它在这儿是本体还是一条软链。**

| 状态 | 形 | 含义与点击行为 |
|---|---|---|
| `linked` 已开启 · 软链 | 9px 实心 `#000` | 这个 agent 下是一条指向本体的软链。点一下关闭，只删链接，不动本体 |
| `missing` 未开启 | 9px 空心 `1px #9a9aa2` | 点一下开启，在这个 agent 下建一条软链；目录不存在就顺手建出来，建完提示条说明 |
| `own` 已开启 · 本体 | 13px 外环 `1px #000` + 6px 内实心 | skill 本身住在这个 agent 下，不是链接。关不掉 |

环在哪一列，与「本体位置」列说的是同一件事。

本体环**不提供"挪走"入口**——「移动本体」本期不做。点本体环时提示条说明「本体在这儿，不是链接」。

**只有这三种常驻。** 同名被占、链接失效、目录不可写**不进格**——点下去做不成时由提示条说原因，需要拿主意的进待处理栏。这是与旧实现最大的差别：旧实现有 7 种格状态。

选中行反色时三种形的取值：实心与外环转 `#ffffff`，空心描边转 `#6a6a72`。

## 3. 按钮

**只有一种：ghost pill。** 规范里没有填充按钮（§Do：ghost outlined pill 是唯一 CTA）。

| 变体 | 边框 / 文字 | 用途 |
|---|---|---|
| 默认 | `1px #000` / `#000` | 所有常规动作 |
| 禁用 | `1px #c8c8d0` / `#9a9aa2` | 不可用；**必须同时给 `title` 说明原因**，不可只置灰 |
| 破坏性 | 同默认（`1px #000`） | 确认删除类。**不用红**——分量由弹窗里的信息和按钮文案承担，见 §1.1 |
| 文字链 | 无边框 / `#5a5a5f` + 下划线 | 取消选择、关闭这类次级动作 |

两种尺寸，按所在容器的高度选，不按重要性选：

| 尺寸 | 内边距 / 字号 | 用在哪 |
|---|---|---|
| 常规 | `7px 20px` / 15px | 弹窗、空态、独立成行的动作 |
| 紧凑 | `4px 14px` / 12px | 挤在一行里的内联动作（待处理栏、自动同步行、提示条） |

#### 3.0 选择片 `Chip`

多选/单选的紧凑控件，用在 agent 选择、筛选、任何"从一组里挑几个"的地方。**pill 形，因为它可点**（§3.1）。

| 态 | 样式 |
|---|---|
| 未选中 | `1px #e0e0e8` 描边、白底、`#000` 字 |
| 选中 | **反色**：`#000` 底、白字、无描边 |
| 不可选 | `1px #e0e0e8` 描边、`#9a9aa2` 字，`title` 说明原因 |

尺寸 `padding: 6px 14px`，图标 16px 在左、间距 8px。文字用 Barlow 15（**不大写**——agent 名是专名，见 §1.2）。

选中用反色而不是填充色，是因为界面零色彩（§1.1），反色正是强调阶梯的最高档。

### 3.1 pill 是可点的记号

**圆角 32px 的 pill 只给可点的东西。** 不可点的标识——agent 名标签、状态徽标、分组标记——一律**零圆角方标签**：`1px solid #000` + Condensed 12/600/0.96px/大写。

这条是形状在承担语义：界面里唯一的圆角就是"这里可以按"，所以圆角不能出现在按不动的东西上。

### 3.2 行的展开态

可展开的行（自动同步行、待处理条目）展开时外框从 `1px #e0e0e8` 转 `1px #000`，箭头翻转。借的是选择操作条的黑线逻辑：**黑线＝此刻正在操作它**。

## 4. 反馈：什么话在哪儿说

四个地方会说话，**一件事只在一个地方说**：

| 说什么 | 在哪 |
|---|---|
| 刚做完了什么（会消失） | 提示条 §4.1 |
| 应用级故障（不会消失） | 错误横幅 §4.2 |
| 要你拿主意，散在几十行里 | 待处理栏 §4.3 |
| 要你拿主意，就挂在这一行上 | 行内待办条 §4.4 |

### 4.1 提示条 `Toast`

右下角浮层，`position: fixed; right:16px; bottom:16px`，宽上限 480px。**不排队——一次操作只汇总成一句**，新的替换旧的。

| 形态 | 内容 | 停留 |
|---|---|---|
| 成功 | 一句话总结 + 副行等宽统计（`新建了 1 个目录 · 1 条链接`）+ `撤销` | 6 秒 |
| 成功·多项 | 汇总成一句（`在 3 个 agent 下开启了 obsidian-cli`），不逐条罗列 | 6 秒 |
| 做不成 | 说原因，不说失败：`Codex 下已经有同名的 defuddle，没有覆盖它` / `Cline 的 skills 目录只读` | 8 秒 |
| 部分失败 | `开启了 2 个，1 个没成——Cline 的目录只读` + `查看`（跳待处理栏） | 8 秒 |

`撤销` 只在该操作可逆时出现：建链、删链、删本体（废纸篓）可逆；清除失效链接不可逆，不给撤销。

### 4.2 错误横幅 `ErrorBanner`

**与提示条的区别：提示条是某次操作的结果，横幅是应用级故障**（扫描失败、配置读不出、后台进程掉了）。顶栏之下通栏，**反色**（`#000` 底、白字），左侧错误原文、右侧 `关闭`。反色是这套零色彩系统里最强的强调手段，留给应用级故障这种罕见情况。不自动消失。

### 4.3 待处理栏 / 待处理页

主视图底部常驻一条（待处理页的快捷版：一次一条，处理完跳下一条），完整列表在「待处理」页。

三类问题各自带动作：同名本体（`删 X 的` / `删 Y 的` / `忽略`）、链接失效（`清除` / `忽略`）、目录不可写（`再试一次` / `忽略`）。

**「忽略」的语义（必须按此实现）**：记的是**这一条具体状况**，不是记这个 skill。涉及的位置发生变化后会重新提示一次。「已忽略」页是同一张列表，右侧动作换成 `恢复提示`，副行写忽略时间。

### 4.4 行内待办条 `RowNotice`

第四个会说话的地方，挂在**具体某一行**下面：`1px #e0e0e8`、一句话 + 紧凑 pill 动作 + `稍后` 文字链。不自动消失。

**它和待处理栏的边界**：

| | 用哪个 |
|---|---|
| 这件事属于某一行，**处理它的动作就在那一行上** | 行内待办条 |
| 跨行、或需要集中一条条过 | 待处理栏 |

所以模型页的「版本升了要重新生成目录」「可以接过来」用行内条（就两行，动作就在右边），而 skill 矩阵的同名本体、失效链接用待处理栏（几十行里散着，得集中处理）。

**不要两边都放。** 一件事只在一个地方说。

### 4.5 文案：说结果，不说机制

用户改过的两句，是这条原则的标准示例：

| 别写 | 写 |
|---|---|
| 导入＝在选中的 agent 下建软链接 | 让这些 skill 出现在「全局」的列表里 |
| 至少选一个：没有链接，它不会出现在列表里 | 至少选一个：有软链或本体，才会出现在列表里 |

软链是我们的实现手段，不是用户的目的。**只有在用户需要据此做判断时才提软链**——比如删本体的弹窗要说「2 条链接会因此失效」，因为那正是他要权衡的东西。其余时候说他能看见的结果。

同理，提示条说「做不成」时给的是原因而不是错误码，见 §4.1。

## 4.6 页面还是弹层

**弹层只有一种用途：确认一个决定。** 除此之外一律是页面。

| 界面 | 形态 |
|---|---|
| 设置 | **二级页面** |
| 导入 skill | **二级页面** |
| 待处理 / 已忽略 | **二级页面** |
| 删本体、开启自动同步的确认 | 弹层（§5） |

弹层用来装一屏内容的东西，代价是把用户困在一个小框里：导入弹层左中右三栏挤在 720px 内，41 个 agent 的设置挤成一条长列表——挤出来的信息密度低，正是"展示效率很低"的来源。页面有整窗可用。

### 二级页面 `SubPage`

占满整窗，**不保留侧栏**。顶栏换成：左侧 `←`（24px 内联 svg，点击返回）+ 页面名（Condensed 20/700/1.9px/大写，与 wordmark 同档）。其余留白。

返回即保存，**没有"保存"按钮**——设置项改一个生效一个，跟现在的实现一致。Esc 等同返回。

## 5. 确认弹窗 `Confirm`

**只有会造成不可逆或难以察觉后果的操作需要确认，且只确认一道**——不做"确认了再确认"。

| 操作 | 是否确认 | 弹窗必须给出 |
|---|---|---|
| 开启 / 关闭链接 | 否 | —（可逆，提示条里给撤销） |
| 删本体 | 是 | 见 §10 第 2 条 |
| 清除失效链接 | 否 | —（删掉零损失，待处理栏已列出条数与路径；不给撤销，重建一条指向不存在路径的链接没有意义） |
| 开启自动同步 | 是 | 会立刻建多少条链接、涉及哪些 agent |

确认弹窗的背景罩：**白罩 `opacity: .72`**。零色彩系统里没有半透明黑（`rgba()` 也会被 lint 拦下）。罩与弹窗是兄弟节点，不影响弹窗本身。

结构：标题（Condensed 15/700）、说明正文（Barlow 15）、条件性警告段（有才出现）、右下 `取消`（文字链）+ 主动作（ghost pill，**破坏性也不涂红**，见 §1.1）。背景点击与 Esc 等同取消。

**一条正确性要求**：关闭链接时若该 skill 在自动同步规则覆盖范围内，必须**先写入排除、再执行删除**，否则下一轮扫描会立刻把链接补回来。这一点即使不弹确认也要做，且要在提示条里说明「已不再自动同步」。

## 6. 空态与忙碌态

| 场景 | 表现 |
|---|---|
| 首次扫描中 | 表格区居中一行次要文字 `扫描中…`，不用 spinner |
| 这个域没有 agent 目录 | 居中说明 + `导入 skill` 按钮。**agent 列照常显示**，灯全为空心 |
| 筛选无结果 | 居中 `没有匹配的 skill` + `清除筛选` 文字链 |
| 一个 skill 都没有 | 居中说明本体位置在哪、怎么加 + `导入 skill`（pill）+ `打开目录`（文字链） |
| 操作进行中（busy） | 受影响控件 `opacity:0.45`；**不受 busy 约束的**：设置、筛选输入框、取消选择、提示条关闭、表头排序 |

**空态里若有两个动作，只有一个是 pill**，另一个降为文字链。§3 只有一种按钮变体，两个 pill 并排就分不出主次——主次靠"是不是 pill"来分。

**busy 的三条细节**：①豁免控件保持 `opacity:1`，**不加聚焦态**——同一屏里别的东西灰了，它没灰，对比本身就说明了它还能用；②表头整行不置灰（排序是豁免项，只灰列名留黑箭头会很怪），只灰表头里的全选复选框；③busy 期间不禁止排序，因为排序不写磁盘。

## 7. 表头与排序

表头**看起来是读的**：默认无箭头、无按钮态。hover 时右侧浮出淡箭头，激活后箭头转黑。可排序的列：skill 名、本体位置、每个 agent 列（按状态）。

排序状态是视图局部的，重扫后重置——这是现状行为，保留。

## 8. 状态映射：7 种 `CellState` → 3 个圆点

**这是实现最容易出错的一节。** 圆点只有三种形，但后端 `CellState` 有七种；归并后**形相同、点击行为必须分叉**。现有代码对这四种异常态点击会弹「没有需要建立的链接」，这句话对它们全是错的。

| `CellState` | 圆点 | 点击做什么 | 提示条文案 |
|---|---|---|---|
| `Own` | 本体环 | 什么都不做 | `本体就在这儿，不是链接` |
| `Linked` | 实心 | 删这条链接（自动同步覆盖时先写排除） | `关掉了 <skill> 在 <agent> 下的链接` |
| `Missing` | 空心 | 建链接；目录不存在先建目录 | `在 <agent> 下开启了 <skill>` |
| `Broken` 链接失效 | 空心 | **不建链接**——路径已被一条断链占着。进待处理栏 | `<agent> 下这条链接指向一个不存在的地方，先清掉它` + `去清除` |
| `Foreign` 链接指向别处 | 空心 | **不建链接**——同名链接已指向另一个本体。进待处理栏 | `<agent> 下同名的 <skill> 指向 <另一个本体>，没有覆盖它` |
| `ReadOnly` 目录写不进去 | 空心 | **不建链接**。进待处理栏 | `<agent> 的 skills 目录写不进去，<skill> 没能开启` |
| `Duplicate` 同名被占 | 空心 | **不建链接**——那里有真实文件/目录 | `<agent> 下已经有同名的 <skill>，没有覆盖它` |
| `Unwritable` 整目录链接 | 空心 | **不建链接**——这个 agent 的目录整个链到了别的本体。进待处理栏 | `<agent> 的 skills 目录整个链到了 <本体>，要逐条开关得先拆开` + `拆开` |

### 8.1 两条契约要求（从实现里倒推出来的）

**一、`<另一个本体>` 需要 core 带出来。** `Cell` 现在只有 `path`（目标侧路径）和 `state`，没有软链解析后的落点——而 `skills.rs:343` 判 `Foreign` 的那一刻手里正好有 `real_path(path)`，只是丢掉了。`Cell` 加 `points_to: Option<PathBuf>`，`Foreign` 与 `Linked` 两个分支填上。不加的话这句话只能写成含糊的「指向别处」，R2「说清楚是什么挡住了」就没做到。

**二、`reason` 只装「为什么不能点」，不装「点完了什么」。**

上表对可点的两种（`Linked` / `Missing`）给的是**点完之后**的结果句，对其余给的是**为什么不能点**的说明句——同一个字段两种时态，拿去当 `title` 会在 hover 时显示「关掉了…」。

更根本的原因：按 §4.1，一次批量操作**只汇总成一句**。所以「每个格自己的成功文案」从构造上就是错的——三个格开启只该出一句话。

**做法**：`CellView.reason` 只在 `clickable === false` 时有值。成功句由调用方在操作结果处聚合生成，不由格提供。上表里可点两行的文案是**聚合前的语料**，不是 `reason` 的取值。

**四条共同约束**：

1. 后四种**不是**"未开启"，只是画得一样。`propose_links` 对它们返回空动作数组，前端**必须先判状态再决定文案**，不能凭动作数组为空就说「没有需要建立的链接」。
2. 后四种都**进待处理栏**（`Duplicate` 除外——它是用户自己放的文件，只在点击时说一次）。`IssueKind` 需要**四个**成员而不是三个：`DuplicateSource`（`Foreign`）、`BrokenLink`、`ReadOnlyTarget`、**`WholeLinkedTarget`**。前两版把 `WholeLinked` 并进 `ReadOnlyTarget`，但两者的动作完全不同——一个是「拆开」，一个是「再试一次」，待处理页按 `IssueKind` 分动作时会撞车。
3. **`Unwritable` 是命名陷阱**：它的含义是「目标整目录链接到别的本体位置」（`models.rs:198`、`skills.rs:331`），**不是**「目录只读」。待处理栏新增的「目录不可写」是另一回事，现有代码没有检测。实现时把 `Unwritable` 改名 `WholeLinked`，「只读」另起 `ReadOnly`。
4. **`拆开` 是 `split_whole_link` 唯一的入口。** 旧表头的「整目录链接」徽标和「拆成逐项链接」按钮在新设计里都没了，如果这里不给入口，这个能力就永久没法触达。

**目录不存在的 agent 照样成列。** 这是 `docs/specs/2026-09-20-create-missing-target-dirs.md` 已定的事：列在、灯空心、格可点，点下去顺手把目录建出来。不要因为"没目录"就把列藏起来——藏起来用户就没有入口把它建出来了。

**无格态**（该 target 在这一行没有 cell，例如本体属于另一个域）：画一条 8px 的 `#e0e0e8` 短横，不可点，`title` 说明「这个 agent 不在当前域」。

## 9. agent 灯（列头）

列头 agent 名左侧一个 6px 圆点。**它说的是目录，不是 skill**——skill 的情况整列的圆点已经说完了，灯再说一遍就是噪音。

| 灯 | 含义 |
|---|---|
| 实心 `#000` | 这个 agent 的 skill 目录存在且可写 |
| 空心 `1px #9a9aa2` | 目录还不存在——开启任一 skill 时会顺手建出来 |
| 空心加一道斜杠 `#9a9aa2` | 目录存在但写不进去（只读、或整目录链到别处）。取空心那一档的色 |

## 9.1 agent 图标 `AgentMark`

**一律单色 inline SVG**，`currentColor` 取色：常态 `#000`，未启用 / 禁用 `#9a9aa2`。**不用品牌色**——用了零色彩（§1.1）就破了。

**实现时用各项目官方的 SVG，转成单色路径，不要手画。** 设计稿里只画了 4 个（`claude-code` `codex` `cursor` `gemini-cli`）作形状参照，其余 37 个是首字母方块占位——凭记忆描品牌标志画不准，也没必要：官方 SVG 都是公开的，取路径改 `fill` 即可。开发时缺哪个就去取哪个，取不到就保持首字母方块。

**首字母方块不是图标的平替，是它缺席时的占位。** 已安装的 9 个里首字母就撞了 3 个 C（Claude Code / Codex / Cursor）和 2 个 G（Gemini CLI / GitHub Copilot），所以方块**永远和名字一起出现**，不单独用。

`data/harnesses.json` 有 41 个 agent，其中大多数没有能在 16px 上认出来的标志。**不给认不出的硬凑图标**——降级成**首字母方块**：14px 零圆角 `1px #e0e0e8` 方框 + 一个大写字母（Condensed 12/600）。

| 位置 | 形态 |
|---|---|
| 列头 | 16px 图标在上、名字 Condensed 12/600/0.96px/大写在下，**堆叠**。列宽约 84px：`CLAUDE CODE` 在 Condensed 14 下约 85px 放不进去，12 下约 73px 刚好，这是尺寸倒逼的取值 |
| 设置弹层 | 16px 图标 + 名字，横排。41 行长列表，图标是扫读的抓手 |
| 导入弹层的 agent 选择 | 同设置弹层 |
| 自动同步行、提示条、确认弹窗 | **不放**。那里 agent 名是句子的一部分，塞图标会打断阅读 |

列头堆叠后，agent 灯（§9）放在图标右上角，6px。

## 10. 破坏性操作的通用规则

删除本体目录是这次重构**新增**的能力，突破了旧实现「只建删软链、绝不碰本体目录」的边界。因此：

1. **只确认一道。** 开关链接是可逆的轻操作，不加确认；删除类确认一次，不做"确认了再确认"。
2. 确认弹窗必须给出做决定所需的信息，而不只是问「确定吗」：完整路径、目录内容摘要、**有多少条链接会因此失效**、是否在 git 仓库内。
3. **删到系统废纸篓**，不彻底删除。
4. **git 里的不代删**——检出到仓库内的本体，提示用户自己处理。
5. 删完把原本指向它的链接**改指向留下的那个本体**。
6. 提示条里仍可撤销。

## 11. 计数口径

界面上出现数字的地方必须口径一致，否则用户会把两个都不信。

| 出现处 | 数 的是什么 |
|---|---|
| 侧栏域名右侧 | 该域**有格可点的 skill 行数**（含异常态，不含无格态） |
| 筛选片「全部 N」 | 当前域的 skill 行数，与上一条同源 |
| 列头 agent 名下 | 该 agent 下**实心＋本体环**的格数，即「这个 agent 现在能用几个」 |
| 引入弹层标题 | **本体总数**（不是未导入数）。两个数不能共用一个位置 |
| 自动同步行的计数 | 该规则**下一轮会新建的链接条数**，不含已存在的 |

**自动同步行的那个数必须带单位，写成 `2 条待建`，不能写成裸的 `+2`。** 原稿的 `+2` 紧跟在 `Claude Code · Codex` 后面，会被读成「还有 2 个 agent 没列出」；带上单位歧义就消失了。同理，agent 列表在这一行**完整列出、不截断**——全app只有四个 agent，那一行大片留白，没有截断的理由。

**`…还有 N 个` 是滚动提示，不是截断**——列表完整渲染，这行只是告诉用户下面还有。所以它不改变上面任何一条的口径。

## 12. 自动同步行：只读一行，顶多关掉

**这一行不展开。** 它反映的就是导入弹层里那个勾建出来的规则，现有实现（`DomainView.tsx:201`）已经是对的形态：一条规则一行文字 + 一个关掉的动作。新设计只换皮，不加东西。

| 这件事 | 在哪做 | 现有 API |
|---|---|---|
| 建规则 / 改目标 | **导入弹层**里「这个来源以后新增的 skill，自动在以下 agent 中开启」那个勾 | `set_auto_link` |
| 关掉本域的规则 | 自动同步行右侧 | `remove_auto_link_targets` |
| 排除某个 skill | **矩阵里点圆点关闭** | `exclude_auto_link` |
| 恢复某个 skill | **矩阵里点圆点开启** | `include_auto_link` |

**不要做**：展开面板、编辑规则、排除项列表与逐条恢复、「现在就同步」、「+ 添加规则」。这些要么已经有别的入口，要么是凭空加的功能。

行的内容：`自动同步　通用仓库 → Claude Code · Codex　2 条待建`，排除数非零时追加 `（排除 2）`，右侧 `关掉`。agent 列表完整列出不截断（§11）。

**一处必须修的不一致**：`include_auto_link` 目前只在导入弹层里被调用（`ImportDialog.tsx:203`），矩阵里点圆点关闭会写排除（`SkillsTab.tsx:264`），但**再点开不解除排除**——结果是链接建着、却仍被标记排除，下一轮自动同步不再维护它。上表第四行要成立，点开时必须调 `include_auto_link`。


## 13. 术语：对用户只说 agent

**界面文案里不出现「harness」**，一律叫 **agent**。用户认的是 Claude Code、Codex、Cline 这些具体的东西，"harness" 是我们内部的分类词。

代码标识符维持现状（`Harness` 结构体、`data/harnesses.json`、`Settings.disabled_harnesses`）：`disabled_harnesses` 是 `settings.json` 里已落盘的键，改名要带迁移，而用户一个字也看不见。**改名只发生在文案层。**

### 13.1 设置页的 agent 选择

**用选择片（§3.0）铺成网格，不是一行一个复选框。** 图标 16px + 名字，点一下切换。参照 cc-switch 的「主页面显示」那一排。

**不展示路径。** 用户要做的判断只有一个——这个 agent 出不出现在矩阵里——却要读复选框、名字、绝对路径三样东西。路径是我们的实现细节。需要时放 `title`。

**默认只列已安装的。** `discovery::installed()` 在本机实测是 **9 / 41**（claude-code、codex、cursor、gemini-cli、github-copilot、amp、command-code、droid、weiboap）。剩下 32 个没装的收在一行 `显示未安装的 32 个` 后面——列出来只是噪音，但要留入口，因为用户可能想预先开启。

一行放得下 4–5 片，9 片两行完事。对比原方案的 41 行长列表，这是整节的重点。

**设置页里不提"目录会被建出来"。** 那是开启 skill 那一刻的事，写在设置里是提前解释一件用户还没做的事。列头那盏空心灯（§9）已经承担了这个信息，到时候提示条也会说。设置弹层只回答一个问题：**这个 agent 出不出现在矩阵里。**

## 14. 不是设置项（别加回来）

实现时容易"补全"出来、但**故意不做**的：

- **链接方式（相对 / 绝对）不可调**。`skills.rs:379` `link_style` 按「本体是否在目标项目内」自动判：项目内用相对路径（随 git 走），项目外用绝对路径。这是正确性判断，不是口味问题，暴露给用户只会让人选错。
