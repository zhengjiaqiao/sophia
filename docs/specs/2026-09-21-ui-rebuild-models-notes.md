# 模型页的前置材料

这不是 spec，是画稿阶段查证出来的事实，写第三份 spec（模型页）时直接用。

## 1. `重启` 按钮后端没有命令（必须新增）

用户点名要这个按钮。`src/api.ts` 现有的模型网关命令只有：`gateway_state` / `save_provider` / `fetch_models` / `select_models` / `enable` / `restore` / `takeover`。**没有重启。**

按画稿文案「改动要重启 Codex 才生效」，指的是**重启 Codex 进程**，不是重启 launchd 路由。这两件事要在 spec 里分清楚，因为它们的失败模式不同：Codex 是用户的编辑器/CLI，我们未必有权重启它；launchd 路由是我们自己装的服务。

**这条是模型页唯一需要新增后端能力的地方**，其余全部是现有能力换皮。

## 2. 三组状态词是正交的三件事

`enabled`（我们的写入在不在 Codex 配置里）、`router.installed` / `router.running`（launchd 后台路由进程）、`codex.version`——三者互不蕴含。

**不要并排三个徽标。** 画稿的做法是合成一句人话 + 一行等宽事实：

- 副行：`3 个模型已经在 Codex 的模型列表里，改动要重启 Codex 才生效`
- 等宽行：`Codex 0.43.0 · 路由 127.0.0.1:8765 运行中`

版本号与端口是计数类事实，走等宽（组件规范 §1.2）。

## 3. 两条提示的归属

| 现有东西 | 归到哪 | 理由 |
|---|---|---|
| `drift`（版本升了要重新生成目录） | **行内待办条**（§4.4） | 不是某次操作的结果，也不是应用级故障；就挂在那一行上，动作就在右边 |
| `takeover`（可以接过来） | 行内待办条 | 同上 |
| `needsCodexRestart` | **并进副行**，右边的 `重启` 就是它的动作 | 单起一条通知是重复 |
| `routerUnavailable`（已启用但路由没跑） | **错误横幅**（§4.2） | 官方模型也会受影响，是应用级故障；§4.2 举的例子正是「后台进程掉了」 |

## 4. 两处形的选择及理由

**开关用 ghost pill 两态**，不用滑动开关也不用复选框：

- 未启用＝默认 ghost pill `启用`；已启用＝反色 pill `已启用`（点一下停用＝恢复）
- 它是会写盘的动作按钮（`gateway_enable` / `gateway_restore`），不是「从一组里挑几个」，所以不借 §3.0 选择片
- 文字是我们自己写的词，走按钮档（Condensed 大写）；选择片规定 Barlow 不大写（专名）
- 滑动开关是 iOS 语言且必然带圆角，规范里没有这个形

**模型列表的「已选」用 12px 方形复选框**，不用圆点：

- §2 圆点的两个维度（填充＝能不能用、外环＝本体还是软链）在模型列表里都不成立，用圆点会让人以为能点出三态
- 由此界面得到一个干净的二分：**圆＝状态（只读事实），方＝选择（我选的）**
- 它和右侧的反色模型片是同一件事的两个视图（勾上 → 上面多一个片）

## 5. 现有能力的落位（已逐条核对 `ModelsTab.tsx` + `api.ts`）

全部有入口：网关地址/密钥/保存/拉取模型（配置二级页）、筛选 query（浮层搜索框）、勾选（浮层复选框）、改显示名（已选行右侧 `改名` → 就地变输入框）、保存选择 + 已选计数（浮层底部）、启用/恢复（行上开关）、`disabledReason`（禁用 pill + `title`）、接管（行上 `接管`）、drift 重新生成、两个空态、限制说明全文、端口与协议（配置页只读）、`canRestore` 的边界态（未启用但服务还装着 → 配置页 `后台服务还装着` + `彻底撤下`）。

## 6. 待决

- **`protocol`（chat/responses）与 `port` 现在 UI 完全没暴露**（`codex_models/settings.rs`）。画稿把它们作为只读事实放进配置页。要不要做成可改是产品决定，**默认假设：只读**。
- **限制说明那段长文**（`使用第三方模型时，Codex 仍会用官方模型生成会话标题…`）画稿放在页面左下常驻。它是事实不是某次操作的结果，所以不随操作消失——这个判断需要确认。
