# 菜单栏入口：关窗不退出，一键开关模型注入

> 依据：`docs/DESIGN.md`。参照对象是 ollama 的菜单栏面板。仅 macOS（模型注入本身只支持 macOS）。

## 问题

模型注入是个开关：额度用完想关，要测试想开，切换很频繁。现在拨它得先找到窗口、切到「模型」页。
而且关窗就是退出，应用没有常驻的入口。

## 需求

- **R1** 菜单栏常驻一个图标。左键弹出面板，右键给原生菜单兜底（打开、退出）。
- **R2** 面板里一行 Codex：图标、名字、一句现状、一个开关。开关是 ghost pill 两态，反色＝已启用。不用滑动开关（DESIGN「Don't」）。
- **R3** 开关按不动时必须说原因（`title`），并给一条去「模型」页的路。
- **R4** 「重启 Codex」只在有改动等着生效时出现（启用或停用之后、Codex 还开着旧配置），重启完自己消失——平时摆着是噪音，还多一个误触的机会。它会中断进行中的对话，确认一道（DESIGN「确认」三处之一），确认就在那一行上完成，不另弹窗。
- **R5** 面板里的动作做不成时，不在面板里解释：把主窗口带到前面、切到「模型」页，由那里说原因。面板放不下一段话，一件事只在一个地方说。
- **R6** 关主窗口＝藏起来，不退出。第一次关时说一次「还在菜单栏里」。点 Dock 图标把窗口带回来。
- **R7** 「退出」真的退出应用。路由是系统后台服务，不受影响——注入状态不因退出而变。
- **R8** 面板每次弹出都重读状态；面板改了状态，主窗口的「模型」页跟着刷新。

## 设计

- 面板是应用自己的一个无边框小窗（标签 `tray`），和主窗口同一份前端产物，按窗口标签分流到 `TrayPanel`。系统原生菜单套不上设计规范，所以不用它做主入口。
- 面板零圆角、1px `ink` 描边、无阴影；失焦即收起。位置取菜单栏图标正下方、水平居中，超出屏幕右缘时往回收。
- 文案复用 `modelsView.ts` 的 `statusSentence` / `enableDisabledReason` / `factsLine`，面板与模型页说同一句话。
- 窗口的显示、隐藏、退出走自己的命令（`tray_open_main` / `tray_hide` / `tray_quit`），不给面板窗口开放通用的窗口权限。
- 菜单栏图标是单色模板图（系统按深浅色自动着色），零色彩。
- Dock 图标保留：应用主体仍是 Skill / MCP 的管理界面，不是纯后台工具。

## 修订（都来自真机，代理验证全绿时没露出来）

### 2026-09-21 · 「要不要重启 Codex」要比状态，不能比时间

**现象**：没启用，面板里却有「重启 Codex」。
**原来的规则**：`Codex 启动时间 < 最近一次变更时间` 就提示。
**为什么错**：Codex 只在启动时读一次设置，该问的是「它加载到的状态和现在是不是一回事」。真机上 Codex 早就开着，之后启用又停用、中间没重启过——它从没加载过注入的配置，和现状一致，时间规则却判成要重启。
**为什么不能简单地「没启用就藏掉」**：反过来那种必须提示——Codex 已经在用注入的配置，这时停用，路由随之卸载，它连官方模型都连不上。
**现在**：设置里记一份变更记录（何时起、是否开着、目录指纹），比较启动那一刻加载到的状态与当前状态。旧设置没有记录时，只在当前开着才按时间提示。

### 2026-09-21 · 启用「很卡」：慢的不是启用，是顺带的「首次运行新程序」

**现象**：每次点启用都卡几秒。
**实测**：稳定状态 0.4–0.9 秒；程序副本的校验记录失效要重算两遍哈希，2.4 秒；**系统从没见过的新程序文件**，首次运行要过系统的安全校验，超过 5 秒并撞上就绪等待的上限，于是又慢又报失败。开发时反复重建，几乎每次试到的都是新程序，所以感觉「每次都卡」；发布后则是「每次更新后的第一次启用」。
**排除掉的怀疑**：主线程上的同步扫描。对进程采样，`scan_all` 只占约 45 毫秒。
**现在**：应用启动时在后台线程预热——更新程序副本、空跑一次让系统做完首次校验；后台服务正开着且程序变了，就地让它换上新版本。就绪等待的上限 5 → 10 秒（「只是慢」不该被判成「没起来」），轮询间隔 200 → 50 毫秒。同一种最坏情况实测 5.38 秒且失败 → 0.21 秒；稳定状态 0.19 秒。
**已知的、可接受的窗口**：预热时「服务正开着且程序变了就地重启」发生在应用启动的后台线程里，那一刻如果正好有 Codex 请求在走路由，这一个请求会断（重启本身是几百毫秒的事）。它只在应用更新后的第一次启动出现一次；Codex 对断掉的请求会自己重试。不为此给路由加活跃连接计数——不值当。**这不是 bug，别修。** 反过来不重启的代价更大：更新后的应用和旧版路由并存，直到用户下一次点启用。
**界面**：忙的时候现状句改说正在做什么（`正在启用…`）。只把按钮变淡不说话，那段时间看起来就是卡住了。
