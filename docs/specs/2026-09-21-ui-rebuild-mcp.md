# 界面重构 · MCP 页

**输入**：`docs/intent/2026-09-21-ui-rebuild.md`、`docs/specs/2026-09-21-ui-rebuild-mcp-notes.md`（画稿阶段查证的事实）
**组件规范**：`docs/specs/2026-09-21-ui-components.md`（**实现以它为准**）
**设计稿**：画布「SymSync 界面重构」的 `Mcp.dc.html`
**前置**：第一份（Skill 管理）已完成，组件库、二级页面、待处理栏都已就位，这一份只是把同一套语言套到 MCP 上。

## 核心判断

**MCP 页和 Skill 页是同一个界面，只是内容不同。** 都是「一批东西 × 一批位置」的矩阵，都有自动规则行，都有引入流程。用户换个 tab 不该重新学一套。

所以骨架直接复用，本份的全部工作是**把 MCP 特有的四处差异正确地映射进这套语言**。

## 需求

### R1 状态映射：六种 `McpCellState` → 三个圆点

语义平移，不是照搬：**环＝本行的「来源位置」就是这一列**；**实心＝这儿也有一份、连的是同一个服务**；**空心＝这儿还没有**。

| `McpCellState` | 圆点 | 点击 | 提示条 |
|---|---|---|---|
| `Own` 来源配置 | 环 | 什么都不做 | `这份 <服务> 就写在 <位置> 里，写到别处去的就是它` |
| `Equal` 连接一致 | 实心 | 什么都不做 | `<位置> 里这份 <服务> 和来源那份连的是同一个服务` |
| `SameEndpoint` 端点一致 | 实心 | 什么都不做 | `两边连的是同一个地址；认证头要到运行时才生成，没法逐字比对` |
| `Missing` 缺失 | 空心 | 把来源那份原样写进去；文件不存在就顺手建，**写前先备份** | `把 <服务> 写进了 <位置>` + 副行 `新建 1 个文件 · 1 处新增` |
| `Invalid` 配置无效 | 空心 + 列头灯加斜杠 | **不写**：整份文件读不出来，整列都写不进。进待处理栏 | `<位置> 的配置这次读不出来，什么都没往里写` + `去看看` |
| `Unsupported` 格式不支持 | 空心，整行不可选 | **不写** | `<服务> 用了只有 <来源> 认得的写法，搬到别处就不是原来那个了` |
| 无格 | 8px 短横 | 不可点 | 不出提示条，`title` 说「这个位置不在当前域」 |

### R2 `Conflict` 不进格，做成行级标记

`scan()` 遍历全部位置的全部条目建行（`mcp.rs:412-430`），某行在列 X 上是 `Conflict` 就说明 **X 自己也持有同名条目、也产出了自己带 `Own` 的一行**。同一个服务名在冲突时会出现两行。

把「两份不一样」画成格状态，就是把行级事实塞进格里，必然自相矛盾。改成：两行各画自己的环，差异做成**行级零圆角方标签「2 份不一样」**（不可点，§3.1），并进待处理栏。

**待处理栏里不给「覆盖 / 合并」**——`mcp.rs:522-540` 的 `prepare` 对目标已有同名条目一律跳过。覆盖是新的破坏性能力，要单独定 spec。

### R3 三个动作说人话，「同步」这个词不出现

- **引入**＝这个域里还没有这个服务，从别处搬一份完整定义过来。二级页面。
- **补齐**＝本域已经有这份定义，只是某些位置还缺——把已有那份复制到缺的位置。点空心格，或勾几行后点选择条上的位置片。
- **同步**＝**界面上不出现**。`previewKind` 初值 `"同步"`（`McpTab.tsx:71`）是残留，`openPreview` 只会传「补齐」「引入」。而且「同步」是双向词，这里只新增、从不覆盖也不删除，用它会骗人。

### R4 引入改成二级页面

与 skill 的导入页对齐：`SubPage`、选择片选位置、列表不截断。`McpImportDialog.tsx` 删除。

### R5 自动引入行只读一行

`自动引入　Claude Code → Codex · Cursor　3 条待写入` + 右侧 `关掉`。计数带单位（§11）。建规则/改目标在引入页那个勾。不展开。

### R6 「刷新」按钮去掉

聚焦、切项目、改设置都会自动重扫（`refreshKey`），再留一个按钮是噪音。

### R7 视觉与文案规范落地

零色彩、token 化、术语 agent、说结果不说机制。`McpTab.tsx` / `McpTab.css` / `McpImportDialog.tsx` 从 lint 豁免名单里划掉。

## 设计

### MCP 页**不该**跟 Skill 页一样的四处

1. **格是单向的。** skill 的格是开关，MCP 只有「写进去」、没有「拿掉」（core 只新增，不删条目）。所以选择条上的位置片不是「灯亮＝全开、点一下关」，而是**「还缺几处、点一下写进去」**——全有的片走不可选态，其余带 `1 处 / 2 处` 计数，另有 `写进全部 3 处`。
2. **实心不是一条链接，是一份独立副本。** 每一处都是别人配置文件里的一段真实内容。§2 的「本体 vs 软链」平移成「来源 vs 另一份一样的」；**§4.1 的撤销不能照抄**——MCP 写入从 UI 上不可逆，改成 `看看备份` + 等宽备份文件名。
3. **差异是行级、不是格级**（R2）。这是 MCP 独有的第四种记号。
4. **列的身份是文件，不是 agent。** 同一个 agent 在一个域里可能有多个 MCP 位置（Claude Code · Local / Project），项目域里会出现同图标两列。列头按 §9.1 堆叠图标 + 名字，但**名字是位置名**。

### `matrixHidden` 与「文件不存在也成列」不冲突（已查证）

两条规则回答的是不同的问题，**保留现状，不改 core**：

| | 规则 | 理由 |
|---|---|---|
| Skill | 目录不存在**也成列** | 一个 agent 一个目录，藏了列用户就没有别的地方能把目录建出来 |
| MCP | 空的 / 不存在的第二位置**藏起来** | Claude Code 在一个项目里有两个位置（`.claude.json` 的 Local、`.mcp.json` 的 Project）。藏掉空的那个是为了不把用户压根没打算用的位置在每一行上都报成缺失；而它**仍然是「引入」的显式目标**，入口没丢 |

**统一后的规则**：列的存废看「用户还有没有别的入口」，不看「文件存不存在」。这条写进组件规范 §8。

### 其余功能的落位

| 现有东西 | 归到哪 | 理由 |
|---|---|---|
| `overview.issues` 扫描问题 | **列头灯加斜杠 + 待处理栏**，不是错误横幅 | 位置级的（某个文件读不出），横幅只留给应用级故障 |
| `report` 写入结果 | 提示条，汇总一句 + 等宽副行（处数、备份文件名） | |
| `preview.issues` 跳过的项目 | 留在确认弹窗内 | 是做决定所需的信息 |
| 传输 / 来源位置 | 矩阵两列，紧跟服务名；`不支持` 那行整行不可选 | |

### 确认的口径

- **同域单格写入：不确认**，提示条给备份名。
- **批量与跨域：确认**。跨域那道就是现有 `allowCrossDomain`。

## 风险

1. **`Conflict` 变成行级标记后，两行会同时带标记。** 用户看到两行各写「2 份不一样」可能误以为是四份。文案要说清是同一对，例如标签 `title` 写「和 <另一个位置> 的那份不一样」。
2. **备份文件会累积。** 每次写入都备份，没有清理机制。现状如此，本期不改，但要在提示条里让用户知道备份在哪。

## 待决问题

- **`Unsupported` 的整行不可选是否太狠**。默认假设：是，因为搬过去就不是原来那个了，给用户点的机会等于给他犯错的机会。
- **备份的清理**。默认假设：本期不做。
