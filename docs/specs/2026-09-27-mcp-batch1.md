# MCP 第一批：Gemini CLI、GitHub Copilot CLI、Claude Desktop — Spec

依据：`docs/intent/2026-09-27-mcp-more-agents.md`（「已定」一节）；配置事实：`docs/research/2026-09-27-mcp-config-compatibility-batch1.md`（官方核实）与 `docs/research/2026-09-11-mcp-config-compatibility.md`（现有三家与无损原则）。

## 需求

- **R1 三家成列。** MCP 页新增 `GEMINI CLI`、`COPILOT CLI`、`CLAUDE DESKTOP` 三种列；装了、并被选进「MCP 的列」的才显示。
- **R2 位置。**

  | agent | 用户级 | 项目级 |
  |---|---|---|
  | Gemini CLI | `$GEMINI_CLI_HOME/.gemini/settings.json`，未设置时 `~/.gemini/settings.json` | `<项目>/.gemini/settings.json` |
  | GitHub Copilot CLI | `$COPILOT_HOME/mcp-config.json`，未设置时 `~/.copilot/mcp-config.json` | `<项目>/.github/mcp.json` |
  | Claude Desktop | macOS `~/Library/Application Support/Claude/claude_desktop_config.json`；Windows `%APPDATA%\Claude\claude_desktop_config.json`；Linux 不支持 | 没有 |

  - 三个文件的根都是 `mcpServers`，一律按严格 JSON 读写（官方没有声明支持注释）。
  - Gemini 的 `settings.json` 里还有大量与 MCP 无关的设置；写入只动 `mcpServers.<名字>` 那一段，其余逐字节不变。
- **R3 读与写的字段映射。** 以现有的「连接字段」（stdio：`command`、`args`、`env`；远程：地址、`headers`）为公共部分：

  | | stdio | Streamable HTTP | SSE |
  |---|---|---|---|
  | Gemini CLI | `command` `args` `env`（没有 `type` 字段） | `httpUrl` `headers` | `url` `headers` |
  | Copilot CLI | `type: "local"` 或 `"stdio"`，`command` `args` `env` | `type: "http"`，`url` `headers` | `type: "sse"`，`url` `headers` |
  | Claude Desktop | `command` `args` `env` | 不支持 | 不支持 |

  - 写进 Gemini 时，Streamable HTTP 一律写 `httpUrl`、SSE 写 `url`，不能反过来（写成 `url` 会被 Gemini 当成 SSE）。
  - 写进 Copilot 时，stdio 写 `type: "local"`，并带上 `tools`（全部工具，写法以官方示例为准，见「待核实」）；读 Copilot 时，`tools` 缺省或为全部工具，视为与别家「没有这个字段」相同。
- **R4 写不过去的，拒绝并说原因（无损原则）。** 格子画 ⊘，按下当即说明：
  - 远程服务器写进 Claude Desktop：`Claude Desktop 的远程服务器要在它自己的「连接器」里添加`。
  - 带有目标家不认识的专属字段：Gemini 的 `trust`、`includeTools` / `excludeTools`、`oauth`、`cwd`、`timeout`、`description`；Copilot 的 `tools` 不是全部工具时。说明写 `带有 Gemini 专属的设置（trust），Copilot 里没有对应的写法`。
  - 值里有环境变量引用（`${VAR}`、`$VAR`）且目标家的展开规则不同：写进 Claude Desktop 一律拒绝（它不展开变量）；其余沿用现有规则，不改写变量语法。
  - 同一家之间复制（例如 Gemini 用户级 → Gemini 项目级）保留全部字段，不受上面限制。
- **R5 Claude Desktop 只在 MCP 页。** 它作为「只有 MCP」的 agent 登记：SKILLS 页、设置里的「SKILLS 的列」都不出现它。项目行上它那一格是空的、不能点。
- **R6 Copilot 与 Claude Code 共用 `.mcp.json`。** Copilot CLI 在项目里也会读 `<项目>/.mcp.json`（Claude Code 的项目级文件）。本版 Copilot 的项目级格子只反映 `.github/mcp.json`；Copilot 列头在项目位置的提示框补一句：`Copilot 也会读这个项目的 .mcp.json（Claude Code 那一份）`。项目级服务器要在 Copilot 里确认过信任这个文件夹才会加载，写进 `.github/mcp.json` 后的提示条说一句 `在 Copilot 里信任这个文件夹后生效`。
- **R7 两页的列分开选。**
  - 设置里原来的 `列表里的 agent · 最多 4 个` 分成两组：`SKILLS 的列 · 最多 4 个`、`MCP 的列 · 最多 4 个`。MCP 那组只列支持 MCP 的 agent（本版 6 家：Claude Code、Codex、Cursor、Gemini CLI、Copilot CLI、Claude Desktop）。
  - 每组各自一份「不显示名单」，各自沿用现在的整理规则：新装的在不满 4 个时自动出现；勾满时其余禁用，按下即说明 `最多显示 4 个，先取消一个`。
  - 升级时 MCP 那组的初值：SKILLS 那组里支持 MCP、且现在显示着的，保持显示；不满 4 个时，按已安装补齐（新支持的三家算新装）。所以升级前 MCP 页的三列不变。
  - MCP 页扫哪些 agent 由 MCP 那组决定，SKILLS 页由 SKILLS 那组决定，互不影响。
- **R8 写入之后何时生效。** 提示条沿用现有写法，Claude Desktop 追加 `重启 Claude Desktop 后生效`（它只在启动时读配置，官方文档要求重启）；Gemini、Copilot 追加 `新开会话后生效`。

## 非功能需求

- 写配置只走 `atomicfile`（快照、备份、原子替换、写前写后指纹校验）；三份文件逐字节只动那一项。
- 不读取、不记录任何值里的密钥；诊断与界面只显示字段名与脱敏后的差异类别（沿用现有规则）。
- 不增加网络请求与后台进程。

## 设计

### 1. 位置表（core）

`crates/core/src/mcp.rs` 里按 agent 写死的 `match`（`discover_locations` 与 `SUPPORTED`）换成一张表：每家一条，给出用户级路径模板（含环境变量覆盖）、项目级相对路径（可无）、格式适配器、平台限制。Claude Code 的 Local、`matrixHidden` 等特殊规则保持原样。

### 2. 格式适配（core）

在现有「JSON `mcpServers`」读写（Claude Code、Cursor 共用）的基础上，为三家各加一个字段映射层：把文件里的条目解析成现有的 `Canonical`（连接字段 + 客户端字段），写回时按 R3 生成条目。插入与删除沿用现有的 JSON 文本级改写（只切入、切掉那一个成员）。客户端专属字段进 `Canonical` 的客户端部分，参与「能否无损写过去」的判断（R4）。

### 3. Claude Desktop 登记

`crates/core/data/harnesses.json` 为 Claude Desktop 加一条「只有 MCP」的记录（没有 skill 目录，探测目录为上表的应用配置目录，非 macOS / Windows 不登记）。SKILLS 侧所有取 agent 表的地方跳过它。图标：Claude 的标志，列头名 `CLAUDE DESKTOP`。

### 4. 设置与整理规则

`Settings` 增加 MCP 那组的不显示名单（例如 `mcp_disabled_harnesses`）与它的 `known_installed`；`discovery::reconcile_shown` 抽成对「一组名单」的函数，两组各调一次。旧设置文件没有新字段：按 R7 的升级规则算初值后写回。

### 5. 前端

- 设置页两组勾选，文案与现有一组相同，只换区块小标。
- MCP 页的列头、格子、提示框沿用现有组件；新增的原因文案按 R4、R6、R8。

## 待核实（实现前）

- Copilot CLI 的 `tools` 写法：字符串 `"*"` 还是数组 `["*"]`；手写 JSON 省略它是否被接受。以官方示例为准，并在测试 HOME 里用真实 Copilot CLI 验证一次。
- Copilot CLI 的 `command` / `args` / `env` 里是否展开 `${VAR}`（官方只在 `headers` 示例里出现）。
- Gemini 的 `mcpServers.*.env` 是否支持 `${VAR:-default}`（官方只在通用插值一节写了）。

## 风险

- Gemini 的扩展（extension）也能提供 MCP，与 `settings.json` 同名时按它的规则合并。本版只读写 `settings.json`，扩展提供的服务器不显示；列头提示框不承诺「这就是 Gemini 能用的全部」。
- Copilot 同时读 `.mcp.json`：一个服务器可能在 Copilot 里实际可用，但 Copilot 的格子显示 ○（R6 已在提示框说明）。以后若改成反映「实际可用」，要一并处理两个文件的优先级。
