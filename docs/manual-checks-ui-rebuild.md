# 真机走查 · 界面重构（Skill 管理）

对应 `docs/specs/2026-09-21-ui-rebuild-skill.md` 的 21 条 AC。**AC20 / AC21 已由 `make lint` 自动覆盖**，这里是剩下必须人工走的 19 条。

**开始前**：如果已有 `make dev` 窗口开着，先关掉重启——vite 会热更前端，但 Rust 侧不会，跑着旧后端的窗口会让设置页拿不到 `installed` 字段。

```
make dev
```

## 一、格与点击（AC1–AC5）

造场景的命令写在每条后面，`$G` 指你的通用仓库（`~/repos/common-skills` 之类），`$C` 指 `~/.claude/skills`。

- [ ] **AC1** 某 skill 在某 agent 下是软链 → 该格是 **9px 实心圆**
- [ ] **AC2** 本体就在某 agent 目录下 → **13px 外环 + 6px 内实心**；点它不发生任何操作，提示条说「本体就在这儿，不是链接」
      用 `ego-browser` 核对（本体在 `~/.local/share/ego`）
- [ ] **AC3** `mkdir -p $C/testdup && echo x > $C/testdup/SKILL.md`，让通用仓库也有同名的 → 点该格，提示条说「Claude Code 下已经有同名的 testdup，没有覆盖它」。**不能出现「没有需要建立的链接」**
- [ ] **AC4** 造断链：`ln -s /nowhere/gone $C/testbroken` → 点该格，提示条说链接指向一个不存在的地方并给「去清除」；同一条出现在底部待处理栏
- [ ] **AC5** 造整目录软链：把某个 agent 的 skills 目录整个换成指向别的本体的软链 → 点该列任一格，待处理栏出现该条且带 **`拆开`**；点「拆开」后该列变成逐项可开关
      这是 `split_whole_link` 在新界面里的**唯一入口**，它不通就等于这个能力没了

## 二、忽略与提示条（AC6–AC8）

- [ ] **AC6** 待处理栏里一条「同名本体」→ 点「忽略」→ **完全退出应用再启动** → 该条不再出现
- [ ] **AC6′** 把其中一个本体 `mv` 到别的路径 → 重扫 → **该条重新出现**（忽略记的是这一条具体状况，不是记这个 skill）
- [ ] **AC7** 勾一个 skill，在 3 个 agent 下批量开启 → **只出现一条**提示条，内容是「在 3 个 agent 下开启了 <skill>」，带撤销；点撤销后三条链接都消失（`ls -la` 核对）
- [ ] **AC8** 把某个 agent 的 skills 目录改成只读（`chmod 500`），再批量开启 → 提示条说「开启了 2 个，1 个没成——<原因>」+ `查看`；点「查看」跳到待处理栏。**记得改回 `chmod 700`**

## 三、设置页（AC9–AC11）

- [ ] **AC9** 打开设置 → 占满整窗、**没有侧栏**、左上有 `←`；agent 以选择片呈现；**页面上没有任何绝对路径**
- [ ] **AC10** 默认只显示已安装的（本机应为 **9 个**：claude-code、codex、cursor、gemini-cli、github-copilot、amp、command-code、droid、weiboap），下方有「显示未安装的 32 个」；点开后另外 32 个出现且字色更轻
- [ ] **AC11** 某 agent 下已有链接 → 在设置里关掉它 → 返回 → 再进设置打开它 → **那些链接始终存在于磁盘上**（前后各 `ls -la` 一次比对，不是看界面）
- [ ] Esc 能从设置页返回

## 四、导入页（AC12）

- [ ] **AC12** 打开导入页，选通用仓库 → **26 个本体全部列出**，没有「…还有 N 个」
- [ ] 选 39 个那个来源 → 自动变三列，仍不截断
- [ ] 一个 agent 都不勾时主按钮禁用，hover 有原因说明
- [ ] 那五句文案逐字在场：`让这些 skill 出现在「全局」的列表里`、`至少选一个：有软链或本体，才会出现在列表里`、`只建链接，不动源文件`、`N 个与已有同名，导入后进待处理`、`这个来源以后新增的 skill，自动在以下 agent 中开启`

## 五、自动同步的往返（AC13）

**这条最容易被漏掉，因为界面上看不出来。**

- [ ] **AC13** 给某来源建一条自动同步规则 → 在矩阵里点圆点**关闭**其中一个 skill → 检查 `~/Library/Application Support/.../settings.json`，该 skill 出现在 `targetExcluded` 里这一格的目标 id 下（只记这个目标，别的位置、别的 agent 下没有）
- [ ] 再点开同一个格 → **`targetExcluded` 里那一条消失了**
- [ ] 触发一次自动同步（切窗口焦点或改动源目录）→ 链接仍在，没有被规则当成"已排除"而不再维护

## 六、删本体（AC14–AC16）—— 不可逆，逐条核对

- [ ] **AC15** 先测拒绝路径：在一个 git 仓库里造一个本体 → 待处理页点「删 X 的」→ **主按钮禁用**，说明为什么不代删、给出仓库根路径
- [ ] **AC14** 造一个不在 git 里的本体 → 确认删除 → 打开**访达的废纸篓**，目录在里面且可恢复。**不是彻底删除**
- [ ] **AC16** 造两个同名本体 + 几条指向其中一个的链接 → 删掉那一个 → `ls -la` 逐条核对：原本指向它的链接**全部改指向留下的那个**，且都不是断链
- [ ] **AC16′** 其中一条链接原本是**相对**的（项目内、随 git 走）→ `readlink` 核对它改指后**仍是相对写法**，没有变成绝对路径
- [ ] 提示条说「已移到废纸篓，可以在访达里恢复」，**没有撤销按钮**（后端没有恢复命令，给了也点不动）

## 七、空态与忙碌态（AC17–AC19）

- [ ] **AC17** 切到一个没有任何 agent 目录的项目 → 居中说明 + `导入 skill` 按钮，且 **agent 列照常显示、灯为空心**（列藏了用户就没入口把目录建出来）
- [ ] **AC18** 在一次长操作进行中，逐个点：**设置、筛选输入框、取消选择、提示条关闭、表头排序**——五者都要能用，且视觉上没被置灰
- [ ] **AC19** 表头未 hover 时无排序箭头；hover 出淡箭头；点一下箭头转黑。hover 时**行不跳**（箭头是占位隐藏，不是 display:none）

## 八、打包产物上才能验的

- [ ] **AC14（打包版）** `make build` 产出 .app，从访达双击启动，重走一遍删本体 → 确认 `trash` 在沙箱与签名之后**仍能调用系统废纸篓**
      这条不能只在 `make dev` 里做：`cargo test` 里能用不代表打包后能用
