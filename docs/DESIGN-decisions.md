## 已裁决的冲突

原则之间、原则与产品负责人意见之间的冲突怎么裁的（原在 `DESIGN.md`「设计原则 › 怎么用这套原则」）。裁决的方法（向上裁决、犹豫时选更克制的）见那一节。

| 冲突 | 裁决 |
|---|---|
| ⑧ 对 ⑥：自创的格内异常记号偏离惯例 | 保留——它帮用户一眼扫完 56×4 个状态；**成立前提**是格子悬停光晕 + 提示框兜底（这两条从改进升为前提） |
| ⑪ 对 ①：单格操作要不要提示条 | **要，出例行一行**（产品负责人真机：加软链、删软链的反馈不足）。格子一闪只在视线正盯着那一格时有效；点完视线已移开、或连点几格时，120ms 闪烁看不到。一行纸窗不抢注意力（①），又给了撤销入口（⑬）。失败提示同样是纸窗，靠句首记号与否定动词分开（2026-09-25） |
| ⑬ 对 ②：删原件要不要确认 | 撤销代替确认 |
| ① 对 ⑪：回应的边界 | 没有意图就没有回应——空闲时界面静止，无呼吸、无循环动画、无吸引注意的晃动，回应只由用户唤起；`prefers-reduced-motion` 下动效退化为即时状态变化，信息不减 |
| ④ 对 ⑮：要不要自动重启 Codex / 做成设置项 | 都不做——重启的是用户正在用的另一个应用，看似空闲也可能有未发草稿与上下文，替用户选中断时机是被产品裹挟（⑮）；做成设置项是回避决策（④）。重启时机归用户，Sophia 把键放在对的地方、如实说出代价 |
| ⑭ 对 ②：「改动待生效」怎么表达 | 不给稍后、不用浮窗、不配读数、不做可关闭提示——按钮即状态，Codex 重启后自动消失 |
| ① ⑤：要不要收件箱 | **不要**（产品负责人：问题已在行上就地显示与处理，收件箱是同一件事的第二处）。曾是「顶栏收件箱 + 待处理页 + 忽略」，删除；换成**就地常显**（2026-09-25 起连「新问题一次性提示」也删了，见上文决策记录）。页签计数、`待处理` 筛选也不做——常驻的数字会一直催处理不了的事 |
| ① ⑯ ③ ⑤ ⑧ ⑰：圆角与阴影（形与层） | **圆角随尺寸（4 / 7 / 12 / 胶囊），投影＝离机面的高度**（产品负责人：全直角 + 黑框的弹窗「不够精致」，对照后「明显圆角的更好看」）。原「零阴影、0 圆角」让浮层只能靠黑框或大块黑与白底分开，要么像表单、要么太重；给浮层一档柔和阴影后，阴影只表示「在上面」，平铺内容仍完全平，同形同义不破。V4 沿用并收紧：机面也不投影，按键的行程用 1px 底边而不是投影。**2026-09-24 物性**把「投影＝在上面」推广为「投影＝离机面的高度」：高度分四档（凹 / 平 / 抬起 / 浮），同义不同量——键、页签滑块、开关滑块抬起一点（柔和短投影，取代 1px 底边），浮层最高；机面、行、片、表格仍然平、不投影（见上文决策记录「物性」） |
| ⑬：删网关连带删钥匙串密钥、本身不可逆 | **二次确认**（产品负责人真机）：曾做成延迟提交 + 撤销，但删后弹一条带 ✓ 的「删掉 X · 撤销」读成删成功了、还把连接摘要往下推；密钥删了找不回，属于不可逆，按 ⑬ 本就该确认；网关一两家、低频，确认一次不费事 |
| ⑬ ③ 对 ⑮：可撤销的删除用黑条撤销还是确认 | **删用户内容一律先确认、不再延迟提交 + 撤销**（2026-09-25 补：删原件、删 MCP 确认之后，例行一行再带 `撤销`——不是延迟提交、不是黑条，删已经做完，`撤销` 是界面上的退路；产品负责人：「因为界面上不可逆」）（产品负责人：删后弹黑色大条「删掉 X · 撤销」突兀，又读成删成功了；既然要打断一次，不如确认）：删网关、只留这份确认。所有成功（含自动规则在背后做的事）用例行一行；失败用带记号栏的纸窗（2026-09-25 起不再有深色提示条）。延迟提交机制随之删除 |
