# 调研：yetone/magpie（2026-09-27）

目的：magpie 与 Sophia 在「一站式管理多个 AI coding agent」上高度重合。摸清它怎么做，定下 Sophia 借什么、不借什么。

依据：克隆 `https://github.com/yetone/magpie`（只读、未运行），读到的提交是 `69b295e`（2026-09-26）。下文 `文件:行` 均指该提交。三条线分别由子代理读码，关键结论由主会话对照源码逐条核对过。

## 一、它是什么

- Go + Wails，MIT，约 4.5 万行，更新极频繁。菜单栏应用，另有窗口、终端界面（`magpie tui`）和命令行，三者共用同一批业务包。
- 定位是「一个地方给每个 agent 挑模型」：本机网关 `127.0.0.1:3425` 同时讲 OpenAI Chat、OpenAI Responses、Anthropic Messages、Gemini 四种接口，互相转换；17 个 agent 可以改模型（README「Agents」表）。
- 另有一个「库」（Library）：skill、MCP 服务器、共享指令，一处维护、同步进各 agent。只管用户级，没有项目的概念。

## 二、skill 与 MCP 的「库」

- **存放**：`~/.config/magpie/library.json` 记条目与分配关系；skill 本体统一放在 `~/.config/magpie/library/skills/<name>`（`internal/library/skills.go:65-67`）。
- **进 agent**：skill 一律软链到库里那份（`skills.go:136-149`），Windows 建不了软链才拷贝并留标记文件。MCP 没有本体文件，库里一份定义，写进各 agent 的配置（文本级改写，`internal/library/mcp.go:488-541`），11 种配置格式各自手写编解码（`mcp.go:98-110,196-404`）。
- **收编（Bring in）**：扫各 agent 的 skill 目录，列出「agent 自己有、库里没有」的（`skills.go:666-709`）。点「收进库」时（`skills.go:711-748`）：
  - agent 目录里的**真实文件夹被整个挪进库目录**，此后各 agent 都改成链到库里那份；
  - 本来就是指向别处的链接，库里建一条链接指向那个别处，不挪文件。
- **同名、不一样的定义**：MCP 同步时，agent 里的定义与库里不一样就**直接覆盖**（`internal/library/sync.go` 中 `syncMCP`，判断见 `mcp.go:89-92`），只在「收进库」之前标一句「在某某 agent 里不一样」。
- **从 GitHub 装 skill、再更新**：支持 `owner/repo`、`github.com/...`（含 `tree/<ref>/<path>`）或本机文件夹。GitHub 走 codeload 压缩包，不走 API，避开每小时 60 次的限流（`skills.go:297-338`），上限 200MB；更新时原地重下、整目录原子替换（`skills.go:542-618`）。
- **粘贴 JSON 添加 MCP**：认 `mcpServers`、`servers`、`context_servers` 等几种写法，也认单个服务器对象；一次贴多个时弹出勾选（`internal/gui/assets/library.js:625-657,785-835`）。
- **市场（Discover）**：
  - MCP：代码里手写的精选清单（`internal/library/market.go:85-122` 起，约 26 条），外加官方 MCP Registry 的搜索接口 `registry.modelcontextprotocol.io/v0/servers?search=`（`market.go:177,289`）。每条带「需要用户填什么」（环境变量、请求头、参数，是否是密钥，`market.go:31-42`）。
  - skill：来自 skills.sh。热门列表是**从它首页的页面数据里抠出来的**（`market.go:699-716`），搜索调它的 `/api/search`（`market.go:718-728`），两者都不是公开文档的接口；随包带一份 200 条的热门快照（`market_skills.json`），网不通时用，热门缓存 6 小时。
- **共享指令**：一份文本写进各 agent 自己的指令文件（`CLAUDE.md`、`AGENTS.md`……），用 `<!-- magpie:begin -->` / `<!-- magpie:end -->` 包住自己写的那段，用户自己写的不动；检测到那段被手改过就停手（`internal/library/instructions.go:19-21,81-138`）。

## 三、模型网关与用量

- **订阅当作模型来源**：已登录的 Claude Code、Codex、Copilot 等直接当模型来源给别的 agent 用。Claude 一路是驱动真实的 `claude` 子进程；另有一条直接发 HTTP 的退路，冒充 Claude Code 的 User-Agent（`internal/provider/claude_cloak.go:79`），复刻 Anthropic 内部的计费签名算法（`claude_cloak.go:214,251`）。只有 Google 一条在 README 里提醒了可能封号。
- **路由分组**：多个 key、多个账号合成一个模型，按额度先到期、顺序、轮换、最少使用分配，失败按原因分级退避，尽量留在同一来源以保住厂商的提示缓存（`internal/gateway/routing.go`、`affinity.go`）。
- **网关令牌**：固定字符串 `"magpie"`，从不校验，只靠绑在回环地址（`internal/gateway/gateway.go:33-34`）。
- **用量是两套独立系统**：
  - 额度：每次现问厂商，得到百分比和重置时间，内存缓存 1 分钟、不落盘。拿法是用各 agent 存在本机的登录凭证，直接调厂商私有接口：Claude `/api/oauth/usage`、Codex `/wham/usage`（`internal/provider/subscription_usage.go:290,352`）。只有第一次才等结果，之后先显示上次的、后台刷新（`subscription_usage.go:64-91`）；超时拿到的半截数据不写缓存（`internal/provider/planquota.go:249-253`）。
  - 调用记录：网关每转发一次，从上游回复自带的用量字段记一行到 `~/.config/magpie/usage.jsonl`（`internal/usage/usage.go:39-40`），只追加、从不清理。价格读时现算，来自 models.dev，查不到标「无价格」。

## 四、配置改写、界面、发布

- **改配置**：JSON、TOML、YAML、.env 各有文本级改写（`internal/edit/`），只改一个键、保留注释与顺序；原子写是临时文件加改名（`internal/edit/file.go:22-58`）。**没有**写前写后的指纹校验，不防与别的程序同时写；TOML 带 BOM 直接拒绝（`internal/edit/toml.go:402-404`）。
- **恢复原值**：替换过的值记在 `stash.json`，切回时写回，但**不检查中途有没有被别人改过**（`internal/agent/stash.go:48-57`）。另记 `applied.json`，事后核对「上次写的还在不在」，被别的工具改掉就提示（`internal/agent/applied.go`）。
- **多语言**：一个字典，键就是英文原文，缺译时退回英文（`internal/gui/assets/i18n.js`）。有暗色模式：CSS 变量，跟随系统，也能手动指定。
- **发布**：签名、公证、发布都在单独的 `yetone/magpie-releases` 仓库，主仓库只负责触发（`.github/workflows/release.yml:1-6`）。自更新强制校验 SHA-256，macOS 还校验新旧版本是同一签名团队（`internal/update/update.go:237-258,483-538`）；用 Homebrew 装的不自己替换自己，改提示用 brew 升级（`update.go:182-184`）。

## 五、对照 Sophia

**它更好的**

- MCP 支持 11 种 agent 格式，Sophia 只有 3 种（`crates/core/src/mcp.rs:26`）；而 Sophia 的 skill 支持 40 种。
- 能发现、安装新的 skill 和 MCP，能从 GitHub 更新；Sophia 只管本机已有的。
- 粘贴 JSON 就能加 MCP；共享指令；暗色模式；多语言；模型网关的广度。

**Sophia 更好的**

- 区分用户级与项目级，项目内用相对软链，随 git 走。
- 按位置的自动同步规则，按目标单独排除。
- 删除要确认、删完能撤销；同名定义不一样时标出来让用户挑，不直接覆盖。
- 写配置只走 `atomicfile`：写前写后指纹校验、拒绝软链父目录、保留 BOM 与 CRLF；恢复只在值没被别人改过时才做（`crates/core/src/codex_models/config.rs:235-291`）。
- 网关校验来源地址与 Host 头（`crates/gateway/src/router/mod.rs:1028-1064`）；密钥在钥匙串；launchd 常驻。
- 额度的取法（规格 `docs/specs/2026-09-26-menubar-usage.md`）让官方 CLI 自己去问，不碰凭证。

## 六、结论

**借**（按对用户的价值 / 工作量排）

1. 发现与安装：skill 市场、MCP 市场、粘贴 GitHub 链接装 skill 并能更新、粘贴 JSON 加 MCP。已立项，见 `docs/intent/2026-09-27-skill-mcp-market.md`。
2. 用量：额度与调用记录分成两套；先显示上次、后台刷新、1 分钟节流、超时不写缓存。落到 `docs/specs/2026-09-26-menubar-usage.md` 的实现里。调用记录要从一开始就有滚动清理。
3. MCP 支持更多 agent：已立项，分三批，见 `docs/intent/2026-09-27-mcp-more-agents.md`。
4. 共享指令；事后核对配置有没有被改掉。后续再立项。
5. 发布：签名放进单独的发布仓库；自更新校验 SHA-256 与签名团队；Homebrew 安装的不自我替换。首次发版前做。
6. 暗色模式、多语言、分配方案快照：看产品需要。

**不借**

- 借用已登录订阅、冒充官方客户端、复刻计费签名：与「防封号」的硬约束冲突。
- 为了让第三方模型像官方模型，内嵌官方系统提示词：同一类风险。
- 令牌不校验、恢复原值不查冲突、原子写不防并发、拒绝 BOM、调用日志不清理：都是它的缺陷。
- 同名不一样就直接覆盖：Sophia 标出来让用户挑。
