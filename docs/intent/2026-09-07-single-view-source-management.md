# Intent: 单视图 + 域内本体源管理

- 状态：已接受（2026-09-07，作者口述）
- 作者：jiaqiao
- 日期：2026-09-07
- 上游：v3 真机使用反馈（PR #4）

## 问题

v3 有"本体位置"和"域"两种视图，同一份同步集从两个轴编辑，规则（合法性、勾选含义、计数范围）反复调整仍然难以理解。域视图一旦具备"引入本体来源"的能力，本体位置视图就没有独立价值，两种视图只是增加复杂度。

## 期望结果

- **只有域视图**：侧栏是全局和各项目（含 WeiboAP 各 agent）。
- 域内表格只显示三类行：本域自有本体位置的全部 skill；本域目标里**已链接**的 skill（只显示被链接的那些，不把同源其他 skill 带进来）；用户在本体源管理里明确引入的 skill。
- **本体源管理**（域内按钮打开弹层）：列出所有已发现的本体位置，可整个引入，也可展开只勾具体 skill；可直接选一个文件夹作为来源。已引入的来源在表格上方以标签显示，可移除（已建链接不动）。
- 行首勾选保留，控制单个 skill 是否参与本域同步；"同步本域"建缺失的链接；坏链表与清理不变。
- 排序、执行结果提示等已有交互保留。

## 约束

- 同步集改为按 (本体位置, 目标) 记录 skill 选择（全部 / 指定名单）；旧 `syncset.json` 直接作废重建。
- 不搬本体、不复制内容；删除仍只有坏链清理和拆分整目录链接。
- Rust core + Tauri；分工不变。

## 不在范围内

- 本体位置维度的汇总视图（以后作为只读报表另议）。
- 内容比对、分叉检测。
