## 目标

MCP 页面沿用 Skills 页的域模型：全局和每个已登记项目分别是一页；默认列表只显示当前域已有的 MCP 服务。用户可以把一个服务从来源位置引入当前域的目标配置，补齐缺失定义，同时保留冲突并避免覆盖。用户也可以为明确的来源位置与目标位置开启自动引入，使后来新增的完整定义在扫描时得到同样的只新增补齐。

## 已确定的行为

- 原范围支持 Claude Code、Codex、Cursor；MCP 传输类型仅支持 stdio 和 http。不支持的传输、字段或引用显示为不可支持/不可安全转换。Claude Code 的文件配置按 User → Local → Project 三个作用域识别：User 为 `~/.claude.json` 的根 `mcpServers`，Local 为同一文件 `projects[绝对项目路径].mcpServers`，Project 为项目根 `<project>/.mcp.json`；作用域优先级为 Local > Project > User。SymSync 扫描这三类文件位置，运行时注入的 `claude.ai` 内置 MCP 不在范围内。新增 WeiboAP 仅支持项目/agent 域，不扩展为第四种全局/项目通用配置。
- 全部页按域分组展示；它不是一个把所有外域服务混入同一张默认列表的同步域。
- 当前域默认按服务名一行。同域同名不因来源配置是否等价而拆行；各 harness 单元格分别保留已有、连接等价、同一服务（端点一致）、配置差异、缺失或明确异常等事实。矩阵主显示将 `own`、`equal`、`sameEndpoint` 统一为 `● 已配置`，具体来源、等价层级和诊断放入 tooltip；`conflict`、`invalid`、`unsupported`、`missing` 仍分别显示各自状态。连接归一只比较连接字段，客户端选项另行保留。
- 外域尚未引入的服务不进入当前域默认行。它们只能在当前域的“引入…”流程中作为来源被选择。
- 当前域引入流程为三栏：来源、未引入服务、当前域目标。已配置来源主显示“已配置（详细原因）”；来源位置可省略显示，但完整路径在 tooltip 中可查。全部页禁用“引入…”，必须先进入单一域。
- Claude Local 对应的 `projects[绝对项目路径].mcpServers` 缺失或为空时，位置保留但标为 `matrixHidden`，从普通矩阵和批量补缺中隐藏；引入弹层仍显示“将写入 Claude Local 配置”，默认不勾选。Local 含有至少一个定义时保持普通矩阵可见。Claude Project 的 `<project>/.mcp.json` 位置始终被发现；仅当 Local 含有定义而该文件尚未创建时，Project 位置标为 `matrixHidden`，从普通矩阵和批量补缺中隐藏，但仍作为“引入…”的显式目标显示“将创建 .mcp.json”，默认不勾选。
- `sameEndpoint`（tooltip 显示“同一服务（端点一致）”）表示 HTTP 的字面 URL 相同，但至少一侧使用 `http_headers_helper` 等动态请求头，因而只能确认端点身份，不能确认请求头等价，也不等于完整连接 `equal`。矩阵主显示仍为 `● 已配置`；它表示目标本地已有配置。目标为真正缺失时，用户可像 Skills 一样直接点击/勾选该单个目标格发起 MCP 预览，仍经过备份、只新增和跨域确认。
- 引入使用既有预览、跨域逐次勾选、备份和只新增执行链路。刷新后，新增到目标的定义作为该域真实来源出现；任意一个本域 `own`/`equal`/`sameEndpoint` 即视为已引入，剩余目标仍可通过本域来源补齐。
- 自动引入规则仿照 Skills 的来源位置开关：绑定来源位置和当前域中用户明确勾选的目标位置，不保存 MCP 定义或凭据，也不因未来新增目标而扩大写入范围。开启前确认会立即尝试补齐当前缺失项，并在之后的扫描中自动补齐该来源新增的完整定义；关闭规则停止后续写入。跨域规则的确认须明确说明当前及未来定义中的凭据可能持续复制到指定目标；该确认只授权这一条来源到这一组目标的规则。更改已开启规则的目标时重新确认。
- 自动扫描每轮只执行一次，发现安全缺失时复用手动引入的 prepare、执行前重验、备份与只新增链路；已配置、端点一致、冲突、无效、不支持或多个不等价来源竞争同一目标的条目不自动写入。自动结果应单独提示；无规则时扫描仍只读。
- 同名不同配置不算已引入，显示差异且不覆盖。来源不同不能默认取第一来源补缺；必须明确选择来源，无法消除歧义时禁用补缺。
- 连接归一与客户端选项分开；已知 Codex enabled 等启用选项不改变连接一致性。对受支持定义只做有界的字面 URL 端点比较：URL 不同仍报告配置差异；URL 相同但请求头表示无法证明等价时报告 `sameEndpoint` 及具体字段诊断，不宣称 `equal`。其他未知字段、非法类型或不可安全转换仍为 unsupported/invalid。
- `own`、`equal`、`sameEndpoint` 的主显示均为“● 已配置”，具体状态在 tooltip 中说明；仅有 unsupported 状态的定义显示“格式不支持”，仅有 invalid 状态的定义显示“配置无效”，冲突显示“差异”。这些状态都不应被误解为未安装或缺失。
- 只有目标没有任何定义时才显示“缺失”；解析失败、非法结构、未知字段或其他异常状态必须显示明确的“配置无效/格式不支持”等未知诊断，不得伪装成缺失。
- connection_eq 不含 client 字段，但 Canonical 完整保留它们；当前支持的客户端设置仅为 enabled、startup_timeout_sec、tool_timeout_sec。同工具 Codex 新增可无损保留这些设置，跨 harness 新增带客户端设置则按字段拒绝。目标已有连接相同也不改任何配置；客户端设置单独保留，不通过当前 DTO 展示。
- 没有逐条导入登记表、删除入口或任意文件安装。MCP 只合并受支持位置中的配置定义。

## 安全边界

无自动规则时扫描只读；用户明确开启自动规则后，扫描可对规则覆盖的安全缺失项执行写入。prepare 只为用户选择或已授权规则中目标缺失的定义生成计划；execute 在执行前重校验来源和目标。普通配置文件写入前生成完整原字节备份，备份失败不写入；写入原子完成，结果带备份路径。WeiboAP 活动 SQLite 使用支持 WAL 的 online backup 生成一致备份并保持权限，不能把 online backup 简化为活动文件的原字节 copy。一次性跨域动作仍须在预览中逐次勾选允许携带凭据；自动跨域动作只可在用户明确确认的精确来源与目标规则内执行。凭据值不进入 DTO、UI、日志、规则或结果。

## 不在范围内

不复制 skill、本体文件、规则或提示词；不做应用关闭后的常驻同步、逐条导入登记、删除、覆盖、冲突替换、字段裁剪或任意文件安装；不扫描或管理 Claude Code 运行时的 `claude.ai` 内置 MCP。

## WeiboAP 项目支持设计

WeiboAP 的 Data/agents 下每个目录就是一个项目；adapter 为每个目录对应的 agent.id 建立独立 project:<normalized> 域。WeiboAP MCP 不是 .mcp.json：目标是共享的本地 SQLite agents.db，但 UI 必须显示项目/agent 身份，按 db 路径、agent id、server name 隔离，不混合多个 agent。

WeiboAP 只在项目/agent 域补齐 agents.mcp_config 缺失字段，事务内不修改 mcps 或其他列。写入后需要用户在 WeiboAP 内启用 MCP，已有会话可能需要重开；文件写入成功不代表客户端运行时已加载。

当某个 agent 的 `mcp_config` 为空时，该项目域仍可进入，但项目矩阵不产生服务行；空状态应说明没有可读取的 MCP 定义。`agents.mcps` 可能只保存启用名称，不能补出传输、端点或认证字段。用户仍可在“引入…”中从其他位置选择完整定义，显式写入该 agent 的 `mcp_config`。本机脱敏只读观察为 4 个 agent 项目均无非空 `mcp_config`、其中 2 个的 `mcps` 非空；真实全局 LevelDB 定义未确认，仍不纳入当前同步范围。

WeiboAP 使用 SQLite online backup 处理 WAL 活动数据库并保持原权限；不能对活动数据库裸 copy 再 rename。写入前重验来源/目标行和 local-mode guard。userData/config.json 中 pgEnabled 必须显式为 false，pgEnabled_* 不能有 true 或非法值；appDataPath 仅接受有效默认值、绝对字符串或唯一精确 exe 匹配数组，无效、相对、歧义或无法定位的 portable 路径拒绝，不猜测。

WeiboAP 全局 MCP 位于 Electron localStorage 的 persist:cherry-studio 根 mcp.servers；本轮不写全局 profile 或 LevelDB，只支持项目/agent。WeiboAP schema 虽含 sse，SymSync 仍只接受 stdio/http，sse 标记为 unsupported。
