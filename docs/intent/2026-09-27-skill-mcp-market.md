# 发现与安装：skill 市场、MCP 市场

调研依据见 `docs/research/2026-09-27-magpie.md`。

## 问题

Sophia 现在只管「本机已经有的」skill 和 MCP：把它们链到或写进各个 agent。用户想要一个新的，得自己想办法先弄到本机。产品负责人：「第一步我们可先把 skill 的 mcp 的管理完善了」。

具体毛病：

- **装不了新的 skill。** 网上看到一个 skill 仓库，要自己 `git clone` 到某个文件夹，再到 Sophia 里把这个文件夹加成来源、再链到各 agent。三步，每一步都要知道 Sophia 的「来源」是什么。
- **装过的 skill 不知道有没有新版本。** 从 GitHub 来的 skill，作者更新了，本机这份不会变，也没有地方提示；要更新只能自己去对应的文件夹 `git pull`（前提是当初是 clone 的）。
- **加不了新的 MCP。** Sophia 只能把一个 agent 里已有的 MCP 定义复制给别的 agent。第一次加一个 MCP，得打开某个 agent 的配置文件手写；MCP 的说明文档给的 JSON 片段，各家外层写法还不一样（`mcpServers`、`servers`、`context_servers`……）。
- **不知道有什么好用的。** 有哪些常用的 MCP、哪些 skill 装的人多，Sophia 里看不到，得去别的网站找。
- **筛选占了三层，概念太多。** 表格上面依次是范围滑槽（`全部 ｜ 用户级 ｜ 项目级`）、项目筛选片、来源胶囊。「范围」「项目」「来源」三个概念、三行控件，才能缩小到想看的那几行。

现在的绕法：在终端里 `git clone`、手改配置文件，或者用别的工具（`npx skills add`、magpie）装好了，再回 Sophia 链接。

## 期望结果

- **一个地方既管已有的，也找新的。** SKILLS 与 MCP 两页的页面头左端都是 `我的 ｜ 发现`：`我的` 就是现在的表格，`发现` 是去找新的。
- **筛选收成一行**（产品负责人给的样子）：`我的` 的表格上方只有一行，左边 `位置` 一排胶囊（`全部`、`用户级`、各项目、`更多 ▾`），右端 `来源：全部 ▾` 下拉。「范围」和「项目」合成「位置」，来源退到下拉里，不懂来源的人可以一直不碰它。
- **发现：看得到常用的，也搜得到。**
  - skill：装的人多的排在前面，可以搜。
  - MCP：精选的常用服务器排在前面，可以搜官方目录。
  - 已经装了的，一眼看得出来；装到哪几个 agent，装的时候就能选。
- **粘一个链接就能装 skill。** 粘贴 GitHub 仓库地址、仓库里某个文件夹的地址都行；如果里面有好几个 skill，列出来勾选要装的。
- **装过的 skill 能更新。** 从 GitHub 装的，作者更新了看得出来，点一下就更新。本机那份被自己改过的，更新前要说清会覆盖什么；更新做错了能撤销。
- **粘一段 JSON 就能加 MCP。** 从说明文档复制的配置片段直接贴进来，常见几种写法都认；一次贴了好几个，就列出来勾选；需要填的密钥、地址，提示填哪一项。
- **装到哪里一目了然，不用先懂「来源」。** 装的时候只选 `用户级` 或某个项目，新装的 skill 落进那个位置的通用仓库（见「已定」）。
- **网不通时不妨碍已有的。** `我的` 照常可用；`发现` 显示上次看到的列表，并说清现在连不上。

## 影响对象

- 所有 Sophia 用户，尤其是刚开始用、本机还没几个 skill 和 MCP 的人。
- SKILLS、MCP 两页的页面头与筛选行（刚按「按对象组织的导航」改过，见 `docs/specs/2026-09-26-object-first-navigation.md` R3、R4、R6，本需求会改掉其中的范围滑槽与项目筛选片）。
- 来源与订阅（`crates/core/src/subscriptions.rs`）、MCP 写入（`crates/core/src/mcp/`）、新增的联网部分。
- 设计规范里讲页面头、来源筛选、添加来源的几节。

## 约束

- **核心库不联网。** 下载、搜索这类联网代码放在 `src-tauri` 或单独的 crate，`crates/core` 保持无异步、无网络（`CLAUDE.md`）。
- **写用户配置只走 `atomicfile`**；删除、覆盖沿用现有规则：先确认、说后果、能撤销（`docs/DESIGN.md`「删除原件」）。
- **只认带 `SKILL.md` 的目录是 skill**，从网上装的也一样。
- **不读、不转存任何 agent 的登录凭证。** MCP 配置里用户填的密钥只写进目标配置文件，不进 Sophia 自己的日志和设置。
- **第三方数据源会变、会挂。** skills.sh 的热门列表和搜索都不是公开文档的接口（magpie 是从网页里抠的）；MCP 官方目录的条目质量参差。任何一个源失败，都只影响 `发现` 里对应那一块，不报错弹窗。
- **下载有上限、看得见去向。** 装之前显示要从哪个地址下载、装到哪里；单个包设大小上限（magpie 用 200MB）。

## 范围外

- MCP 支持更多 agent——已另立需求：`docs/intent/2026-09-27-mcp-more-agents.md`。本需求里装 MCP 时，可选的 agent 就是当时 MCP 页支持的那些。
- 共享指令（一份指令同步进各 agent 的 `CLAUDE.md` / `AGENTS.md`）、分配方案快照、备份与多机同步——调研里记下了，另行立项。
- 私有 GitHub 仓库、需要登录的下载源。
- MCP 从目录更新版本（MCP 大多是远程地址或 `npx` 启动，版本由它自己管）。
- 在 Sophia 里发布、上传、评分、评论 skill。

## 已定

- **新装的 skill 放在通用仓库，位置由用户选**（产品负责人，2026-09-27）：装的时候选 `用户级` 或某个具体项目。`用户级` 放 `~/.agents/skills`，项目放 `<项目>/.agents/skills`，目录不存在就创建，并自动成为这个位置的「通用仓库」来源。选项上悬停显示完整路径。不另建 Sophia 自己的库目录（Q1 的方案 A；「收进通用仓库」的方案 B 以后单独做，不做方案 C）。
  - 依据：`~/.agents/skills` 是 vercel-labs/skills（`npx skills`）的公共目录，产品负责人本机已有它的安装记录 `~/.agents/.skill-lock.json`（18 条，每条记来源仓库、路径、`skillFolderHash`、安装与更新时间）。放在这里，Sophia 与 `npx skills` 装的在同一处；卸掉 Sophia，skill 照样能用。
  - 目录是共用的：装的时候碰到同名的，停下来说清楚，不覆盖。
- **装给哪些 agent，用户直接选**（同上）：默认勾上当前显示的 agent 列（设置里的「SKILLS 的列」「MCP 的列」），并记住上次的选择；MCP 里某家不支持这个服务器的传输方式时不能勾，并说明原因。
- **市场数据参照 magpie**（同上）：
  - MCP：官方 MCP Registry（公开接口）+ 我们维护的精选清单，随版本发布；起点可参考 magpie 的精选条目（MIT，注明出处）。
  - skill：skills.sh（热门与搜索，非公开接口）。热门缓存 6 小时，随包带一份热门快照，连不上时用快照；「粘贴 GitHub 链接」不依赖任何目录站，始终可用。
- **更新要比 magpie 多做一步**（同上）：magpie 只记来源、不记版本，更新是手动整包重下、直接覆盖、不能撤销（`internal/library/skills.go:36-42,540-620`）。Sophia：
  - 装的时候记下 GitHub 上那个文件夹的版本哈希（与 `.skill-lock.json` 的 `skillFolderHash` 同一种），以及本地文件的指纹。
  - 打开 SKILLS 页时，距上次超过 6 小时查一次；另有手动「检查更新」。按仓库合并请求，不开后台常驻进程。
  - 有新版本的行标出来。更新时，本地改过的先确认、说清覆盖哪些；旧的一份先挪进暂存，能撤销。
  - GitHub 未登录每小时 60 次，被限流时说一句稍后再试，不弹错。

## 待决问题

### Q1 `.skill-lock.json` 只读还是也写回

建议第一版只读：用它认出哪些 skill 是从 GitHub 装的、能更新；Sophia 装的另记在自己的设置里。它是 `npx skills` 的内部文件，格式没有公开承诺。写回的好处是 `npx skills update` 也能更新 Sophia 装的，等核实格式稳定再做。另需核实：`skillFolderHash` 是否就是该文件夹在 GitHub 上的树哈希（对照 `npx skills` 源码）。

### Q2 「自动检查更新」默认开还是关

这是 Sophia 第一次在打开页面时联网（「按对象组织的导航」那一版约定过不增加网络请求）。建议默认开、设置里可关。

### 附：「库」的分析（Q1 原文，已按方案 A 定）

magpie 有一个自己的库目录（`~/.config/magpie/library/skills`），新装的都放进去再链到各 agent；「收进库」时把 agent 目录里的原件整个挪进库。它相当于「只有一个来源、归工具所有」；Sophia 的来源是「用户已有的若干文件夹，Sophia 不拥有」。差别：谁拥有文件（应用自带的、被 git 跟踪的不能挪）、有没有项目级（magpie 没有）、卸掉工具后还能不能用（magpie 的会断）。所以不整体照搬，只借「默认落点」。

### Q3 筛选行的细节

- 选中 `全部` 时，表格仍有 `位置` 列；来源下拉里的选项，跟着当前位置变吗？
- 项目很多时，`更多 ▾` 之前放几个项目？沿用现在的 6 个吗？
- `管理来源`、`+ 来源` 两个键还留在页面头吗？有了 `发现` 和默认落点以后，`+ 来源` 是否只在 `管理来源` 里出现？
