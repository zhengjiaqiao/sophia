# Intent: 只展示事实，只做动作

- 状态：已接受（2026-09-07，作者口述）
- 作者：jiaqiao
- 日期：2026-09-07
- 上游：v4 真机使用反馈（PR #4）

## 问题

v4 持久化一份"同步集"（每个目标从每个本体位置引入哪些 skill），表格按它算出"已引入 / 已启用"，"同步"只补缺失的链接。这份配置和磁盘现实会分叉：移除一个来源、取消一个 skill 之后再"同步"，链接原样还在，界面又把它们当事实显示回来，用户分不清"同步"到底是增量补齐还是维护最终状态。

两条修法都不自然：
- 声明式（同步 = 让磁盘等于配置）：删来源要提示"会删掉链接"，而本体就在项目里的来源根本不该能被删除，规则越加越多。
- 增量式保留配置：还得另开一页展示"全集"，而现在的表格看起来已经是全集。

## 期望结果

不再有需要和磁盘对账的配置。**表格就是现实，按钮就是对现实的修改。**

- 域页表格只显示两类行：本域自有本体位置的全部 skill；本域任一目标里已链接到某本体位置的 skill（只显示被链接的那些）。
- 每格是事实：本体在此 / 已链接 / 未同步 / 坏链 / 指向别处 / 已存在同名条目 / 整目录链接到别处。
- 动作只有三种，都作用于用户当场勾选的行：
  - **补齐缺失**：给选中行的"未同步"格建链。
  - **取消链接**：删除选中行的"已链接"格。只删软链本身；"本体在此"的格不是链接，永远不可删；删前重校验仍是指向该本体位置的软链。需二次确认。
  - **清理坏链**：不变。
- "引入…"改成一次性动作：选一个本体位置、勾 skill、确定，当场为本域每个目标建链。建完它们就是事实，自然出现在表里。
- 来源标签只是信息（本域的行来自哪些本体位置、各几行），没有"编辑 / 移除"。
- 行首勾选是临时选择，默认全选，只影响这次点的按钮；切换侧栏即重置。
- 「全部」页、排序、暂态结果框、整目录链接拆分保留。

## 约束

- 删除 `syncset.json` 与 picks 概念；持久化只剩设置（harness 开关、手动项目、手动本体位置）与自定义同步规则。
- 不搬本体、不复制内容。工具能删的只有软链接：坏链、用户点"取消链接"的链接、拆分整目录链接时那条目录级软链。
- 不加"忽略名单"。某个 skill 不想同步，就不勾它；真觉得吵再议。
- Rust core + Tauri；分工不变。
