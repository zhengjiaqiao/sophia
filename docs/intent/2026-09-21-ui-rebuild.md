# 全部页面重构

## 问题

界面长到今天是一层层加出来的，三个毛病凑在一起：

**一、做不成的时候不说为什么。** 点一下想开启某个 skill，如果那个位置已经被同名的东西占了、或者那儿有一条断掉的链接，界面只会说"没有需要建立的链接"。这句话对这四种情况全是错的，用户读完不知道发生了什么，更不知道下一步该干什么。

**二、把实现细节摆在用户面前。** 设置里 41 行列表，每行是复选框、名字、一长串绝对路径——用户要做的判断只有一个"这个 agent 出不出现在矩阵里"，却要读三样东西，其中路径他并不关心。同样的问题散布各处：文案说"建软链接"而不说"让它出现在列表里"，说"操作失败"而不说哪里不通。

**三、同一件事在不同地方长得不一样。** Skill 页和 MCP 页都是"一批东西 × 一批位置"的矩阵，却是两套交互；同一个数字在两处口径不同；该用弹窗的用了页面，该用页面的挤进了弹窗。用户每换一个页面都要重新学一次。

## 谁在什么场景下遇到

日常同时用多个 AI 编码工具的人，在两个时刻遇到：一是刚装了新工具、想把已有的 skill 铺过去；二是发现某个工具读不到某个 skill，想弄清楚卡在哪。现在的绕法是打开终端自己 `ls -la` 看软链。

## 期望结果

- **界面回答两个问题**：这个 skill 在这个 agent 下现在能不能用；点了没成的话，是什么挡住了。第二个问题必须给出用户能据此行动的话，不是错误码，也不是"操作失败"。
- **需要拿主意的事集中在一处**，不散落在各个弹窗里；同一条状况处理过或忽略过之后不再反复打扰。
- **换页面不用重新学**：一样的东西长一样，一样的数字口径一致。
- **用户看得见的东西里没有实现细节**：不出现绝对路径、不出现"软链接"这类词，除非他正要据此做判断（比如删掉一个目录前，要知道有几条链接会因此失效）。

## 不做什么

- 不做移动本体的能力。
- 不重做底层的扫描与同步逻辑——这次只改界面层和它直接依赖的判断，扫描出来的事实不变。
- 不改已落盘的配置文件格式。

## 待决问题

- 删除本体目录是这次新增的能力，突破了此前"只建删软链、绝不碰真实目录"的边界。已定要做，但删到废纸篓、git 仓库里的不代删、删完把链接改指向留下的那个——这三条安全约束的实现代价还没评估。
- 41 个 agent 的图标，目前只有 4 个有形状参照，其余用首字母方块占位。要不要逐个去取官方图形，取决于用户觉得占位够不够用。
