# 在 SymSync 里管理 Codex 的第三方模型

## 问题

作者想让 Codex 桌面应用里官方模型和公司网关（wecode）上的模型同时可选。这件事已经在一个独立的小工具 agents-manager 里做通，并在本机真实启用：Codex 的模型选择器里两类模型并列，对话、工具调用都可用。

但它的界面是一张用浏览器打开的本机网页，不是一个应用。作者原话：“等下，你给我开发的是网页，不是一个像 ollama 的 app？”“我想把这个功能集成到我做的另一个应用里。”

作者已经有 SymSync 这个桌面应用，管的正是同一类事情：各个 AI 编码工具的 skill 和 MCP 配置。模型配置是同一张桌子上的第三样东西，却要另开一个网页、记另一套命令。而且两个工具都会改 Codex 的同一份设置文件，各改各的，迟早互相踩到。

目前的绕过方式：在终端里运行命令打开网页来改模型；不改的时候靠后台服务自己跑着。

## 期望结果

- 打开 SymSync 就能管理 Codex 的第三方模型：看到当前是否已启用、后台服务是否正常、选了哪些模型，并能添加网关、勾选模型、启用、恢复。不再需要浏览器网页和命令行。
- 关掉 SymSync 之后，Codex 里的官方模型和第三方模型照常可用。
- 现在这台机器上已经启用的状态被 SymSync 原样接管：接管前后 Codex 里的模型列表不变，不需要重新填密钥、重新选模型。
- SymSync 同步 MCP 和管理模型这两件事改的是同一份 Codex 设置，先后操作互不破坏：任一方写入后，另一方要么成功，要么明确提示“设置已变化，请重试”，不会悄悄覆盖对方或用户手写的内容。
- 恢复之后，Codex 设置里不留这项功能的痕迹，MCP 配置原样保留。

## 影响对象

作者本人：SymSync 和 Codex 桌面应用的使用者，有官方订阅和 wecode 账号。SymSync 现有的 skill、MCP 功能不应受影响。

## 约束

- agents-manager 在真实环境验证过的行为不能倒退，重写后要重新在真实环境验证一遍：按模型分流、协议转换、工具调用、远程压缩、官方凭据不外泄、第三方密钥只在钥匙串里。
- SymSync 对“改用户文件”的标准不能降低：备份、原子替换、写前写后校验、拒绝可疑路径，和 MCP 同步一致。
- SymSync 现在关窗即退出，没有常驻能力；而模型路由必须常驻。
- 作者当初选 Rust 和 Tauri 就是为了 macOS 和 Windows 两端都能用，这项功能最终也要两端可用。目前它只在 macOS 上做过并验证过；Windows 上的常驻方式、密钥存放、系统代理读取都还没有做，也没有在 Windows 真机上验证过。
- 任何阶段，SymSync 在还不支持这项功能的系统上都必须照常编译和运行。
- SymSync 的 MCP 功能只存在于本机仓库，尚未推到远程；另有一个 skill 方向的改动正在进行中。

## 范围外

- wecode 以外的网关、Codex 以外的工具（Claude Code 等）的模型管理。
- 让 SymSync 变成常驻菜单栏的应用。
- Windows、Linux 上的模型共存（本期不做；非 macOS 上这个页面不出现）。
- 改变 SymSync 现有的 skill、MCP 行为。

## 已确认（作者 2026-09-20 答复）

- 这项功能最终要 macOS 和 Windows 两端都能用；**本期只交付 macOS**，Windows 另开需求，届时需要真机验证。
- 路由和协议转换**用 Rust 重写并入 SymSync**，不沿用 agents-manager 的 Go 程序。作者的考虑：长期维护一个两端可用的应用，整个仓库一种语言、安装包里只有一个程序；现在仓库里还没有集成代码，此时换语言最便宜。agents-manager 已验证过的行为和它的测试作为重写的验收依据。
- 独立的 agents-manager（Go 程序加网页界面）**原样保留**，继续可以单独使用。两个工具可能同时装在一台机器上，必须互不踩踏：同一时刻只有一方接管 Codex，另一方能认出对方并明确提示，而不是覆盖。
