# 按对象组织的导航

## 问题

侧栏上半截按「谁」分（AGENT › Codex），下半截按「在哪」分（项目 › 全局 / CardBox / …），而用户做事是按「管什么」想的：管 skill、管 MCP、管模型网关，以后还有看用量。产品负责人的原话：「侧栏现在是 agent 和项目，其实管理的是 skill、mcp（项目视图在管理）和网关（agent 视图管理）」。

三个具体毛病：

- **同一个 agent 被拆成两处。** Codex 的 skill 在某个项目页的一列里，Codex 的模型在「AGENT › Codex」下。想了解 Codex 的全部情况，要在侧栏两头来回找。
- **新能力没有自然的位置。** 产品要做成一站式的跨 agent 管理工具，管的东西只会越来越多。比如用量要加进来，就只能挂在 AGENT 下，Claude Code 会变成一个只装着用量的侧栏项。
- **项目一多，侧栏就很长。** 项目其实只是一个范围条件，却占掉了侧栏的大半。

现在的绕法是记住东西在哪：skill 和 MCP 去项目下面找，模型去 agent 下面找。

## 期望结果

- **侧栏只列要管的东西。** 项目不再占侧栏：有 3 个项目和有 30 个项目，侧栏一样长。
- **范围是一个条件，切一次，各页都跟着变。** 在 skill 和 MCP 之间来回切，停在哪个项目就还在哪个项目；换一次项目，这两页一起换。
- **默认一眼看全。** 默认显示「全部」：用户级和各项目的东西列在同一张表里，每一行标明在哪个位置，同一个 skill 装在两处时一眼看得出来。想缩小范围，一下点到「用户级」或「项目级」，再点某个项目。
- **一种东西只在一处管。** 第三方模型只在一个地方配，不因 agent 不同而散在不同位置。
- **该留的能力都还在。** 原侧栏项目区的切换、排序、看完整路径，搬到新位置后都还在，只用键盘也能完成。项目很多时，页面不跟着变长。
- **老用户升级后不迷路。**
  - 打开时停在升级前最后停的那个项目和那一页。
  - 已经学会的快捷键（SKILLS、MCP 的那两个）意思不变。
  - 应用菜单「显示」里的项和侧栏一一对应。
- **以后加东西不用重排。** 加入用量或会话，只是在侧栏多出一项；已有项的位置和快捷键都不动。

## 影响对象

- 同时用多个 AI coding agent 的 Sophia 用户，尤其是项目多的人。
- 界面层的外壳：侧栏、每页顶上一行、应用菜单与快捷键、「上次停在哪」的记忆。
- 设计规范里讲外壳与导航的几节。

## 约束

- 扫描出来的事实、同步逻辑、落盘的配置文件格式都不变。这次只动导航。
- 本机已记住的「上次停在哪」要能读懂；读不懂时落到默认位置，不能报错。
- 遵守现行设计原则：一处只有一个选中项；让用户知道自己在哪；不可用的不列出来，也不灰着列。
- 已定（2026-09-26，产品负责人）：
  - 侧栏不分组，平铺列出要管的东西。
  - 管第三方模型的那一项叫「模型」，不叫「网关路由」：新手不理解网关。
  - 原来的「全局」改叫「用户级」，与各 agent 自己文档里的 user / project 对上。
  - 范围条件多一个「全部」，并默认选它。
  - 范围分三档：全部、用户级、项目级，三个选项一眼可见。「全部」和「项目级」下都能再点一个项目来缩小；「全部」下点一个项目，看的是用户级加这个项目。
  - 项目多的时候，只露出最近活跃的 6 个，其余收进「更多」。
  - 去掉「按来源筛选」：来源仍是表里的一列，要找来源用筛选框搜。筛选框现在只按名字匹配（已查代码），这次要让它也能搜到来源名。
  - 去掉「手动添加项目」和「从列表移除项目」：项目只来自自动检测，列表里的就是检测到的，不需要手动增删。
  - 不在范围条件旁常驻「最近项目」快捷片。
  - 侧栏里拉丁结构词（SKILLS、MCP）大写，中文词照常写，两种混排。

## 范围外

- 用量：用量页、托盘里的用量、菜单栏上的数字、接入 Claude Code 读用量。这些另开一份需求，本次只保证它以后能作为侧栏一项加进来。
- 会话页。
- 托盘面板：结构和内容不变。
- 任何视觉风格上的调整。

## 待决问题

- 还没做的「会话」要不要先在侧栏占一个灰着的位置？（产品负责人）—— 默认假设：不占，等它能用了再出现。依据是「不可用的不列」这条原则。
- 在不支持第三方模型的平台（非 macOS），「模型」一项怎么办？（产品负责人）—— 默认假设：不列，它的快捷键什么都不做，其他项的快捷键不跟着变。
- 升级后，旧版里停在「Codex 页」的用户落到哪？—— 默认假设：落到新的模型页。
- 「全部」下，同一个 skill 装在两个位置时怎么显示？（产品负责人）—— 默认假设：分成两行，不合并，因为每个格子要对应确定的一个位置。
- 「全部」下点「管理来源」「添加来源」怎么办？（产品负责人）—— 默认假设：先问加到哪个位置。
- MCP 在「全部」下，用户级那几行遇到只有项目才有的列怎么办？（产品负责人）—— 默认假设：留空。
- 以前手动加进来、又没被自动检测到的项目怎么处理？（产品负责人）—— 默认假设：升级后不再列出，磁盘上的东西一样不动。
